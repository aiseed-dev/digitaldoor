# やりたいこと

2026年9月17日。尼寺康泰。

扉コントローラの仕様と参照実装を、aiseedの名義で公開する。

## 何を公開するか

- 仕様。何を満たすかだけを、番号を付けて書く。本文は `扉コントローラ仕様書.md`。
- 参照実装。Pythonで動く物。`digitalkey` の `door`。判断と監査と門。
- 試験。この入力でこの出力、の形。通れば「通った」と言える。

英語版は急がない。日本人が働けるようにするためである。日本の扉メーカー、錠メーカー、電気工事の人、学生が、今日から同じ言葉で作れる。英語はAIで後からいつでも作れる。

## どういう性格の物か

Matterと同じ席で、Matterが届かない業務用を取る。今の業務用は高価な上にソフトが良くない。買うのは総務や設備で、使うのは現場で、仕様は制御盤の会社が独自の言葉で持ち、直すたびに見積もりである。公開の仕様と動く参照実装があれば、値段は落ち、ソフトは直せる物になる。

認証ではなく、実務的なものである。認証の仕組みも、会費も、商標も持たない。満たすかどうかは公開の試験を自分で回して分かる。だからPythonのように広がっていってよい。

責任を取るものではない。利用者の声を整理して、ドアメーカーに伝える要望書である。責任は、扉に入れて認定を取る扉メーカーと、鍵を出す発行者と、その家で客を泊める経営者が持つ。

だから、ドアメーカーからは料金を取らない。aiseedの収入は鍵の発行と、機器と業務のつなぎである。仕様は、その二つが入居できる扉を増やすための投資である。

仕様は「何を満たすか」だけで、これからどんどん追加していく。足すときは、要求一つに理由と試験手順と日付を添える。既にある番号は変えない。満たす側はどの番号を満たすかを申告する。「どう作るか」は書かない。公開しても、その中でドアメーカーは工夫できる。

## 仕様の芯

セキュリティを含めて自由に使えるAPIである。

- 業務システムから、三社のアカウントを経由せずに、扉へ直接呼べる。
- 呼ぶ側は認証され、権限で区切られる。
- 扉で起きたことは全部、署名つきで出て、改ざんが分かる形で並ぶ。
- 火災や停電のときの挙動は扉が持ち、外からの呼びで上書きできない。

ローカルだけで動作する機能が必ず必要である。認証の判定、施錠と解錠、火災と停電と避難の挙動、監査の記録、失効の適用、非常手段は、外部との通信が無くても動く。通信が切れても、扉は最後に受け取った資格情報と失効の一覧で判定を続ける。扉の出来事は構内で完結し、外へ出す先は事業者が決める。

これが無ければ、物理鍵は無くせず、電子錠は追加になる。これがあれば、電子錠は基準錠になり、外のシリンダーが消える。

スマートロックの認証は分散しておく。一社のサーバーが握る形は、障害、撤退、侵害、値上げ、差押えの一点に全戸が集まる。扉が自分で判定し、発行者は署名した伝票を渡すだけで、開くたびに呼ばれない。監査は扉と台帳の二か所に別々に残る。

Aliroは多重化に使う。扉は互いに独立した二つ以上の経路で資格情報を受ける。

将来は、カメラとマイクとセンサーとAliroが扉の中で連動する。組み合わせの規則は事業者が決める。ここはドアメーカーの仕事である。

## 誰と話すか

この一枚があれば、三つの相手と同じ言葉で話せる。

- 事業者。民泊の経営者、管理組合、企業。「あなたの声をこう整えた」。
- SIerの席。「ここが独占の中身だった。高かったのは独自の言葉の値段で、公開すれば消える。残るのは据付と一棟分の統合で、それは正当な仕事である」。
- AppleとGoogle。「あなたたちの言葉で住宅は開いた。業務用の扉には、あなたたちのアプリの外から呼べる、認証と監査を含んだ口が要る。ここに仕様と動く実装がある」。

## 扉メーカーとの関係

扉メーカーは仕様を書く側ではなく、仕様に入居する側である。扉と認定に専念でき、囲い込みの疑いがかからない。公開の仕様の中で工夫する場所は、防火戸への収め方、基準錠との組での認定、通線路の自己診断の測定値、接点の信頼性、値段と納期である。

## 足りない物

- ライセンスの選定。無保証の条項を持つ、Pythonと同じ系の形。
- 試験を適合試験として切り出すこと。
- 仕様書への追加。ローカルで完全、複数の経路、複数の入力の組み合わせ、出来事は構内で完結。
