# 扉コントローラ 仕様書

2026年9月16日 第1版

## 0. この文書について

扉の中に置く専用コントローラの仕様である。公開規格(Matter・Aliro)が範囲に入れていない部分を、扉側で持つために書く。

範囲は、一枚の扉と、その扉の枠までである。読取機の中身、錠の機構、建物の縦系統配線、上位の発行者(誰に鍵を出すか)は範囲外とし、それぞれ界面で受ける。

関連する文書。

| 文書 | 関係 |
|---|---|
| 錠を選べるドア | 事業としての位置づけ。標準インターフェース(第7章)、認定の境界(第6章) |
| ドア製品の階層構造 | この機器がどの層にあたるか。上下の層との関係 |
| digitalkey(実装、この置き場) | 本書に沿って動いている試作。`door`(判断と記録、旧tobira core)と`panel`(Matterの橋と盤) |

要求には `R-CT-nn` の番号を付ける。「〜すること」が要求、それ以外は説明である。

## 1. 位置づけ

コントローラが持つのは、規格が機器の言葉を決めた後に残る部分である。

Matterの錠(Door Lockクラスタ)が持つもの。施錠・解錠・アンボルト、利用者と資格情報、曜日と年日と休日の予定、扉位置センサー、操作の通知、操作モード、自動再施錠、警報。

Aliro 1.0が持つもの。スマートフォンと読取機の相互認証、NFC・BLE・UWB、オフラインでの失効。Aliroは読取機から後ろ(制御盤とその先)を意図して範囲外にしており、鍵の共有と監査は後の版に置いている。

この二つの外に残るものが、本書の中身である。

| # | 残るもの | 理由 |
|---|---|---|
| 1 | 火災・停電・避難のときの挙動 | 認定と消防で決まる。規格に型がない |
| 2 | 改ざんの分かる監査記録 | 通知はあるが、連番・連鎖・署名の記録がない |
| 3 | 二人同時と強要コード | 規格外 |
| 4 | 回数制限の鍵 | 予定は時間帯であって回数ではない |
| 5 | 読取機と制御盤の間の言葉 | Aliroが範囲外にした所 |
| 6 | 建物側との連動 | JEM-A、集合玄関の取り次ぎ |
| 7 | 通線路の自己診断 | 等級を点検の暦に載せるための測定 |
| 8 | 時刻の同期と未同期の記録 | 記録の証拠力に関わる |
| 9 | 非常手段の使用記録 | 給電パッド・機械キー・手動リリース |
| 10 | 保守者の権限 | 更新と診断はできて、解錠は管理者の承認が要る |

**R-CT-01** 上の10項目を扉側で持つ**こと**。

**R-CT-02** 持った機能は公開した言葉で外へ出す**こと**(第5章)。規格が後の版で同じ機能を取り込んだ場合は、その部分を規格に譲れる形にしておく**こと**。

## 2. 構成

三つに分ける。境目は接点とコネクタである。

| 層 | 中身 | 速さ |
|---|---|---|
| 安全側 | 接点の読み書き、火災と停電の一次挙動、機械的な解放 | 遅い。認定と一緒に固める |
| 判断側 | 状態の表、監査の記録、二人同時、設定 | 中。試験で固める |
| 界面側 | Matter、伝票の書き出し、読み取りの口、読取機との接続 | 速い。規格の版に合わせて動く |

**R-CT-03** 錠の銘柄は接点の下に隠す**こと**。コントローラから見える錠は、次の入出力の束とする。

| 向き | 信号 |
|---|---|
| 入力 | 火災信号、商用電源の有無、扉の開閉、デッドボルトの位置、手動リリース、改ざん検知 |
| 出力 | 解錠、施錠 |

**R-CT-04** 錠に固有の事情は、接点の層の差し替えとして書く**こと**。判断側の記述を錠ごとに変えないこと。

## 3. 状態と判断

### 3.1 状態

通常、火災、停電、通行。扉の状態(開・閉)と錠の状態(施錠・解錠)は別に持つ。

### 3.2 判断の表

| 入来事 | 既定の挙動 | 記録 |
|---|---|---|
| 有効な資格情報 | 解錠する | 認証/成功、操作/解錠 |
| 無効な資格情報 | 施錠のまま。理由を残す | 認証/拒否(理由付き) |
| 二人同時が要る扉で一人目 | 待つ。窓の秒数を過ぎた待ちは落とす。同じ人は二人と数えない | 認証/二人同時 待ち |
| 強要の印が付いた資格情報 | 解錠する | 認証/強要コード。外への通報は上の層 |
| 火災信号 入 | 設定に従い、解放するか保持する | 非常/火災信号 |
| 火災中の施錠要求 | 受け付けない | 操作/施錠 拒否(理由:火災中) |
| 停電 | 設定に従い、解放するか保持する | 非常/停電 |
| 復電 | 通常に戻す | 非常/復電 |
| 自動施錠の時刻 | 扉が閉じていれば施錠する。開いている間は待つ | 操作/施錠(自動施錠) |
| 手動リリース | 記録する。状態は解錠 | 非常/非常手段(手段名) |
| 改ざん検知 | 記録する | 異常 |

**R-CT-05** 火災信号を受けたときの挙動を、設定で解放と保持のどちらにもできる**こと**。既定は解放とする。どちらを使うかは、扉ごとに評価機関との協議で決まる。

**R-CT-06** 停電のときの挙動を、設定で解放と保持のどちらにもできる**こと**。既定は解放とする。

**R-CT-07** 電源が失われても機械的に開けられる手段を残す**こと**。その使用を記録できる**こと**。

**R-CT-08** 二人同時の人数と窓の秒数を設定できる**こと**。窓の内に人数が揃って初めて解錠する**こと**。

**R-CT-09** 自動施錠の秒数を設定できる**こと**。扉が開いている間は施錠しない**こと**。

**R-CT-10** 資格情報が有効かどうかの判定は、上の層(発行者)から受け取る**こと**。コントローラは提示された事実と結果を記録する。

## 4. 監査の記録

**R-CT-11** 記録は連番を持ち、欠番が分かる**こと**。

**R-CT-12** 各記録は前の記録のハッシュを持ち、改ざん・削除・挿入を検出できる**こと**。

**R-CT-13** 各記録に署名を付ける**こと**。署名の鍵は取り出せない場所に置く**こと**(セキュアエレメント)。

**R-CT-14** 記録は錠自身の操作で消せない**こと**。

**R-CT-15** 連番を指定した差分の取得ができる**こと**。

**R-CT-16** 時刻が同期していない間の記録に、その旨の印を付ける**こと**。同期したときは、前の時刻と新しい時刻の両方を残す**こと**。

記録する種別は、操作・物理・認証・資格情報・設定・非常・異常・時刻とする。一件の中身は、連番、錠の時刻、同期の印、種別、事象、結果、主体(仮名化した識別子)、経路、詳細、前ハッシュ、ハッシュ、署名。

主体と人の対応表は、コントローラの外(発行者と台帳)が持つ。

## 5. 界面

三つの向きに分ける。向きを分けることで、外から入ってくる認証をほとんど持たずに済む。

### 5.1 出す(記録)

**R-CT-17** 監査の記録を、署名つきの伝票として外へ出せる**こと**。相手が検べるのは接続ではなく署名とする。

置き場は箱(フォルダか、それに相当する受け口)でよい。止まっている間は溜まり、復旧したときに続きから流れる。装置の中の形式と、箱を流れる伝票の形式が違ってよく、翻訳は境界で一度だけ行う。

この向きに鍵の配布と失効は要らない。三十年もつのは、接続に付けた認証ではなく記録に付けた署名の方である。

### 5.2 受ける(命令)

**R-CT-18** 施錠と解錠の命令を、Matterの錠として受けられる**こと**。

操作する相手の認証は、Matterのペアリングで済んでいる。同じ認証をコントローラで作り直さない。

**R-CT-19** 読取機からの認証結果を受けられる**こと**。読取機は差し替えられる前提とし、コントローラが受けるのは「どの主体の資格情報が、どの経路で提示され、有効だったか」だけとする。

読取機がAliroの読取機であっても、ドアホンに吸収されたものであっても、この受け口は変わらない。

### 5.3 引かれる(照会)

**R-CT-20** 状態と記録を読み取る口を一つ持てる**こと**。読みは何も壊さないので、守るのは漏れだけである。

### 5.4 建物側

**R-CT-21** 既存のインターホン設備との連動を、業界標準の接点(JEM-A)で受けられる**こと**。

## 6. 設定

据付のときに決める項目である。ルータやプリンターと同じく、機器自身が設定の画面を持つ。

| 項目 | 内容 |
|---|---|
| 火災信号のとき | 解放 / 保持 |
| 停電のとき | 解放 / 保持 |
| 自動施錠 | 秒数。0で自動施錠しない |
| 二人同時 | 人数と窓の秒数 |
| 接点 | 各入力の極性、出力の型 |
| 時刻 | 同期の相手 |

**R-CT-22** 設定の変更を記録に残す**こと**(種別:設定)。前の値と新しい値の両方を残す**こと**。

設定画面の守り方は、次のどれかで足りる。利用者の一覧と失効を持たずに済む形を選ぶ。

- 機器に印刷した一つの合言葉
- 工事用の網からだけ見えるようにする
- 扉を開けた状態か、内側の押しボタンを押している間だけ受け付ける

## 7. 診断

**R-CT-23** 通線路の伝送性能と給電時の温度を測り、記録に残せる**こと**。等級の試験成績を、点検のたびの測定値として続けられる形にする。

**R-CT-24** 通信モジュールの脱落、時刻の大幅なずれ、記録領域の上書きを検出し、記録する**こと**。

## 8. 試験

合否の判定は、入力と出力の対で行う。次は実装で自動試験にしてあり、現在は緑である。

| # | 入力 | 期待する出力 |
|---|---|---|
| 1 | 有効な資格情報 → 自動施錠の秒数が過ぎる | 解錠し、その後に施錠する |
| 2 | 解錠 → 扉を開ける → 秒数が過ぎる → 扉を閉じる | 開いている間は施錠せず、閉じた後に施錠する |
| 3 | 火災信号 入 | 解放する。施錠の要求を拒否する。自動施錠しない |
| 4 | 停電(設定=解放 / 保持) | 設定どおりに解放または保持する。復電で通常に戻る |
| 5 | 二人同時=2で、一人目 → 同じ人 → 窓を過ぎて別人 → 一人目 | 揃うまで待ち、揃ったときだけ解錠する |
| 6 | 無効な資格情報 / 強要の印 | 拒否して施錠のまま / 解錠して強要を記録する |
| 7 | 手動リリース、改ざん検知 | それぞれ記録に残る |
| 8 | 時刻が未同期のまま操作 → 同期 → 操作 | 前者に未同期の印が付き、後者には付かない |
| 9 | 記録を書き換える / 一件消す | 検査が内容の変化 / 欠番を指摘する |
| 10 | 署名の鍵が違う | 検査が署名の不一致を指摘する |

**R-CT-25** 上の対を自動で試験できる**こと**。接点を模擬に差し替えて、実機の錠なしで回せる**こと**。

## 9. 実装の現在

試作は Linux の小さな機械で動かしている。判断と記録を先にソフトで固め、基板へは接点の層だけを写す。

| 部分 | 現在 | 後で |
|---|---|---|
| 判断と記録 | Python。接点は模擬に差し替え可能 | そのまま。決定的な挙動が要る部分は安全側へ写す |
| 署名 | ソフトのHMAC | セキュアエレメント(STSAFE) |
| Matterの錠 | Python(CircuitMatter)。Door Lockクラスタを自前で定義 | 同じ。製品にするときは自前の証明書 |
| 読取機 | 未接続 | 参照設計の基板(NUCLEO-WBA55CG、NFC12A1、SAFEA1B)、のちにドアホン |
| 設定画面 | 状態と操作と記録まで | 設定の項目を足す |

## 10. 規格に足すべきもの

第1章の10項目のうち、日本固有ではなく、規制のある建物なら世界のどこでも要るものを、規格側に足す候補とする。

- 火災信号・停電・避難のときの挙動の型
- 改ざんの分かる監査記録(連番・連鎖・署名・差分取得)
- 二人同時と強要コード
- 読取機と制御盤の間の秘匿通信の指針

足す先は、MatterのDoor Lockクラスタと、Aliroが後の版に置いた監査と共有の部分である。本書の要求と第8章の試験の対を、そのまま要望書に使える。

等級の測定値と試験成績は、規格に出さずに持つ。規格が「測って保証せよ」と定めるほど、測った記録を持つ者の値打ちが上がる。
