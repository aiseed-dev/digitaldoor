## 1. 個別住宅との違い

| 観点 | 個別住宅 | 事業所 |
| --- | --- | --- |
| 利用者 | 家族と少数の来客・業者 | 従業員、来客、業者、清掃、警備。人数と入れ替わりが多い |
| 時間の扱い | 常時施錠が基本 | 営業時間は通行モードや受付経由、時間外はオートロック。時間帯の設定が中心 |
| 扉の数 | 1〜2 | 複数（正面、通用口、搬入口、非常口）。扉ごとに権限が違う |
| 記録 | 家族の安心 | 入退室記録が就業管理・監査・警備に使われる |
| 既設設備 | ほぼない | 既設の電気錠システム（制御盤）、警備システム、入退室管理、受付システムがあることが多い |
| 法規 | 住宅 | 避難経路、非常口、防火設備、消防設備との連動。テナントビルでは管理規約 |
| 非常口 | なし | 内側からは常に開き、外からは開かない。開扉で警報 |

### 2.5 鍵の管理の責任（2026-10-20）

事業所のデジタルキーは、アカウントや多要素認証と同じ、本人と権限の管理である。扉と錠の物理（据付、点検、交換）は設備の担当が持ち、鍵の発行、失効、台帳、発行者の鍵は情報システム部門が持つ。

| ID | 要求 |
| --- | --- |
| R-EB-33 | 事業所の鍵の発行者は、その会社の情報システム部門とする**こと**。発行者の鍵（コア R-AC-11）と台帳の責任者を、情報システム部門に置く。設備の担当と業者には、扉と錠の物理の作業に要る範囲の権限だけを渡す |
| R-EB-34 | 入社、異動、退職、契約の終了は、人事の届けを正として扉の台帳に入れ、アカウントと扉の鍵を同じ日に変える**こと**。退職の日に、アカウントの停止と全経路の鍵の失効（コア R-AC-15）を行い、両方が止まったことを照らし合わせる。片方からもう片方を自動で動かさない |
| R-EB-35 | 従業員の鍵も、ネットワークの届かない扉では、コア R-AC-14 の最長の時間で区切る**こと**。R-EB-03 の「期限なし」は、ネットワークが届く扉で即時の失効が効く場合に限る。期限はネットワークが届くときに自動で延ばす |
| R-EB-36 | 端末の紛失は、アカウントと端末の管理と同じ窓口（情報システム部門）で受け、本人を確かめてから、全経路の鍵を止めて出し直す**こと**。窓口を外の会社に任せない |
| R-EB-37 | 扉の台帳は、鍵の要る全員（社員、派遣、アルバイト、清掃、警備、出入りの業者、来客）を載せる、それ自身が正の台帳とする**こと**。ディレクトリ（Entra ID など）を正にせず、そこから自動で鍵を出し入れしない |
| R-EB-38 | 社員の鍵は、情報システム部門が、自分の発行者の鍵で出せる**こと**。そのための道として、ウォレットを通さないアプリ（コア R-CM-17）を持つ。このアプリで、全部の扉が開く状態を先に作る。ウォレット（Apple、Google）の社員証は、ウォレットの制度に入った会社の仕組みを、その会社だけの別の発行者として足す形で受け、その署名は、資格情報が本物であることの確かめにだけ使う。通すのは、情報システム部門が登録した資格情報だけとする（コア R-AC-18、R-AC-20 の代わりの案、R-AC-25）。ウォレットとその会社の仕組みが止まっても、アプリで開く。事業所の扉は、ホームアプリ（Matter の登録先）からの鍵の登録と解錠を受けない設定とする（コア R-AC-24） |
| R-EB-39 | 扉に管理者の鍵を入れる作業は、工事と分ける**こと**。工事と試験が終わったら、試験に使った鍵を消して鍵の無い状態に戻し、消したことを扉の記録に残す（扉コントローラ仕様書 R-CT-27）。管理者の鍵は、情報システム部門が自分で入れ、予備の管理者の鍵（コア R-AC-23）は会社が保管する。施工の人と設備の担当は、鍵を持たない（90 R-IP-03） |

足した要求の理由と確かめ方（2026-10-20）

- R-EB-33〜36
  - 出どころ：使う人の言葉「デジタルキーの管理の責任は、その会社の情報システム部門が持たないと無理でしょう」（2026-10-20）。コア 7.6 の R-AC-14〜19 の出どころ（鍵の管理は受託では重すぎ、各管理者が責任を持つ）。米国の CISA と FBI の注意喚起 AA23-320A は、IT のヘルプデスクへの成りすましで認証を作り直させる手口を挙げている
  - 理由：扉の鍵は、アカウントと同じく「誰が、どこに、いつまで入れるか」の権限である。総務や設備が別の台帳で持つと、退職したのにアカウントは止まり扉の鍵は生きている、という漏れが起きる。端末の紛失も、アカウントと端末の管理と同じ窓口でなければ、本人の確かめが二重に弱くなる。R-EB-03 の「期限なし」のままでは、ネットワークの届かない扉で失効が効かない
  - 確かめ方：R-EB-33 は、発行者の鍵と台帳の責任者の名簿を点検で確かめる。R-EB-34 は、試しの従業員を人事の届けで退職させ、同じ日にアカウントが止まり、全経路の鍵で開かず、両方を照らし合わせた記録が残ることを確かめる。R-EB-35 は、ネットワークを切った扉で、決めた時間を過ぎた従業員の鍵が拒まれ、ネットワークが戻ると延ばされることを疑似の扉で確かめる。R-EB-36 は、紛失の届け出から出し直しまでを訓練し、窓口の記録を残す
- R-EB-37（と R-EB-34 の言い方の直し、2026-10-20）
  - 出どころ：使う人の言葉「Entra ID は人の台帳の入口としても使えない」「鍵が要る人が載っていないというのが、EntraID が使えない証明」（2026-10-20）
  - 理由：ディレクトリはアカウントの台帳で、扉に入る人の台帳ではない。清掃、警備、派遣、アルバイト、出入りの業者、来客は、ライセンスの費用がかかるのでディレクトリに作られないのが普通で、鍵の要る人が載っていない。全員を載せられない台帳は正になれず、扉の台帳は別に要る。逆に、サービス用のアカウント、共有のメールボックス、外部のゲスト、メールを残すために生かした退職者のアカウントは載っている。そのうえ、ディレクトリから自動で鍵を出し入れすると、テナントを乗っ取った攻撃者が偽の社員を作るだけで扉が開き、退職の通知を偽造すれば全員を締め出せ、本物の退職を握りつぶせば失効が止まる。クラウドの ID の侵害が、建物の物理の侵入になる。ディレクトリを読むためのアプリの資格情報も、広い権限を持つつなぎとして狙われる。個人の Microsoft アカウントは本人の物だが、権限を分ける、記録を管理者が見る、といった管理の仕組みが無く、扉の台帳にも使えない（使う人の言葉「Microsoft ID には管理する仕組みがないから使えない」、2026-10-20）
  - 確かめ方：扉の台帳に、ディレクトリにアカウントの無い人（清掃、来客）を載せて鍵を出せることを確かめる。ディレクトリにアカウントを一つ足しても、扉の台帳に人が増えず鍵が出ないことを確かめる。退職の訓練で、人事の届けから扉の鍵が止まり、アカウントの停止と照らし合わせた記録が残ることを確かめる

足した要求の理由と確かめ方（2026-11-11）

- R-EB-38
  - 出どころ：使う人の言葉「独自のAliro用アプリが必要になるでしょう。homeアプリでは対応できない」「一般住宅や事務所用は。どうしたらいいか公開しろ」（2026-11-11）。Apple のウォレットに入館の鍵を入れる制度（Apple Wallet Access Program）のガイドと、Google Wallet の更新の記録を読んだ
  - 理由：ホームアプリは一つの家のための物で、会社が社員に鍵を出し、退職の日に止める使い方に合わない。ウォレットの社員証は、制度に入った会社が鍵をスマートフォンに入れる形で、Apple のガイドでは、会社は建物を持つか管理する者の立場で入る。情報システム部門が自分で鍵を出せる道は、ウォレットを通さないアプリである。これを土台にし、ウォレットは、使いたい会社が後から足す。足しても、通すかは情報システム部門の登録で決めるので、ウォレットに鍵を載せる会社が攻められても、扉は開かない
  - 確かめ方：ウォレットを使わない状態で、情報システム部門が出したアプリの鍵で、全部の扉が開くことを確かめる。ウォレットに鍵を載せる会社の発行者の鍵で署名した、登録していない資格情報が拒まれることを確かめる。ホームアプリからの登録が拒まれることを確かめる
- R-EB-39
  - 出どころ：同じ言葉と、コア R-AC-23 の出どころ（管理者の鍵をなくしたときに、本人を誰が確かめるかが決まっていなかった）
  - 理由：工事と試験に使った鍵が扉に残ると、施工の人が後から開けられる。機械の鍵で、工事用の鍵を、本物の鍵を使ったときに効かなくするのと同じく、工事の終わりに鍵の無い状態に戻し、会社が自分の鍵を入れる。予備を会社が持てば、管理者の鍵をなくしても、製造者や業者に頼らずに入れ直せる
  - 確かめ方：工事の後の扉が、鍵の無い状態を返し、消した記録があることを確かめる。情報システム部門が自分で管理者の鍵を入れ、予備で入れ直せることを、引き渡しの受入れ試験で確かめる（コア R-RS-18）
