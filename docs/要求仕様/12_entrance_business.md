## 1. 個別住宅との違い

| 観点 | 個別住宅 | 事業所 |
| --- | --- | --- |
| 利用者 | 家族と少数の来客・業者 | 従業員、来客、業者、清掃、警備。人数と入れ替わりが多い |
| 時間の扱い | 常時施錠が基本 | 営業時間は通行モードや受付経由、時間外はオートロック。時間帯の設定が中心 |
| 扉の数 | 1〜2 | 複数（正面、通用口、搬入口、非常口）。扉ごとに権限が違う |
| 記録 | 家族の安心 | 入退室記録が就業管理・監査・警備に使われる |
| 既設設備 | ほぼない | 既設の電気錠システム（制御盤）、警備システム、入退室管理、受付システムがあることが多い |
| 法規 | 住宅 | 避難経路、非常口、防火設備、消防設備との連動。テナントビルでは管理規約 |
| 非常口 | なし | 内側からは常に開き、外からは開かない。開扉で警報 |

## 2. 要求

### 2.1 権限と時間帯

| ID | 要求 |
| --- | --- |
| R-EB-01 | 扉ごとに資格情報の範囲を設定でき、正面玄関・通用口・搬入口・非常口で権限を分けられる**こと**（コア 7.2 範囲） |
| R-EB-02 | 営業時間の通行モード（コア 3 章 `passage`）は曜日と時間帯で自動的に始まり終わり、終了時刻を管理ソフトが通知**すること**（10 R-SF-12） |
| R-EB-03 | 従業員の資格情報は期限なし、来客・業者は期限・時間帯付きとし、退職・契約終了で即時失効できる**こと**（コア R-AC-03） |
| R-EB-04 | 来客は受付（人）または受付端末からの一時解錠、もしくは事前発行の一時鍵で入れる**こと**。受付端末は管理ソフトのクライアント |
| R-EB-05 | 従業員がスマホを持たない・使えない場合のため、カードまたは暗証番号を併設できる**こと**（10 R-CM-09）。既存の社員証（FeliCa / MIFARE）を読めるかは機種による |

### 2.2 既設設備との連携

| ID | 要求 |
| --- | --- |
| R-EB-10 | 既設の電気錠システム（制御盤付き）が残る扉は、無電圧接点で連携し、置き換えない**こと**（[11_entrance_apartment.md](11_entrance_apartment.md) R-AP-07 と同じ考え方） |
| R-EB-11 | 警備システムとの連携（警備セット中の解錠を拒否または警報、最終退出でセット）は無電圧接点で行い、警備会社の仕様に従う**こと** |
| R-EB-12 | 入退室記録を就業管理などの外部システムへ渡す場合は、公開 API（70 R-DV-10）から書き出す**こと**。錠側に外部連携を持たせない |

### 2.3 避難・非常口

| ID | 要求 |
| --- | --- |
| R-EB-20 | すべての外周部の扉は内側から常に機械的に開ける**こと**（10 R-MC-06） |
| R-EB-21 | 非常口は外からの解錠手段を持たず、開扉を検知して警報と記録を行う**こと**。防火設備や避難経路に当たる場合は [30_fire_compartment.md](30_fire_compartment.md) の要求を優先 |
| R-EB-22 | 火災信号で解錠側へ倒す扉と、施錠を保持する扉を、扉ごとに設定できる**こと**。設定は設計者・消防との確認に従う |

### 2.4 運用

| ID | 要求 |
| --- | --- |
| R-EB-30 | 最終退出時に全扉の施錠状態を一覧で確認でき、開いている扉を通知**すること** |
| R-EB-31 | 清掃・警備・設備点検の業者に対し、曜日・時間帯・扉を限定した資格情報を発行できる**こと** |
| R-EB-32 | テナントビルでは、ビル共用部の入退室（ビル側の設備）と事業所の玄関を分け、事業所側だけを本書の対象とする**こと** |

### 2.5 鍵の管理の責任（2026-10-20）

事業所のデジタルキーは、アカウントや多要素認証と同じ、本人と権限の管理である。扉と錠の物理（据付、点検、交換）は設備の担当が持ち、鍵の発行、失効、台帳、発行者の鍵は情報システム部門が持つ。

| ID | 要求 |
| --- | --- |
| R-EB-33 | 事業所の鍵の発行者は、その会社の情報システム部門とする**こと**。発行者の鍵（コア R-AC-11）と台帳の責任者を、情報システム部門に置く。設備の担当と業者には、扉と錠の物理の作業に要る範囲の権限だけを渡す |
| R-EB-34 | 鍵の台帳を、人事の台帳とアカウントの台帳（ディレクトリ）と結び、入社、異動、退職、契約の終了で、アカウントと扉の鍵を同じ手順で、同じ日に変える**こと**。退職の日に、アカウントの停止と全経路の鍵の失効（コア R-AC-15）を一度の手続きで行う |
| R-EB-35 | 従業員の鍵も、網の届かない扉では、コア R-AC-14 の最長の時間で区切る**こと**。R-EB-03 の「期限なし」は、網が届く扉で即時の失効が効く場合に限る。期限は網が届くときに自動で延ばす |
| R-EB-36 | 端末の紛失は、アカウントと端末の管理と同じ窓口（情報システム部門）で受け、本人を確かめてから、全経路の鍵を止めて出し直す**こと**。窓口を外の会社に任せない |

足した要求の理由と確かめ方（2026-10-20）

- R-EB-33〜36
  - 出どころ：使う人の言葉「デジタルキーの管理の責任は、その会社の情報システム部門が持たないと無理でしょう」（2026-10-20）。コア 7.6 の R-AC-14〜19 の出どころ（鍵の管理は受託では重すぎ、各管理者が責任を持つ）。米国の CISA と FBI の注意喚起 AA23-320A は、IT のヘルプデスクへの成りすましで認証を作り直させる手口を挙げている
  - 理由：扉の鍵は、アカウントと同じく「誰が、どこに、いつまで入れるか」の権限である。総務や設備が別の台帳で持つと、退職したのにアカウントは止まり扉の鍵は生きている、という漏れが起きる。端末の紛失も、アカウントと端末の管理と同じ窓口でなければ、本人の確かめが二重に弱くなる。R-EB-03 の「期限なし」のままでは、網の届かない扉で失効が効かない
  - 確かめ方：R-EB-33 は、発行者の鍵と台帳の責任者の名簿を点検で確かめる。R-EB-34 は、試しの従業員を退職させ、同じ日にアカウントが止まり、全経路の鍵で開かないことを確かめる。R-EB-35 は、網を切った扉で、決めた時間を過ぎた従業員の鍵が拒まれ、網が戻ると延ばされることを疑似の扉で確かめる。R-EB-36 は、紛失の届け出から出し直しまでを訓練し、窓口の記録を残す

## 3. ケース確認表（事業所で加わる事象）

個別住宅の 30 件（10 第 8 章）に加えて確認する。

| # | 事象 | 期待する振る舞い | 要求 |
| --- | --- | --- | --- |
| 1 | 営業時間の開始・終了 | 通行モードが自動で始まり終わる。終了時に開いている扉を通知 | R-EB-02、30 |
| 2 | 従業員の退職 | 即時失効。アカウントの停止と同じ日、同じ手続き。記録に残る | R-EB-03、R-EB-34 |
| 3 | 来客 | 受付からの一時解錠、または一時鍵 | R-EB-04 |
| 4 | 社員証で入りたい | カード併設。既存カードの可否は機種次第 | R-EB-05 |
| 5 | 警備セット中に開けようとする | 拒否または警報。警備会社の仕様に従う | R-EB-11 |
| 6 | 最終退出者が施錠を確認したい | 全扉の一覧と通知 | R-EB-30 |
| 7 | 非常口が開いた | 警報と記録。外からは開かない | R-EB-21 |
| 8 | 火災 | 扉ごとの設定に従い解錠または保持。内側は常に開く | R-EB-20、22 |
| 9 | 既設の電気錠が残る扉 | 接点で連携。記録は錠側にも残す | R-EB-10 |
| 10 | 入退室記録を勤怠に使う | 公開 API から書き出す | R-EB-12 |
| 11 | 搬入口だけ業者に開けさせる | 扉ごとの範囲と時間帯 | R-EB-01、31 |
| 12 | テナントビルの共用部 | 対象外。事業所の玄関だけを扱う | R-EB-32 |
