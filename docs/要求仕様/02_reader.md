| 項目 | 内容 |
| --- | --- |
| 版 | 0.1（草案） |
| 日付 | 2026-10-17 |
| 前提 | [00_core.md](00_core.md)（5.3 機器種別ごとの適合基準、第 6 章 監査ログ、第 7 章 権限モデル、第 9 章 ユニバーサルデザイン）、[01_interface.md](01_interface.md)（R-IF-07 機器の開口）、[../扉コントローラ仕様書.md](../扉コントローラ仕様書.md)（R-CT-10 判定は上の層から受ける、R-CT-19 読取機からの認証結果） |
| 目的 | 玄関で来訪者を識別する読取機の役をドアホンが担い、顔を含む複数の手段で識別した結果を扉のコントローラに渡す。衣服、名札・ワッペン、全身、行動のような、誰かではなく何が写っているかを読む認識は、属性として上の層の規則の材料にする。扉の製造者が持つ物（開口、接続、受け口の言葉、試験）と、買う物（ドアホン、顔認識の機能）を分け、顔を使うときに守る事を要求にする |

要求には `R-RD-nn` の番号を付ける。「〜すること」が要求、それ以外は説明である。

---

## 1. 位置づけ

読取機は、来訪者を識別する機器である。玄関でその役を担うのはドアホンで、顔、NFC、UWB、音声を 1 台で読み取る方向に向かっている（解説記事「スマートドアに求められる条件」）。扉の製造者は読取機を作らない。持つのは、読取機を載せる開口・台座・コネクタ（R-IF-07）と、読取機から判定結果を受ける口（R-CT-19）と、受け入れ試験である。そして給電である。顔を読むドアホンは、映像の処理と夜間の照明に電気を使い続けるので、電池式の後付け機器では成り立たない。扉と枠を渡る有線給電（R-WR）を標準で持つ扉だけが、この読取機を載せられる（R-RD-16）。

顔認識は、読取機の中の一つの手段である。顔で識別した結果は、Aliro の鍵や暗証番号と同じ「どの主体の資格情報が、どの経路で提示され、有効だったか」という形でコントローラに届く（R-CT-10、R-CT-19）。コントローラは顔の画像を受けない。

| 手段 | 読取機の側で起きること | コントローラに渡る物 |
| --- | --- | --- |
| 顔 | 登録した顔との照合と、生体検知（写真や画面でないこと） | 主体の仮名化した識別子、経路 = 顔、信頼度、生体検知の結果 |
| Aliro（NFC、BLE、UWB） | スマートフォンやウォッチのウォレットの鍵との相互認証 | 主体、経路 = Aliro、有効 / 無効 |
| 暗証番号 | 入力の受付 | 主体（番号に結び付けた物）、経路 = 暗証 |
| 呼び出し | 住人や管理者が映像と音声で応答し、開けると決める | 操作 / 解錠（人の名前つき）。認証ではなく操作として記録 |
| 音声（配達など） | 用件を聞き取る。開けるかは上の層の規則 | 上の層の判定結果 |

## 2. 顔認識の要求

顔の特徴を電子計算機で使える形に変えた符号は、個人情報保護法の「個人識別符号」である（施行令第 1 条第 1 号ロ、個人情報保護委員会規則の基準に適合する物）。登録した人の顔だけでなく、ドアホンの前に立った来訪者の顔も写る。だから、顔は錠の鍵と同じ便利さで扱えない。

| ID | 要求 |
| --- | --- |
| R-RD-01 | 顔の照合と生体検知は、読取機の中か構内のゲートウェイで完結**すること**。外部のサーバーに顔の画像や特徴量を送らなくても解錠できること（ローカルで動く。00_core R-EL-17 と同じ考え） |
| R-RD-02 | 登録した顔の特徴量は、構内の保存領域に置き、持ち主（事業者、居住者）が一覧し、一人ずつ削除できる**こと**。削除は記録に残す（種別：資格情報） |
| R-RD-03 | 顔を登録するときに、目的、保存の場所、保存期間、削除の方法を本人に示し、同意を記録**すること**。登録しない人のための別の手段（Aliro、暗証、呼び出し）を必ず残すこと |
| R-RD-04 | 登録していない来訪者の顔の画像は、照合が終わったら保持しない**こと**。録画として保存する場合は、目的と期間を事業者が決めて設定に書き、設定を記録に残す（R-CT-22） |
| R-RD-05 | 写真、画面、面のような物によるなりすましを退ける生体検知を持つ**こと**。方式（奥行き、近赤外、動き、複数カメラ）は製造元の裁量とし、第 5 章の試験で確かめる |
| R-RD-06 | 他人受入率と本人拒否率を、照明の条件（昼、夜、逆光、雨天）ごとに申告**すること**。申告の方法（試験の人数、条件）も一緒に出す |
| R-RD-07 | 顔だけで解錠するかどうかを扉ごとに設定できる**こと**。重要な扉では、顔と別の経路（Aliro、暗証）を揃えてから解錠する二要素を設定できること。これは R-CT-08 の二人同時とは別の設定とする |
| R-RD-08 | 顔で解錠した記録に、主体の仮名化した識別子、経路 = 顔、信頼度、生体検知の結果を含める**こと**。顔の画像そのものは監査の記録に入れない |
| R-RD-09 | 読取機を替えても、誰を登録しているかの一覧は失われない**こと**。特徴量は機器ごとの形式でよいが、登録者の一覧は発行者の台帳側（00_core 第 7 章の主体）で持ち、新しい読取機に登録をやり直せる形にする |
| R-RD-10 | 顔を判定できないとき（暗い、マスク、帽子、子供の背の高さ、車椅子）に、呼び出し、暗証、Aliro に落ちる**こと**。判定できないことを理由に閉じ込めも締め出しもしない。カメラの高さと画角は 00_core 第 9 章のユニバーサルデザインの要求に従う |
| R-RD-11 | 顔の特徴量を、鍵の発行以外の目的（広告、分析、外部への提供）に使わない**こと**。使う場合は別に同意を取る |

登録した人の顔を家の中の機器で照合することと、民泊の本人確認（宿泊者の顔と旅券の照合。発行者側の `entrance` が受け持つ）は、目的が違う。前者は鍵の提示、後者は法令の本人確認である。同じカメラの一枚を使ってよいが、記録と保存期間は別に決める。

## 3. 顔以外の認識 — 衣服、名札・ワッペン、全身、行動

映像を読む AI のモデル（VLM）は、顔のほかに、衣服、名札やワッペン、全身、行動を読める。これらは「誰か」ではなく「何が写っているか」を読む物である。資格情報（Aliro、暗証、顔）とは役割が違い、上の層が解錠や通知を決めるときの材料になる。

| 読む物 | 読み取れること | 使いどころ |
| --- | --- | --- |
| 衣服 | 制服、作業着、配達の服装 | 配達、工事、清掃の来訪を、住人や登録者と区別する。宅配の受け口の扉だけを開ける規則の材料 |
| 名札・ワッペン | 会社名、名前、腕章 | 来訪の記録に会社名を残す。事業所の入構で、申告した会社と一致するかの確認 |
| 全身 | 人数、子供、車椅子、荷物、ロボット | 後ろから付いてくる人（共連れ）の検出。通行の補助（開けておく秒数を延ばす）。配送ロボットの通行 |
| 行動 | 長く立ち止まる、扉を試す、覗く、転倒、連れられて歩く | 通知と通報の材料。強要（R-CT の強要コード）と合わせて読む |

| ID | 要求 |
| --- | --- |
| R-RD-19 | 衣服、名札・ワッペン、全身、行動の認識の結果は、属性（何が写っているか）と信頼度として扱い、資格情報として扱わない**こと**。解錠の判定に使うときは、資格情報と組み合わせる規則を事業者が上の層で決める（R-CT-10）。属性だけで開けてよいのは、事業者が低い危険と決めた扉（宅配の受け口など）に限り、その設定を記録に残す |
| R-RD-20 | 認識はモデル（VLM）で行い、構内で動かすか外に出すかは事業者が決める**こと**。モデルは月単位で入れ替わるソフトなので、同じ入力（画像、時刻、扉）と同じ出力（属性、信頼度、根拠の短い説明）の形で差し替えられる**こと** |
| R-RD-21 | 認識の結果は、人が確かめる前提で記録**すること**。拒否、通報、締め出しのような重い動作は、人の確認か、二つ以上の根拠（例：行動 + 共連れ、名札 + 申告）が揃ったときに限る設定ができる**こと** |
| R-RD-22 | 要配慮個人情報に当たる物（人種、信条、社会的身分、病歴、犯罪の経歴など）を推定せず、解錠や通知の条件にしない**こと**。属性の記録は目的と期間を決め、映像の保持（R-RD-04）とは分けて文字で残す |
| R-RD-23 | 共連れ（一人の資格情報で二人以上が通る）を検出したときの動作（記録だけ、通知、二人目に資格情報を求める）を扉ごとに設定できる**こと**。既定は記録と通知とする |
| R-RD-24 | 認識の誤りを前提にした逃げ道を持つ**こと**。制服の誤認識で開かない、転倒の誤検知で通報する、のような誤りが起きたときに、人が結果を直し、直した記録が残る（扉コントローラ仕様書 第 4 章の記録と同じ考え） |

扉のコントローラは、カメラ、マイク、センサー、読取機の情報を扉の中で組み合わせて判断する方向にある（扉コントローラ仕様書 第 1 章、解説記事「扉のコントローラの仕様と参照実装を公開する」）。組み合わせの規則を決めるのは事業者で、モデルの答えは人が確かめる。現場の写真を VLM に見せて判断を助ける進め方は、aiai の手引き「現場で VLM を使う」（https://aiai.aiseed.dev/skills/genba.html ）と同じである。

## 4. ドアホンとの接続

| ID | 要求 |
| --- | --- |
| R-RD-12 | ドアホンは [00_core.md](00_core.md) 5.3 の適合基準に従う物を買う**こと**。Matter 1.5 の Doorbell、Chime、Intercom の機器種別（CSA の 1.5.1 の発表の呼び方）か、SIP と ONVIF / RTSP。扉の製造者が持つのは開口・台座・コネクタ（R-IF-07）と受け口（R-CT-19）だけとする |
| R-RD-13 | ドアホンの映像と音声は、構内で録画と検知ができる**こと**（ONVIF / RTSP）。外部に送る範囲は事業者が決める |
| R-RD-14 | 呼び出しに人が応答して開ける経路は、認証ではなく操作として記録**すること**（操作 / 解錠、主体 = 応答した人、経路 = 遠隔） |
| R-RD-15 | 来訪者の一枚の画像を、発行者側の本人確認の口に渡せる**こと**。参照実装は `entrance` の `/doorbell/{錠}/frame` で受ける |
| R-RD-16 | 読取機（ドアホン、カメラ、顔認識の処理）への給電は、扉と枠を渡る有線（[10_entrance_house.md](10_entrance_house.md) R-WR-01 の PoE+、R-WR-08 の DC 12〜24 V）で行う**こと**。電池式にしない。映像の処理、夜間の照明と近赤外、生体検知のセンサーは電気を使い続けるので、電池では持たず、電池切れが締め出しになる。扉の製造者が持つ通線と等級（01_interface 第 7 章）が、顔認識つきの読取機を載せる前提になる |
| R-RD-17 | 読取機の消費電力（待機時と動作時）を申告**すること**。扉側のバックアップ電源（R-WR-09）が最後の解錠と状態報告を賄える範囲に収める |
| R-RD-18 | 読取機とコントローラの間の言葉は、Aliro が範囲外にした所である（扉コントローラ仕様書 第 1 章の 5）。公開した形（扉コントローラ仕様書 5.2）で受け、読取機の銘柄を替えても受け口を変えない**こと** |

Matter の Doorbell は映像、音声、チャイムの口であり、顔の照合の結果を錠に渡すクラスタは、2026-10-17 の時点で CSA の発表に見当たらない。読取機の判定結果をコントローラに渡す言葉は、扉コントローラ仕様書 第 10 章の「規格に足すべきもの」の候補である。

## 5. 受け入れ試験

| # | 入力 | 期待する出力 | 要求 |
| --- | --- | --- | --- |
| 1 | 登録した人の顔 | 解錠。記録に主体、経路 = 顔、信頼度、生体検知の結果 | R-RD-08 |
| 2 | 登録していない人の顔 | 拒否。来訪者の画像を保持しない（設定で録画する場合は期間内だけ） | R-RD-04 |
| 3 | 登録した人の写真、画面、面 | 拒否。生体検知の結果が記録に残る | R-RD-05 |
| 4 | 夜間、逆光、雨天で登録した人の顔 | 申告した本人拒否率の範囲で解錠 | R-RD-06 |
| 5 | 網を切って登録した人の顔 | 解錠（ローカルで完結） | R-RD-01 |
| 6 | 登録を削除した後の顔 | 拒否。削除が記録に残る | R-RD-02 |
| 7 | 二要素を設定した扉で顔だけ | 待つ。Aliro か暗証が揃って解錠 | R-RD-07 |
| 8 | 暗くて判定できない | 呼び出し、暗証、Aliro に落ちる。締め出しにならない | R-RD-10 |
| 9 | 読取機を別の銘柄に替える | 受け口（R-CT-19）を変えずに動く。登録者の一覧が台帳に残る | R-RD-09、R-RD-18 |
| 11 | 制服の配達員。資格情報なし | 低い危険と設定した受け口の扉だけ開く。玄関は開かない。記録に属性と信頼度 | R-RD-19 |
| 12 | 一人の資格情報で二人が通る | 共連れとして記録と通知。設定により二人目に資格情報を求める | R-RD-23 |
| 13 | 名札を印刷した紙 | 名札だけでは開かない。申告と一致しても資格情報が要る | R-RD-19 |
| 14 | 長く立ち止まる、扉を試す | 通知。通報は人の確認か二つ以上の根拠 | R-RD-21 |
| 15 | モデルを別の物に替える | 同じ入力と出力の形で動く | R-RD-20 |
| 10 | 停電 | 読取機は止まってよい。扉側のバックアップ電源で最後の解錠と報告（R-WR-09）。復電で読取機が登録を失わずに戻る | R-RD-16、R-RD-17 |

試験 1〜8 と 11〜14 は読取機とモデルの申告と、扉の受け入れ試験で確かめる。試験 9、10、15 は参照実装の自動試験にする。

## 6. 実装の現在

| 部分 | 現在 | 後で |
| --- | --- | --- |
| 判定結果の受け口 | コントローラの `/auth`（主体、有効、理由）。経路と信頼度の欄は無い | 経路、信頼度、生体検知の結果の欄を足す（R-RD-08） |
| 顔の照合 | `entrance` の `Matcher` の差し替え口と、配線確認用の `StubMatcher`。本人確認（旅券の顔との照合）の用途 | 構内で動く顔認識の実装を差す。鍵の提示の用途（本書）は別の規則で呼ぶ |
| ドアホンの取り込み | `/doorbell/{錠}/frame` に一枚を送る形 | Matter 1.5 の Doorbell か ONVIF からの取り込み |
| 顔以外の認識 | 無い | 構内のゲートウェイ（70_dev_server の ONVIF クライアントと動体検知の隣）で VLM を動かし、属性と信頼度を上の層に渡す |
| 読取機の機器 | 未接続。参照設計の基板（Aliro の読取り）の予定 | ドアホンに吸収する。顔認証を持つドアホンの候補は解説記事「スマートドアに求められる条件」の報道の節 |
