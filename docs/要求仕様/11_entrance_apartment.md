## 1. 4 点セット

```
 [集合玄関]                      [弱電盤 / 管理室]
  集合玄関機 ── 玄関電気錠         ルーター（LAN、Wi-Fi、PoE、Thread ボーダールーター）
   │ 接点 or Matter                 │
   └───────────────────────────── ミニサーバー（親。管理ソフト、Matter コントローラ、ONVIF、監査ログ）
                                    │ 任意: 外部公開（Cloudflare Tunnel 等）
                                    │ Thread（階ごとにボーダールーター）
 [各住戸]  住戸玄関錠（新設: 玄関プロファイル / 既設: Matter Door Lock 認証品の後付け）
```

| 要素 | 役割 | 適合基準（コア 5.3） |
| --- | --- | --- |
| 集合玄関機 | 来訪者の呼出し・通話・映像、居住者の解錠（Aliro タップ、暗証、カード）、玄関電気錠の駆動 | 新設なら Matter 1.5 Video Doorbell / Intercom + Matter Door Lock。既設のインターホン系（アイホン、パナソニック等）は**無電圧接点で連携**し、置き換えない |
| ルーター | 建物内 LAN の幹線、ミニサーバー・集合玄関機・カメラの接続、PoE 給電、Thread ボーダールーター、任意でインターネット接続 | 一般的な有線ルーター / L2 スイッチ。Thread は USB ドングルまたは対応アクセスポイント |
| ミニサーバー | 居住者・来訪者・配達の資格情報、予約（共用施設）、監査ログ、管理会社向け UI、カメラ録画 | 70_dev_server.md と同じイメージ。役割 = 親 |
| 玄関用装置 | 住戸玄関の錠と、その電子部（新設はドア製造者の電子錠埋込型ドア、後付けは Matter Door Lock 認証品） | 第 3.4 節。4 点のうち製造者が自社製造するのはこれだけ。他 3 点は調達品 |

## 2. 用途と脅威

| 観点 | 内容 |
| --- | --- |
| 相手 | 外部の侵入者（共連れ、なりすまし）、退去済み居住者、業者の鍵の流用 |
| 守るもの | 共用部への入場管理と、誰がいつ入ったかの記録 |
| 最悪の失敗 | 火災・停電時に内側から出られない、退去者の鍵が生き続ける、管理会社が全戸分の鍵を一括で失効できない、集合玄関機が止まって誰も入れない、管理側が住戸を記録なしに開けられる |
| 規模 | 数十〜数百戸。資格情報は居住者 × 家族 + 業者 + 一時鍵で千件級 |

## 3. 要求

### 3.1 集合玄関

| ID | 要求 |
| --- | --- |
| R-AP-01 | 集合玄関の扉は内側から常に電気なしで開ける**こと**（避難）。火災信号で解錠側へ倒す**こと**（30_fire_compartment.md の考え方を共用部にも適用） |
| R-AP-02 | 停電時は既設と同じ「通電時解錠型（施錠保持、居住者は機械キー）」を基本とし、施設の判断で解錠側に設定できる**こと** |
| R-AP-03 | 居住者の解錠は Aliro タップ（スマホ・ウォッチ）を第一とし、カードまたは暗証番号を併設**すること**（スマホを持たない居住者、子ども、高齢者） |
| R-AP-04 | 来訪者は集合玄関機の呼出しで住戸から解錠（既設のインターホン機能）、または時間限定の一時鍵（URL / QR）で入場できる**こと** |
| R-AP-05 | 配達・清掃・点検の業者には、曜日・時間帯付きの資格情報を発行でき、宅配ボックスの解錠と連動**してもよい** |
| R-AP-06 | 集合玄関機の解錠判定はミニサーバー不在でも玄関機（または玄関錠）内で完結**すること**。ミニサーバーは鍵の配布と記録の集約を担う |
| R-AP-07 | 既設インターホン系と連携する場合、無電圧接点（解錠出力、扉開閉入力）の仕様を設置前に確認し、玄関錠側の最小コントローラ（[20_interior_business.md](20_interior_business.md) 方式 B）を接点で並列接続**すること** |

### 3.4 住戸玄関

住戸玄関は居住者の「玄関」であり、同時に共同住宅では多くが防火設備（遮炎性能のある防火戸）に当たる。2 つの経路で組み込む。

| 経路 | 適用 | 電子部 | 認定 |
| --- | --- | --- | --- |
| 新設・建具交換 | [10_entrance_house.md](10_entrance_house.md)（自動車ラッチ、双安定レバー、通線） | 系統 1 + 系統 2（玄関と同じ 2 系統） | 扉・枠・自閉装置・錠のセットで防火設備の認定を製造者が取得。[30_fire_compartment.md](30_fire_compartment.md) のうち「確実に閉まる」（自閉を妨げない、2 段ラッチで確実に掛かる、閉鎖状態の報告）を適用。「解錠へ戻す」は住戸玄関には適用しない（避難は内側からの機械操作） |
| 既設扉への後付け | Matter Door Lock 認証品（コア R-EL-19）。集合住宅に多いプッシュプル錠は MIWA PiACK HOME PG が Matter 対応の後付け候補。Sesame は自前 BLE 経路 | 認証品の 1 系統 | 既設の防火戸の認定に影響しない範囲（追加工なし・配線なし）で行う。可否は管理組合・設計者が確認 |

| ID | 要求 |
| --- | --- |
| R-AP-30 | 住戸玄関の内側は施錠状態によらず常に機械的に開ける**こと**。自閉装置による閉鎖と掛かりを電子錠が妨げない**こと** |
| R-AP-31 | 居住者の Aliro 鍵 1 つで集合玄関と自宅の住戸玄関の両方が開き、他の住戸は開かない**こと**。鍵の配布と失効は親ミニサーバーから同じ API で行う（コア第 7 章） |
| R-AP-32 | 住戸玄関の解錠判定は住戸の錠内で完結し、ミニサーバー・ルーター・集合玄関機が止まっても居住者は入れる**こと** |
| R-AP-33 | 管理者・運用者（管理組合、管理会社）は住戸玄関を通常操作では開けられない**こと**。緊急開錠（安否確認、漏水等）は、居住者の事前同意または規約に基づく手順として、二人同時（コア 7.3）と事前通知を条件に実行でき、必ず監査ログに残る**こと** |
| R-AP-34 | 退去処理（R-AP-20）で住戸玄関の資格情報も同時に失効し、次の入居者の鍵は新規に発行**すること**。錠の機密鍵を再生成できる**こと** |
| R-AP-35 | 住戸玄関の監査ログは居住者に帰属し、管理側は R-AP-33 の緊急開錠と故障情報のみ閲覧できる**こと**。閲覧範囲は権限モデルで分ける |
| R-AP-36 | 新設の住戸玄関の通線（玄関プロファイル第 4 章）は、共用廊下側の弱電経路から各住戸の枠へ引き込む**こと**。既設扉の後付けでは通線を要求しない |
| R-AP-37 | 住戸内の室内扉や住戸ごとの子サーバーを置く場合、親ミニサーバーからの資格情報の配布と監査ログの集約は同じ API で行う**こと** |

## 5. 受入れ試験（応用側で実施できる範囲）

| 試験 | 合格条件 |
| --- | --- |
| ミニサーバー停止中の居住者入場 | Aliro タップ・カードで入場でき、復旧後にログが集約される |
| 退去処理 | 住戸の全資格情報が即時失効し、集合玄関で拒否される |
| 停電 | 内側から開く。設定どおり施錠保持または解錠 |
| 一時鍵 | 期限内のみ有効、期限後は拒否、使用は記録 |
| 既設インターホンからの解錠 | 接点で解錠され、玄関錠側にも記録が残る |
| 住戸玄関の鍵の範囲 | 居住者の鍵で自宅と集合玄関のみ開き、隣戸は拒否される |
| 緊急開錠 | 二人同時と通知なしでは開かず、実行時は記録が残る |
