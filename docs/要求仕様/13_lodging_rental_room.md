## 1. ほかの用途との違い

| 観点 | 住宅、事業所 | 宿泊、貸室 |
| --- | --- | --- |
| 使う人 | 家族、社員。同じ人が長く使う | 客、借りる人。一度きりか、短い間 |
| 期限 | 無いか、長い | 時刻で決まる。泊まる間、借りている時間だけ |
| アプリ | 入れてもらえる | 入れてもらえないことが多い |
| 鍵を出す側と使う側 | 同じか、同じ会社の中 | 利害が分かれる。入ったか、いつ出たかが、争いと料金の元になる |
| 人の居る受付 | あることが多い | 置かない運営が増えている |
| 法令 | 住宅、事業所の決まり | 宿泊は、本人確認と名簿の決まりがある |

## 2. 要求

### 2.1 鍵を出す、止める

| ID | 要求 |
| --- | --- |
| R-LR-01 | 宿と貸室の鍵の管理者は、その経営者とする**こと**。発行者の鍵は、経営者の機械の、取り出せない所に置く（コア R-AC-11）。予約を受ける仕組みは外の網に向いているので、発行者の鍵と同じ機械に置かない（コア R-AC-13） |
| R-LR-02 | 客と借りる人の鍵は、予約ごとに出し、部屋と、始まりと終わりの日時を持つ**こと**。扉は、自分の時計で期限を確かめる（コア R-AC-01、R-AC-02）。終わりを過ぎた鍵は、網が止まっていても通らない |
| R-LR-03 | 延長、早い到着、部屋の替えは、新しい鍵を出し、前の鍵を止めて行う**こと**。出した、止めたは、台帳に追記で残す |
| R-LR-04 | 清掃、点検、経営者の側の人の鍵は、部屋と、曜日と時間帯を限る**こと**。人が泊まっている間、借りている間の部屋を、経営者の側の鍵で開けたときは、客に知らせが届き、その記録を客が見られる。緊急のときに入る手順を決め、入ったことを記録に残す |
| R-LR-05 | 客室は、内側から、外からの通常の解錠を拒める**こと**（在室ロック。20 R-IN-15）。内側からは、いつでも機械で開く（20 R-IN-14） |

### 2.2 鍵を渡す道

| ID | 要求 |
| --- | --- |
| R-LR-10 | 客がアプリを入れなくても鍵を受け取れる道を、一つ以上持つ**こと**。道は、財布（Apple、Google）の鍵、受付で渡すカード、暗証番号、予約の知らせから開く一時の鍵とし、どれを使うかは経営者が決める |
| R-LR-11 | 財布の鍵は、認証と権限を分ける形で受ける**こと**（コア R-AC-25）。財布に鍵を載せる会社の署名は、鍵が本物であることの確かめにだけ使う。扉は、経営者の予約の仕組みが登録した鍵だけを、泊まる間、借りている間だけ通す。その会社には、誰がどの部屋に入れるかの台帳と、出入りの記録を渡さない |
| R-LR-12 | 写しの取れる鍵（暗証番号、画面に出す符号）を使うときは、部屋と期限を限り、使われたことが記録で分かる**こと**。端末の鍵に結んだ鍵（コア R-AC-21）より弱いことを、経営者が承知して選ぶ |
| R-LR-13 | 財布と、財布に鍵を載せる会社の仕組みが止まっても、カードか、暗証番号か、受付で開けられる**こと**（コア R-AC-18、R-RS-06） |

### 2.3 本人確認と名簿（宿泊）

| ID | 要求 |
| --- | --- |
| R-LR-20 | 宿泊では、本人確認が済んだ人にだけ鍵を渡し、その鍵が無ければ、宿泊する人だけが入る区域に入れない**こと**。本人確認の記録（いつ、どの方法で行ったか）と、鍵を出した記録を、同じ予約の下に結ぶ |
| R-LR-21 | 本人確認と名簿は、経営者の仕組みが受け持つ**こと**。扉と錠は、名簿も、旅券の写しも持たない。扉の記録には、鍵の識別だけを残す |
| R-LR-22 | 出入りを録画するカメラは、構内で録画でき（02 R-RD-13）、録画と扉の記録を、時刻で照らし合わせられる**こと**。扉とカメラの時刻を、同じ相手に合わせる |

### 2.4 記録

| ID | 要求 |
| --- | --- |
| R-LR-30 | 部屋の出入りは、扉が、連番と連鎖と署名のついた記録として残す**こと**（扉コントローラ仕様書 第 4 章）。扉の記録の鍵は、経営者が取り出せない所に置く。客は、自分が泊まった間、借りていた間の、自分の部屋の記録を見られる |
| R-LR-31 | 料金が時間や回数で決まる貸室では、入った時刻と出た時刻の記録を、料金の元として書き出せる**こと**（12 R-EB-12 と同じく、公開 API から書き出す） |

### 2.5 時間で貸す部屋

| ID | 要求 |
| --- | --- |
| R-LR-40 | 予約の始まりの前と、終わりの後は、借りる人の鍵で開かない**こと**。終わりの時刻に中に人が居ても、内側からは出られる。終わりの後に扉が開いたままのときは、経営者に知らせる |
| R-LR-41 | 予約と予約の間に、清掃と確かめのための時間を置ける**こと**。長さは経営者が決める |

足した要求の理由と確かめ方（2026-11-12）

- R-LR-01〜05
  - 出どころ：使う人の言葉「宿泊、貸室は、使えますね」「宿泊と貸室の記事と要求仕様も、公開の側に書く」（2026-11-12）。扉コントローラ仕様書 5.2b は、宿の鍵の管理者を経営者としている
  - 理由：宿と貸室の鍵は、予約のたびに出して止める。数が多く、期限が時刻で決まるので、扉が自分で期限を確かめる形でないと、網が止まったときに、終わった予約の鍵が通り続ける。予約を受ける仕組みは、外から届く所にあるので、発行者の鍵と同じ機械に置くと、そこを破られたときに、全部の部屋の鍵を作られる。経営者の側は鍵を出せるので、客の居る部屋に入ったことが、客に必ず伝わる形にする
  - 確かめ方：R-LR-02 は、網を切った疑似の扉で、終わりの時刻を過ぎた鍵が拒まれることを確かめる。R-LR-03 は、延長のあと、前の鍵が拒まれ、新しい鍵が通ることを確かめる。R-LR-04 は、客の居る部屋を経営者の側の鍵で開け、客に知らせが届くことを確かめる。R-LR-05 は、在室ロックの間、外からの通常の解錠が拒まれ、内側から開くことを確かめる
- R-LR-10〜13
  - 出どころ：同じ言葉。Apple と Google は、財布に入れられる鍵として、ホテルの鍵を挙げている（Apple Platform Security の Access key types、Google Wallet の Access の一覧。2026-11-11 に読んだ）
  - 理由：客は一度きりで、アプリを入れてもらえない。財布の鍵は、予約の知らせから入れられ、電話を開かずにかざせるので、宿に合う。財布に鍵を載せるのは、財布の制度に入った会社で、経営者ではない。認証と権限を分ければ、どの部屋に、いつ通すかは、経営者の手に残る。電話を持たない客、財布を使わない客のために、カードと暗証番号を残す。暗証番号は写しが取れるので、強さの違いを分かったうえで使う
  - 確かめ方：R-LR-11 は、財布に鍵を載せる会社の発行者の鍵で正しく署名した、登録していない鍵が拒まれること、登録した鍵が、泊まる間だけ通ることを確かめる。R-LR-13 は、その会社の仕組みを止めた状態で、カードと暗証番号で開くことを確かめる
- R-LR-20〜22
  - 出どころ：厚生労働省「旅館業における衛生等管理要領」の改正（令和7年3月11日改正、令和7年4月1日施行）。玄関帳場を置かない場合に、本人確認を受けた者に交付した鍵がなければ宿泊者専用区域に出入りできないこと、出入りの状況を顔を判別できる角度で録画することを求めている。本人確認の方法に、自動チェックイン機器等で、事前に共有した情報と照合する形が加わった。国土交通省の民泊制度ポータルサイトは、住宅を使った宿泊について、宿泊の開始までに宿泊者それぞれの本人確認を行うこと、名簿を 3 年間保存することを書いている
  - 理由：人の居る受付を置かない宿では、鍵が、本人確認の済んだ人だけに渡ることが、制度の条件になっている。本人確認の記録と鍵の記録が別々だと、後から照らし合わせられない。名簿と旅券の写しは、要配慮の情報を含むので、扉には持たせない
  - 確かめ方：R-LR-20 は、本人確認の済んでいない予約に鍵が出ないこと、鍵の無い人が、宿泊する人だけが入る区域の扉を開けられないことを確かめる。R-LR-21 は、扉の記録に、名前と旅券の番号が入っていないことを確かめる。R-LR-22 は、扉の記録の時刻と、録画の時刻のずれが、決めた範囲に収まることを確かめる
- R-LR-30、R-LR-31
  - 出どころ：使う人の言葉「第３社がいないと記録が信用できないからでしょう」（2026-11-12）
  - 理由：宿と貸室では、鍵を出す側と使う側の利害が分かれる。留守の間に誰かが入ったか、借りた時間を超えたかが争いになる。鍵を出す側だけがとった記録は、使う側から信用されない。出す側は、相手の名前の鍵を自分で作れるからである。財布に鍵を載せる会社が、鍵が本物であることを保証し（R-LR-11）、鍵が端末に結ばれ（コア R-AC-21）、扉の記録の鍵を経営者が取り出せなければ、扉の記録は、両方に通用する
  - 確かめ方：R-LR-30 は、記録の一件を書き換えたとき、連鎖の検べで分かることを確かめる。客の画面に、自分の部屋の、自分の期間の記録だけが出ることを確かめる。R-LR-31 は、書き出した記録と、扉の記録が合うことを確かめる
- R-LR-40、R-LR-41
  - 出どころ：同じ言葉
  - 理由：時間で貸す部屋では、終わりの時刻が、次の人の始まりになる。終わりを扉が確かめ、内側からは出られ、開いたままを知らせる形にする
  - 確かめ方：予約の前と後で鍵が拒まれること、終わりの時刻に内側から開くこと、開いたままのときに知らせが出ることを確かめる

## 3. ケース確認表（宿泊と貸室で加わる事象）

| # | 事象 | 期待する振る舞い | 要求 |
| --- | --- | --- | --- |
| 1 | 客が、予約の知らせから、財布に鍵を入れる | 財布に鍵を載せる会社が鍵を入れ、経営者の予約の仕組みが、その鍵を、部屋と期間に結んで扉に登録する | R-LR-10、11 |
| 2 | チェックインの前、チェックアウトの後 | 鍵は通らない。網が止まっていても同じ | R-LR-02 |
| 3 | 泊まる日を延ばす、部屋を替える | 新しい鍵を出し、前の鍵を止める | R-LR-03 |
| 4 | 電話を持たない客、財布を使わない客 | カードか、暗証番号で開ける | R-LR-10、12 |
| 5 | 本人確認が済んでいない | 鍵が出ない。宿泊する人だけが入る区域の扉は開かない | R-LR-20 |
| 6 | 清掃の人が入る | 部屋と時間帯を限った鍵で入る。客の居る間に入ったら、客に知らせが届く | R-LR-04 |
| 7 | 客が、留守の間に誰かが入ったかを知りたい | 自分の部屋の、自分の期間の記録を見られる | R-LR-30 |
| 8 | 経営者と客で、いつ出たかが食い違う | 扉の記録で確かめる。記録は、どちらも後から作れない | R-LR-30 |
| 9 | 財布に鍵を載せる会社の仕組みが止まる | カード、暗証番号、受付で開ける。登録していない鍵は通らない | R-LR-13、コア R-AC-25 |
| 10 | 貸室の予約の時間が終わる | 借りる人の鍵は通らなくなる。内側からは出られる。開いたままなら知らせる | R-LR-40 |
| 11 | 貸室の料金を、使った時間で決める | 入った時刻と出た時刻の記録を書き出す | R-LR-31 |
| 12 | 客が、室内に居る間、外から開けられたくない | 在室ロックで、外からの通常の解錠を拒む。緊急の手順は通る | R-LR-05、04 |
| 13 | 網が止まる | 扉は、入っている鍵と期限で、自分で判断を続ける。新しい鍵の登録と、記録の集まりだけが止まる | コア R-AC-10、R-NW-05 |

## 4. 認定・法規（確認先）

| 項目 | 内容 | 確認先 |
| --- | --- | --- |
| 旅館業 | 宿泊者名簿、本人確認の方法（対面、映像、自動チェックイン機器）、玄関帳場を置かない場合の条件（緊急のときの体制、本人確認と出入りの確認、鍵の受渡し）。自治体の条例で、条件が加わることがある | 保健所、自治体 |
| 住宅を使った宿泊 | 宿泊者名簿（3 年間の保存）、宿泊の開始までの本人確認、対面と同等の方法の条件 | 自治体、観光庁の窓口 |
| 外国から来た客 | 旅券の呈示と、写しの保存 | 保健所、自治体 |
| 避難 | 客室と避難の経路の扉は、内側から常に開くこと | 設計者、消防署 |
| 個人情報 | 名簿、旅券の写し、録画、出入りの記録の扱いと、保存の期間 | 経営者 |
| 貸室 | 建物の用途と、貸し方の決まり | 建物の持ち主、自治体 |

## 5. 受入れ試験（応用側で実施できる範囲）

| 試験 | 合格条件 |
| --- | --- |
| 期限 | 始まりの前と、終わりの後に、鍵が拒まれる。網を切っても同じ |
| 延長と部屋の替え | 前の鍵が拒まれ、新しい鍵が通る |
| 登録していない鍵 | 財布に鍵を載せる会社の署名があっても、経営者が登録していない鍵は拒まれる |
| 財布なしの入室 | カードと暗証番号で開く |
| 本人確認と鍵 | 本人確認の済んでいない予約に、鍵が出ない |
| 経営者の側の入室の知らせ | 客の居る部屋を経営者の側の鍵で開けると、客に知らせが届く |
| 客の記録 | 客の画面に、自分の部屋の、自分の期間の記録だけが出る |
| 在室ロック | 外からの通常の解錠が拒まれ、内側から開く |
