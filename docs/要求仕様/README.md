## 製造業としての位置づけ

製品の核は電動ラッチである。自動車ラッチの機構をそのまま建築扉に持ち込むので、耐久と静音は自動車の水準、価格は機械錠の水準になる。

## 第一の開発目標：ドア用電動ラッチ

- 自動車用サイドドアラッチを建築扉の電子錠に転用した製品は確認できない。自動車用ラッチは日本メーカーが世界シェア上位を占め、耐久・静音・単価の水準が建築錠と異なる。これを建築錠の市場に持ち込む
- 開発の範囲は自動車ラッチの建築扉用への派生。双安定レバー（無通電で施錠モードを保持し、オートロックの有無を運用中に切替）、2 段ラッチとセンサー（半ドアの検出）、扉側給電に合わせたアクチュエータ、建築の公差（垂れ、反り、季節変動）への追従。目標は自動車ラッチの耐久と静音を建築錠の価格で実現すること

## なぜ現状のドア用電子錠ではなく、電動ラッチなのか

現状のドア用電子錠は、既存の錠前（デッドボルト、サムターン）にソレノイドまたはモーターを付加した構成である。施錠の動作と保持に通電が要り、通電時解錠型か通電時施錠型かは施工時に固定され、制御は各社の制御盤かクラウドに依存する。電動ラッチは自動車ラッチの機構を基に、掛かりをラチェットとポール、施錠モードを双安定レバーで持ち、通電は切替時のみとする。コストは機械錠と同じ水準に収まる（下表）。

| 電動ラッチにする理由 | 何が変わるか |
| --- | --- |
| **コストパフォーマンスが高い（機械錠と同じ価格帯で、規格対応の電子錠付き扉になる）** | 機械錠と比較して、扉 1 枚の錠の部分を機構・電子部・通線の順に積み上げると（下の計算）、機構は電動ラッチの方が安く、電子部・通線・現場の取付まで含めた扉全体でも、機械錠の扉に 1〜3 万円を足した価格に収まる。既存の電子錠（有線の電気錠システムで 1 扉 20〜30 万円、後付けの電動サムターンで 5〜8 万円）が届いていない価格帯である |
| 閉めるだけで施錠が成立する | ラチェットがバネで掛かるので、施錠に電気を使わない。停電中も閉めれば施錠される |
| オートロックの有無を運用中に切り替えられる | 双安定レバーで外ハンドルの結合・切り離しを切り替える。切替の一瞬だけ通電し、保持は無通電。既存の電気錠は施工時に型を固定する |
| 半ドアを機構で検出する | 2 段ラッチで半ドアと全閉を機構的に区別する。無人運用の「施錠表示なのに半ドア」が起きない |
| 待機電力がゼロで、動作は一瞬 | 双安定の保持は無通電。電池とバックアップ電源が小さくて済み、停電時も最後の解錠ができる |
| 自動車の耐久・静音・量産品質 | 10 万回級の耐久、静かな動作音、量産の品質と価格。数十年設計の変わっていない建築錠と比べて桁が違う |
| 内側からは常に機械で開く | 自動車のオーバーライド機構。施錠モードによらず内ハンドルで出られる |
| 制御が開いている | 錠の中に Matter / Aliro の認証品と自前の制御を持てる。特定の制御盤やクラウドに閉じず、認証品どうしで交換できる |
| 扉と一体で設計できる | 錠ケースの寸法に縛られず、扉メーカーがハンドルと見付けを設計できる。扉とラッチを同じ会社が作る |
| 日本が強い部品である | 自動車ラッチは日本メーカーが世界シェア上位。その品質と価格を建築の錠に持ち込むのは扉を持つ製造者にしかできない |

機構の推定の根拠：自動車の補修部品は、納入価格に流通と補修の費用を乗せて小売価格になるため、小売が納入価格の 3〜4 倍になるのが通例である。年 1〜2 万個という数量は自動車の量産（年数十万〜数百万個）より少ないので、型と工程の償却で単価は上がるが、それでも機械錠の錠ケース 1 個（仕入れ 0.6〜0.7 万円）と同じか安い。この数字は Go-Tech の 1 年目に試作と見積りで確定する。

既存の電気錠との詳しい比較は [annex_latch_vs_miwa.md](annex_latch_vs_miwa.md)。

## 第二の開発目標：規格対応ドア

- ラッチを組み込んだ Matter / Aliro / ONVIF 対応の電子錠埋込型ドア（玄関、住戸玄関、室内扉）。扉・枠・ラッチ・扉側電子部・通線・認定をセットで開発し、ドア製造者の扉の本業の延長として国内の新規市場に出す
- 玄関の電子部は独立した 2 系統（Aliro + 自前 BLE、Matter）と無線を持たない安全 MCU。通線は Ethernet と多芯線に予備の空配管。集合住宅では 4 点セット（集合玄関機 + ルーター + ミニサーバー + 玄関用装置）として売る

## 2 つの販売

| 販売 | 何を売るか | 相手 |
| --- | --- | --- |
| 部品販売 | ドア用電動ラッチ。性能（耐久、静音、保持力、消費電力）の数字で売る。国内の扉メーカー・錠メーカーへ販売し、海外へは輸出または技術提携で出す | 扉・錠のメーカー |
| オープン規格ドア事業 | ラッチを組み込んだ Matter / Aliro / ONVIF 対応の電子錠埋込型ドア（玄関、住戸玄関、室内扉）と、集合住宅向けの 4 点セット（集合玄関機 + ルーター + ミニサーバー + 玄関用装置）、その保守 | 管理組合、管理会社、事業所、個別住宅 |

- 部品販売は性能で勝負する。国内の 3 年で数字と実績を作り、規格対応が世界で落ち着いた後に「機構が違う」部品として入る
- オープン規格ドア事業は新規市場（オープン規格ドア市場）を作る。既存の電気錠・スマートロック市場での競争ではなく、「ウォレットの鍵で開く扉」「メーカーを問わず組み合わせられる」「規格改定に追従して長く使える」という価値を買い手に示す。扉単体ではなく、関連製品を含めた入退室の仕組み一式で提案する

## 製品と技術方針

| 項目 | 方針 |
| --- | --- |
| 適合の基準 | 公開規格を優先する。錠は Matter Door Lock + Aliro、カメラは ONVIF / RTSP（Matter 1.5 カメラは望ましい）。認証品であれば製造元を問わない |
| 玄関の電子部 | 独立した 2 系統（系統 1：Aliro + 自前 BLE、系統 2：Matter）と、無線を持たない安全 MCU。片方が止まっても解錠できる |
| 通線 | Ethernet と多芯線の 2 系統に、予備の空配管を加える |
| 室内扉 | 扉と枠の条件に応じて、クラッチ式（通線あり）か電気ストライクなどを選ぶ。壁側の装置は最小限のコントローラとし、扉とともに出荷する |
| 用途別 | 玄関（個別住宅、集合住宅、事業所）、室内扉（業務用、家庭用）、防火区画を、それぞれ別のプロファイルで扱う |
| ユニバーサルデザイン | 全プロファイル共通。誰でも開けられ、誰も閉じ込めない。脱出操作は片手・握らず・小さな力、操作部の高さ、視覚・聴覚・触覚の 2 つ以上で報知、複数の認証手段、介助者の鍵、画面は JIS X 8341-3 AA 相当、日本語と英語 |
| 安全のためのセンサー | 全プロファイル共通。扉間の障害物では施錠しない、火災・感震・ガスの安全入力は安全 MCU に直接入れてネットワークに依存せず扉ごとの設定で解錠側へ倒す、自動再施錠しない、無動作・転倒の通知、指はさみは構造で防ぐ |

## ソフトウェア（2 つの担当、AI を使う）

| 担当 | 仕事 | 担う範囲 |
| --- | --- | --- |
| ラッチ担当のソフトウェア開発者 | **錠の部品メーカーとして生きていけるようにする**（ラッチを部品として販売できるようにする） | ドア事業と同じく、規格対応と API 化である。Matter / Aliro のリーダー（扉側電子部：2 系統）と ONVIF 対応で認証品からラッチを動かし、性能の数字（耐久、静音、保持力、消費電力）を試験で出してデータシートにし、扉メーカー・錠メーカーに実演できる状態にする。**自社と国内向けには制御部分まで開発する**：安全 MCU のファーム（駆動、センサー、施錠モード、安全入力）と、系統 1 / 系統 2 からの制御の取り決め（コア別添 B）を作り、扉側電子部として規格対応ドアに載せる |

- ドア事業のソフトは、結局は**規格対応**（Matter / Aliro / ONVIF で錠・リーダー・カメラが動くこと）と、**よく使う操作の API 化**（鍵の発行と失効、時間帯、状態の取得、記録の書き出し、更新の配布）である。API があれば、管理会社の画面も業者の道具も他社のアプリも、その上に誰でも作れる
- ドア事業でドア固有に要求されるソフトウェアの例（要求書に入れるもの）
  - 半ドア・扉間の障害物を 2 段ラッチのセンサーで検出し、施錠を保留して通知する
  - 火災・感震・ガスの安全入力に対する扉ごとの振る舞い（解錠側へ倒す／保持／通知）の設定と、安全解錠後に自動再施錠しない制御
  - オートロックの有無と通行モードの時間帯設定、終了時刻の通知
  - 集合住宅の住戸単位での鍵の一括発行・失効（入居・退去）と、居住者の鍵 1 つで集合玄関と自宅だけが開く範囲の設定
  - 集合玄関機や既設の電気錠システムとの無電圧接点による連携
  - 来客・業者向けの時間限定の鍵（URL / QR）と、スマホを持たない人向けのカード・暗証番号の併用
  - 扉ごとの構成記録（ラッチ型式、電子部のシリアル、ファーム版）と、更新配布（段階配布、切り戻し、互換表）
  - 管理会社の初動チェックリストと、保守記録の書き出し
- どちらも Matter / Aliro / ONVIF の改定を追う。版が上がったときに、ラッチ・扉側電子部・アプリケーションのどこを変える必要があるかをドキュメントに書き、変える部分のプログラムを直し、直したプログラムを納入済みの扉のミニサーバーと扉側電子部に送って入れ替える
