扉を作る会社が、ウォレットの鍵を出す会社になるには

技術は Apple と Google が作った物を使う。課題は、守りを作れるかどうかだけ

2026.11.14

扉がスマートフォンで開くために作る技術は、難しくありません。スマートフォンとウォレットは Apple と Google が、スマートフォンとリーダーの間のやり取りは規格団体の CSA(Connectivity Standards Alliance)が作っていて、扉を作る会社はそれを使うだけだからです。課題は一つです。会社として、セキュリティ対策ができるかどうか。この記事は、扉を作っている会社の経営、情報システム、開発の人に向けて、その事を順に説明します。

Apple、Google、CSA が正式に書いている事と、このサイトの考えは分けて書きます。この記事の内容は、2026年11月14日に確かめた物です。

扉は、スマートフォンで開く所に行き着く

ここは、このサイトの考えです。理由は四つあります。

  1. 扉は、開ける人が持っている物で開けるしかありません。 機械の鍵、カード、暗証番号と、開ける人が持ち歩く物は変わってきました。今、誰もが持っている物はスマートフォンです。
  2. 扉の鍵は、スマートフォンの中で最も高度に守られた部分に入ります。 支払いのカードや車の鍵と同じ所です。そこに鍵を入れるには、Apple と Google の審査を通るしかありません。
  3. 扉は、買った人のスマートフォンを選べません。 一つの扉を、iPhone の人も Android の人も使います。Apple と Google の両方が要ります。
  4. 自社のアプリだけで開ける道は、その守られた部分を使えません。 アプリが BLE で鍵を示す形は今でも組めますが、鍵はアプリの中にあり、守られた部分には入りません。iPhone でアプリから守られた部分を使う道(NFC & SE Platform)もありますが、これも Apple の審査を通る道です。

戸建ての家では、住む人がホームアプリに錠を登録すれば、ウォレットに鍵が入ります(Google Wallet に戸建ての家の鍵が入る、戸建てと事務所で、スマートフォンの鍵をどう持つか)。この道では、鍵を出すのも止めるのも住む人です。この記事が扱うのは、扉を作る会社が鍵を出す側に立つ形です。鍵の出し直し、持ち主の交代、作業用の鍵まで会社が受け付けるには、会社が制度に入る必要があります。

会社が発表している事

  • Google は、2026年11月9日付の Google Play services v26.44 のリリースノートで、Matter と Aliro に対応した戸建て住宅の鍵を、Google Home から Google Wallet に足せるようにしたと書きました(Google Wallet に戸建ての家の鍵が入る)。Google Wallet の Access の頁には、社員証、ホテルの鍵、集合住宅の鍵、学生証、車の鍵が並んでいます。
  • Apple は、ウォレットに入館の鍵を入れる制度として Apple Wallet Access Program を持っています(戸建てと事務所で、スマートフォンの鍵をどう持つか)。

扉を作る会社の今の位置

扉を作る会社が、自社のアプリでスマートフォンを鍵にする例は、公開されています。

  • LIXIL は、玄関ドアの電気錠 FamiLock を、アプリ My Entrance を入れたスマートフォンで開けられると、製品の頁に書いています。
  • YKK AP は、スマートドアの専用アプリ「スマートコントロールキー」を出しています。App Store の説明では、ドアに近づいてハンドルのボタンを押すと施解錠でき、鍵の追加と、なくした鍵の削除もアプリでできます。
  • ドイツの Hörmann は、玄関ドアとガレージの扉を、アプリ Hörmann BlueSecur を使い、Bluetooth でスマートフォンから施解錠できると、製品の頁に書いています。

どれも、扉を作る会社のアプリの中で鍵を持つ形です。ウォレットの鍵を自分で発行している扉の製造者は、2026年11月13日に調べた範囲では見つかりませんでした。

作る物は、ほとんど無い

ウォレットの鍵で開く扉の部品のうち、ほとんどは買う物か、使う物です。

[cols="2,3,2"]

部分 何を使うか 誰が作るか
スマートフォンとウォレット iPhone と Apple Wallet、Android のスマートフォンと Google Wallet Apple、Google
スマートフォンとリーダーの間のやり取り Aliro 1.0 CSA
電子錠とリーダー Aliro と Matter の認証を取った製品を買う 錠とリーダーの会社
スマートホームへの登録 Matter CSA

扉を作る会社が自分で持つのは、次の物です。

[cols="2,4"]

自分で持つ物 中身
鍵の受け付けと実行 鍵を出す、止める、出し直す
台帳と記録 どの扉に、どの鍵を、いつ出し、いつ止めたか

扉のコントローラ 扉の中で鍵を確かめ、記録を残す

Aliro が決めているのは、スマートフォンとリーダーの間だけです。鍵の発行と、その後の業務は、Aliro の範囲の外にあります(Aliroとは何か)。この自分で持つ部分の仕様と参照実装は、このサイトで公開しています(扉のコントローラの仕様と試験の道具を公開する、マニュアル)。

課題は、守りを作れるかどうか

Apple が書いている事

Apple の NFC & SE Platform の頁は、申し込む会社に、たとえば次の事を求めています。

  • 個人情報の扱いに当てはまる、セキュリティと個人情報の決まりを満たす事
  • 個人情報の扱い(第三者に渡す事を含む)と、脆弱性の扱い(届け出を受け、調べ、直す事)について、文書にした方針と手順を持つ事。権限を受ける前に用意しておく事
  • 実際に悪用されている脆弱性や、セキュリティの事故があったときに、遅れずに Apple に知らせる手順を持つ事
  • スマートフォンの守られた部分に入れるプログラムを、認定を受けた独立の試験所に確かめてもらう事
  • 商業上の条件と料金を定めた Apple との取り決めと、秘密保持の取り決めを結ぶ事
  • 対象の国と地域に会社がある事。日本は対象に入っています

用途の一覧には、家の鍵、社員証、ホテルの鍵などが挙がっています。料金があることは書かれていますが、額は書かれていません。

Apple Wallet Access Program のガイドでは、参加は Apple に質問票を求めるところから始まります。質問票を出した後、Apple から招かれると、Apple Business Register という協力先の場に入り、実装のガイドを受け取ります。ガイドは、参加する会社の役割と要件を定めています。要件には、責任者と技術の窓口と夜間の窓口を決める事、本番の稼働率 99.99%、複数の地域に分けた備え、Apple がリーダーを試験して認証する事などが並んでいます。鍵をスマートフォンに入れ、止める主となる会社を、ガイドは Credential Manager と呼んでいます。

Google が書いている事

Google Wallet の社員証の始め方の頁は、開発者の頁の限られた部分を見るには NDA が要る、と書いています。条件は、NDA を結んだ後に見られる形です。

審査で見られる事

ここからは、このサイトの考えです。公開されている要件を読むと、審査で見られるのは、会社の大きさや付き合いではありません。自分で作り、自分で守れるかどうかです。方針と手順を文書にし、脆弱性を受け付けて直し、事故を知らせ、試験所の確かめを通る。どれも、会社の中にその仕事を担う人がいなければできません。

この表は、このサイトの考えです。

鍵を発行する会社が、すべての管理を受け付ける

ここは、このサイトの考えです。

ウォレットの鍵をスマートフォンに入れられるのは、制度に入った会社だけです。そのため、鍵を出す、止める、出し直す、スマートフォンの買い替え、扉の持ち主の交代、作業用の鍵、問い合わせは、全部その会社が受け付けることになります。

二つの原則から、そうなります。

  • 確かめられる所だけが、受け付けられる。 ゼロトラストの考え方では、依頼は、確かめられる所で受けます。ウォレットの中の鍵の状態を確かめ、入れ、止められるのは、鍵を発行する会社の仕組みだけです。
  • 責任を負う所が、動かせる所でないといけない。 鍵が誤って出たときに説明するのは、鍵を入れた会社です。動かせない所が責任だけを負う形は、回りません。

自動車の鍵では、自動車の会社が一社で鍵とアプリと窓口を受け持っています。ウォレットの鍵の扉も、これと同じ形に近づきます(デジタルドアが遅れている理由 の「自動車の鍵との違い」)。

ただし、誰に鍵を出し、いつ止めるかを決めるのは、扉の持ち主と建物の管理者のままです(デジタルキーは管理者が自分で持つ)。鍵を発行する会社は、持ち主が入れた通りに実行し、記録を残す側です。このサイトの決めでは、ウォレットに鍵を載せる会社の署名は鍵が本物である事の確かめにだけ使い、扉は持ち主が登録した鍵だけを通します(R-AC-25。戸建てと事務所で、スマートフォンの鍵をどう持つか の「認証と権限を分ける」)。受け付けるのは発行する会社、決めるのは持ち主、という分け方です。

受け付けが一社に集まると、その会社が攻められた時の被害も大きくなります(業者に預けた鍵と権限)。だから、その会社の中を分けます。受け付ける所は鍵を出せず、鍵を出す所は相手を知らない形にします。次の二つの節は、その分け方です。

会社の形。新しく作るのは二つだけ

ここは、このサイトの考えです。

会社
├─ 本社(鍵の情報の側)
│   ├─ 管理部門     数とお金
│   ├─ 工場       製造番号、錠の中身
│   └─ 鍵の部門     鍵を配る。署名の鍵、匿名の台帳
└─ 営業所(利用者の情報の側)
    ├─ 販売       申し込み
    ├─ メンテナンス   修理と点検
    └─ 鍵の管理     依頼を受け付けて、伝票にする

デジタルドアになると、安全のために、一つの会社の中で、扉の生産と扉の販売を独立した部門として持つことになります。本社は扉の生産と鍵の配布を、営業所は扉の販売とメンテナンスを受け持ちます。利用者の情報と鍵の情報は共有しません。本社の鍵の部門の台帳は、鍵の識別子と扉の製造番号で引く物で、利用者の名前を持ちません。

六つの部門のうち、管理部門、工場、販売、メンテナンスは、今ある仕事です。新しく作るのは、本社の鍵の部門と、営業所の鍵の管理の二つだけです。扉を作るのも、売るのも、今のままです。工場に足すのは、最後の工程です。

  • 錠とリーダーを組み込む
  • 製造番号を付けて、錠の中身を入れる
  • 確かめて出す

営業所の負担は小さくて済みます。営業所は鍵に触らず、依頼を受けて、決まった形の伝票を書くだけだからです。難しい所は、本社の鍵の部門の一か所に集まります。

鍵は、次の道で動きます。

利用者 → 営業所の鍵の管理 → 伝票 → 本社の鍵の部門 → 利用者のスマートフォン

営業所は相手を知っていますが、鍵を出せません。本社は鍵を出せますが、相手を知りません。電子証明書を出す認証局が、本人を確かめる登録局と、証明書を出す発行局を分けているのと同じ分け方です。

区画で止める。防火区画と同じ

ゼロトラストは、建物の防火区画で考えると分かりやすくなります。建物は、火が出ない事を前提にせず、火は出る物として、区画で燃え広がりを止めます。会社のシステムも、侵入されない事を前提にせず、侵入はされる物として、区画で止めます。

  • 区画ごとに、別のネットワーク、別の認証、別の担当者にします
  • 壁を通すのは、決めた形の伝票と、数だけです
  • 壁では、次の事を確かめます。形が決めた通りか。署名が正しいか。入っていてはいけない物(利用者の名前を本社へ、鍵の中身を営業所へ)が入っていないか。向きが決めた通りか。通した事を記録したか
  • どの区画も、ほかが止まっても自分だけで動きます。工場は工場だけで、営業所は営業所ごとに、鍵の部門は鍵の部門だけで動きます
  • クラウドに頼りません。区画の間のやり取りは、ためておいて後で渡せる形にします

この考え方を、ソフトウェアを作る業者に、自分の言葉で言えることが大切です。言えなければ、業者の作りやすい形で、一つにつながったシステムが納められます。関係する話は、サイバー攻撃に耐える扉、デジタルドアはサイバー攻撃対策そのもの、業者に預けた鍵と権限、自分で持つべき人と物 に書いています。

利用者の情報を、会社が持たない

Aliro の作り

Aliro 1.0 の仕様(CSA、文書 26-42802-001、2026年2月18日)を読むと、利用者を追いかけにくい作りになっている事が分かります。要点を、このサイトの言葉でまとめます。

  • 仕様の範囲は、スマートフォンとリーダーの間の NFC と BLE のやり取りです。リーダーと鍵を決める者の間や、スマートフォンと鍵を発行する者の間は、範囲の外です(1.1 節)
  • かざした後の最初の段では、先にリーダーが、自分の長く使う鍵で署名して、本物のリーダーである事をスマートフォンに示します。双方は使い捨ての鍵から共通の鍵を作り、暗号をかけた通り道を開きます。スマートフォンが自分の公開鍵の識別子を示すのは、その通り道の中だけです(8.1.1 節)
  • 仕様は、偽のリーダーがスマートフォンから固定の識別子を取り出したり、そのスマートフォンが特定のリーダーと関係を持つかを探ったりできないようにする事を、目的として書いています(8.1.1 節)
  • 鍵の文書(Access Document)には ID の欄がありますが、その中身は仕様の範囲の外です(7.3.2 節)。鍵と人を結び付けるのは、Aliro の外、鍵を発行する側の台帳です

連絡は、利用者の方から来る

ここからは、このサイトの考えです。鍵が人の名前を運ばないので、会社が名簿を作って利用者を追いかける形にはなりません。連絡は、利用者の方から会社へ来る形になります。窓口は、利用者のスマートフォンの画面です。鍵を止めたい、出し直したい、という依頼は、利用者がスマートフォンから営業所の鍵の管理へ出し、伝票になって本社へ渡ります。

始める順

ここは、このサイトの考えです。

  1. 情報システムと開発の担当者が、AI を自由に使えるようになる。 方針と手順の文書も、区画を分けたシステムも、担当者が AI と一緒に自分で作る物です(AI の時代に、委託をやめて自社で育てる、AI で自社のシステムを確かめる)。
  2. 今のネットワークとは別に、新しい区画と開発環境を作る。 スマートフォンを使う世代の消費者が使っている物を買って、実験できるようにします。iPhone、Android のスマートフォン、Mac、Linux、Aliro と Matter に対応した錠、ドアホンです。規格を決めている CSA の最上位の会員(Promoter)は、2026年11月14日に CSA の会員の頁で数えると 33 社で、スマートフォン、半導体、錠、家電の会社が並んでいます。この顔ぶれから見ると、開発の道具も Mac と Linux が中心になります。同じ日に確かめた Promoter の一覧に、Microsoft の名前はありませんでした。
  3. Google と NDA を結び、Apple に問い合わせて、条件を聞く。
  4. 条件に合わせて、セキュリティの方針と手順を、担当者が自分で書く。
  5. 申請する。

情報システムの部門は、セキュリティを理由に、開発の担当者の道具と実験を必要以上に縛らないようにします。新しい区画を今のネットワークと別に作るのは、そのためです。今のネットワークの決まりは今のネットワークを守り、新しい区画は新しい区画の決まりで守ります。

分かっていない事

2026年11月14日の時点で、次の事は会社と団体の公開の資料に見つかりませんでした。

  • Google Wallet の鍵の制度に入る審査の基準と料金。NDA を結んだ後に見る形です
  • Apple Wallet Access Program と NFC & SE Platform の料金の額
  • Apple Wallet Access Program の対象の国
  • Google Wallet の戸建ての家の鍵を、扉を作る会社が自分で発行する道があるか
  • 審査にかかる期間
