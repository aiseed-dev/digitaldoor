扉のコントローラを Rust で書く

仕様とテストを残したまま、参照実装から製品の実装へ移す道筋

2026.10.19

扉のコントローラは、火災の信号や停電のときに扉を開けるか閉めるかを決め、起きたことを署名つきの記録に残す層です(扉のコントローラの仕様と試験の道具を公開する)。このサイトが公開している疑似の扉と試験の道具は Python で書いてあります。仕様を確かめ、リーダーや管理ソフトを作る人が実機なしで相手にするための物です。

製品として扉に組み込み、十年単位で現場で動かす実装は別の話です。この記事では、製品の実装に Rust が向いている理由、製造者が選ぶ所、仕様とテストを残したまま実装を移す道筋を説明します。どのコンピューターに載せるかは、扉メーカーが製品ごとに選びます。

なぜ Rust か

メモリを壊す欠陥を、組む段で締め出せる

C や C++ で書いたソフトウェアの脆弱性は、多くがメモリの扱いの誤り(範囲の外を読み書きする、解放した領域を使う)から生まれます。Rust は、この種類の誤りを、コンパイルの段の検査と、実行時の範囲の検査で止めます。

  • Google は、Android の脆弱性に占めるメモリの扱いの誤りが、2019年の 76% から 2024年には 24% まで下がったと書いています。新しく書く部分を、メモリを安全に扱える言語に移していった結果です(2024年9月25日、Google Security Blog)。
  • 米国の CISA と FBI は「Product Security Bad Practices」(2.0 版、2025年1月)で、重要な社会基盤に使う製品の新しい製品群は、メモリを安全に扱える言語で作るよう求めています。既存の製品には、メモリの安全への移行の計画を 2025年の末までに公表するよう求めています。拘束力のない指針です。

扉のコントローラは、ネットワークにつながり、署名と記録を扱い、火災のときの開け閉めを決めます。メモリを壊す欠陥が、そのまま扉の安全の欠陥になる場所です。

小さなコンピューターにも、一つのバイナリにも組める

Rust は、OS の無いマイコンでも動きます(no_std。標準ライブラリのうち OS に頼る部分を使わない形)。マイコン向けには、非同期の実行環境(Embassy)や、割り込みで動かす枠組み(RTIC)があります。Linux の基板に載せるなら、静的に結んだ一つのバイナリにできます。

一つのバイナリは、運用で扱いやすい形です。置き換えるのは一つのファイルで、確かめる値(sha256)も一つです。組むときには、全体をまとめた最適化(LTO)、記号を落とす、panic のときに巻き戻さず止める、などで小さく速くできます。組む道具のバージョンを固定し、日時を埋め込まなければ、同じソースから同じバイナリができます。手元で組み直した値と、扉に入っている物の値を照らせば、本物かどうかを確かめられます。

安全規格の認証に使える道具がある

火災のときの開け閉めを扱う製品は、機能安全の規格(IEC 61508 など)で認証を受けることがあります。そのとき、コンパイラが認証に使える物かどうかが問われます。

Ferrous Systems の Ferrocene は、Rust のコンパイラを安全規格に合わせて認定した物です。2025年12月3日の 25.11.0 の時点で、TÜV SÜD による ISO 26262(ASIL D)、IEC 61508(SIL 3)、IEC 62304(Class C)の認定を受けています。同じバージョンから、Rust の core ライブラリの一部が IEC 61508(SIL 2)の認証を受けています。

道具が認定されていても、製品が認証されたことにはなりません。製品の認証は、扉メーカーが製品ごとに取ります。道具の側で道が開いている、という意味です。

Python と組める

Rust の関数と型は、PyO3 で Python に見せられます。maturin で組み済みの wheel にすれば、使う側は pip install だけで済み、コンパイラは要りません。

この形はすでに広く使われています。扉のコントローラの参照実装が署名(Ed25519)に使っている cryptography も、中身の多くは Rust です。35.0.0(2021年9月29日)から、組むのに Rust が必要になっています。

型の検査が、書いた物を確かめる

Rust のコンパイラの型の検査は、unsafe を使わない部分について、メモリの扱いとデータの取り合い(複数の処理が同じデータを同時に書き換えること)に誤りが無いことを保証します。AI が書いたコードでも、人が書いたコードでも、同じように確かめられます。テストを動かして確かめることは、それでも要ります。型が確かめるのは仕組みの誤りで、扉の振る舞いが仕様のとおりかどうかは、テストが確かめます。

製造者が選ぶ所

どのコンピューターに載せるかで、作りが変わります。どれを選んでも、判断の核は同じ物を使えるように作ります(次の節)。

形 向いている所 気をつける所
マイコン一つ 部品が少なく、電力が小さい。OS の更新が要らない ネットワーク、TLS、HTTP、記録の置き場が小さなコンピューターには重い
Linux の基板と、安全側のマイコン ネットワーク、HTTP、Matter の橋、記録の置き場を Linux が持つ。接点と安全側の挙動はマイコンが持つので、Linux が止まっても内側から開けられる OS の更新と監視が要る。二つの間のインターフェースを決める
マイコン二つ(判断と安全側) 判断も安全側も小さく保てる。安全側を単純にして認証を取りやすくする ネットワークのインターフェースをどちらに置くかを決める

安全側のマイコンとの分け方は、要求仕様の電子部の 2 系統(共通コアの R-EL)と、電動ラッチの性能(05_latch の R-MC)に関わります。火災のときに扉を開ける、停電のときに設定どおりに振る舞う、内側から機械で開けられる、という挙動は、判断の側が止まっても保たれるように置きます。

核と入出力を分ける

製品の実装は、仕様の層の分け方をそのまま crate(Rust の部品の単位)の分け方にすると、載せるコンピューターを替えても核を使い回せます。

部品 中身 載せるコンピューター
判断の核 判断の表(火災、停電、非常手段、二人同時、強要、自動施錠)と設定。入力の事象から、出力と記録を決めるだけ どれでも(no_std)
監査の記録 記録の形、hash の連鎖、署名のインターフェース(Signer)、伝票の形 どれでも(no_std)
資格情報 署名つきの資格情報を確かめる(形、発行者、署名、範囲、期限、使用済み) どれでも(no_std)
入出力 接点、HTTP のインターフェース、Matter の橋、記録の置き場、時計 コンピューターごとに作る
  • 接点は trait にする。 錠の銘柄は接点の下に隠します(R-CT-03、04)。判断の核から見えるのは、火災、電源、扉の開閉、デッドボルトの位置、施錠と解錠の出力だけです。
  • 署名のインターフェースも trait にする。 開発ではソフトの Ed25519 を使い、製品ではセキュアエレメント(STSAFE など)に差し替えます。秘密鍵は、セキュアエレメントの外に出しません。
  • 判断の核は、時計を外から受け取る。 時刻を引数で渡せば、実時間を待たずに、自動施錠や時刻のずれを試せます。参照実装の tick と set_time と同じ考え方です。

テストを残して実装を移す

正は仕様です。テストは、確かめる要求の番号を先頭に書いて、仕様とつないであります(適合の現在)。実装を Rust に移しても、仕様とテストは残ります。

  1. 言語に依らない試験の値を作る。 判断の表の入力と出力、監査の記録の hash と署名、資格情報の判定と断る理由を、JSON の値にします。Ed25519 の署名は、同じ鍵と同じ内容なら同じ値になるので、固定の値として書けます。Python の参照実装と Rust の実装が、同じ値で確かめます。
  2. 核を Python に見せて、今のテストを当てる。 PyO3 で判断の核を Python に見せれば、参照実装の 105 件のテストを、Rust の核にそのまま当てられます。
  3. 移す順番を決める。 判断の表、監査の連鎖と署名、資格情報、入出力の順に移します。前の物が通ってから次に進みます。
  4. 移す前に、参照実装で見つかっている点を直す。 直さずに移すと、Rust の実装に引き継がれます。今見つかっているのは次の三つです。
    • 一度だけ使える資格情報は、解錠より前に、使ったことを記録に書く。逆の順だと、電源が落ちたときに二度使えてしまう
    • 使用済みかどうかは、発行者と識別子の組で数える。識別子だけだと、別の発行者の同じ識別子と取り違える
    • 署名を確かめる前の文字列(発行者、識別子)を、そのまま記録に書かない

参照実装は、移した後も残します。仕様を確かめ、リーダーや管理ソフトを作る人が実機なしで相手にするための物で、役目は変わりません。

仕様書との関係

このサイトが持つのは、仕様と、言語に依らないテストです。製品の実装は扉メーカーが作り、どの番号を満たすかを申告します。仕様は「何を満たすか」だけを書き、どの言語で書くかは決めません。Rust は、この記事が勧める選び方の一つです。

関係する要求は次のとおりです。

  • R-CT-03、04: 錠の銘柄を接点の下に隠す(接点の trait)
  • R-CT-11〜16: 監査の記録(記録の部品)
  • R-CT-17: 署名つきの伝票(署名のインターフェース、伝票の形)
  • 5.2a: 署名つきの資格情報(資格情報の部品)
