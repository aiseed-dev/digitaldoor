戸建てと事務所で、スマートフォンの鍵をどう持つか

ホームアプリ、ウォレット、自分で出す鍵。誰が鍵を出し、誰が止めるかから決める

2026.11.11

スマートフォンで扉を開ける道は、いくつもあります。ホームアプリに錠を登録する道、ウォレットに鍵を入れる道、ウォレットを通さないアプリで開ける道です。どれを選ぶかは、技術の良し悪しよりも先に、誰が鍵を出し、誰が止めるかで決まります。

戸建ての家と事務所では、この答えが違います。戸建てでは、鍵を出すのも止めるのも住む人です。事務所では、会社が社員に鍵を出し、退職の日に止めます。この記事では、三つの道を並べ、戸建てと事務所のそれぞれで、どの道を使い、扉の側で何を決めておくかを書きます。会社が正式に書いている事と、このサイトの考えは分けて書きます。この記事の内容は、2026年11月11日に確かめた物です。

鍵をスマートフォンに持たせる三つの道

[cols="2,3,3"]

道 鍵を出すのは誰か 主な形
ホームアプリ(Apple のホーム、Google Home) 住む人 一つの家のための物。錠を登録した人が、家族や客に鍵を渡す
ウォレット(Apple Wallet、Google Wallet の社員証など) ウォレットの制度に入った会社が、鍵をスマートフォンに入れる スマートフォンのウォレットに、入館の鍵が入る
ウォレットを通さないアプリ 扉の管理者(会社の情報システム部門など) 管理者が出すアプリで開ける。Android は NFC と BLE、iPhone は BLE

ホームアプリでも、ウォレットに鍵が入る事があります。ただ、その鍵を出す元はスマートホームで、鍵を出し、止めるのは住む人です。表の「ウォレット」は、会社が制度に入って、社員などのスマートフォンに鍵を入れる形を指しています。

戸建ては、ホームアプリで足りる

戸建ての家では、鍵を出す人と使う人が、同じ家族の中に収まります。Matter と Aliro に対応した錠をスマートホームに登録すれば、ウォレットに鍵が入ります(Google Wallet に戸建ての家の鍵が入る)。戸建てでは、この道で足ります。

そのうえで、扉の側で決めておく事が三つあります。どれも、このサイトの要求仕様に置いている事です。

予備の管理者の鍵

据付のときに、管理者の鍵とは別に、予備の管理者の鍵を作ります。予備の秘密の部分は封をして、持ち主が持ちます。

管理者の鍵をなくしたときは、室内の側の物理の操作と、予備の鍵の両方を使って、管理者の鍵を入れ直します。予備もなくしたときは、鍵を持つモジュールを替えます。機械の鍵を全部なくしたときに、シリンダーを替えるのと同じです。製造者が合鍵を持つ必要はありません(R-AC-23)。

扉を登録した先

扉を Matter の錠として登録した先(Matter の Fabric)は、管理者のインターフェースの一つとして扱います。

  • コミッショニングウィンドウは、管理者の鍵の操作か、室内の側の物理の操作でだけ開きます
  • 今の登録先の一覧を見られ、足した事と外した事が記録に残ります
  • 持ち主が替わるときは、登録先を全部外します

Matter の SDK の実装(connectedhomeip の v1.4 の枝)では、登録先を外しても、その登録先が入れた鍵は錠に残ります。そこで、登録先を外すときは、その登録先が入れた鍵も一緒に消します(R-AC-24、R-CT-26)。

更新

扉のソフトの更新は、製造者が署名して配ります。入れる時期と方法は、持ち主が決めます。製造者は、配ったバージョンを公開の一覧に載せます。持ち主は、扉に入っているバージョンを一覧と照らせます(R-EL-34、R-RS-19)。

戸建ての扉が、工場から家に届くまで

扉の中の鍵が、どの段で誰の手にあるかを並べます。このサイトの決めでは、扉を開ける鍵は、工場でも出荷でも入れません。

[cols="1,1,3,3"]

段 誰が する事 扉の中の鍵
工場 製造者 組み立てと試験。個体の台帳に、扉とモジュールの番号を書く 更新を確かめる公開鍵と、機器の証明書だけ。扉を開ける鍵は入れない
出荷 製造者 送る 誰の鍵も無い
据付 施工の人 配線、ネットワークの区画分け、時刻の設定。試験に使った鍵を消す。持ち主の管理者の公開鍵を入れ、予備の鍵を封をして渡す 持ち主の管理者の公開鍵。秘密の部分は、施工の人が持ち帰らない
引き渡し 持ち主 自分で、鍵を出す、止める、入れ直す 持ち主が出した鍵
使う間 持ち主 鍵の管理を続ける 鍵は全部、持ち主の側。製造者が持つのは、更新の署名の鍵、個体の台帳、交換の部品(R-RS-20)

使う間に起きる事と、その手当てです。

[cols="2,4,3"]

出来事 手当て 製造者の関わり
端末をなくした 持ち主が、その端末の鍵を止める 無し
管理者の鍵をなくした 室内の側の物理の操作と、予備の鍵で入れ直す 無し
予備もなくした 鍵を持つモジュールを替える 交換の部品を出す。個体の台帳を書き換える
持ち主が替わる 登録先と、その登録先が入れた鍵を全部消し、新しい持ち主が管理者の鍵を入れる 無し
機器が古くなった 更新を入れるか、機器を替える 署名した更新を配る。交換の部品を出す

事務所では、ホームアプリでは足りない

ホームアプリは、一つの家のための物です。会社が社員に鍵を出し、退職の日に止める、という使い方には合いません。

このサイトの決めでは、事務所の鍵を出すのは、その会社の情報システム部門です。アカウントと同じく、本人と権限の管理の一つとして扱います(R-EB-33)。

主な道は、ウォレットを通さないアプリです。まずこのアプリで、全部の扉が開く状態を作ります(R-EB-38、R-CM-17)。ウォレットの社員証は、そのうえで足す物です。

事務所の扉は、ホームアプリからの鍵の登録と解錠を受けない設定にします(R-AC-24)。社員が自分のスマートフォンのスマートホームに会社の扉を登録すると、会社の台帳の外に管理者が増えるからです。

ウォレットの社員証を足す場合

ここでは、会社が正式に書いている事を整理します。

Apple Wallet Access Program

Apple には、ウォレットに入館の鍵を入れるための制度として、Apple Wallet Access Program があります。ガイドは、参加する会社の役割を三つに分けています。

[cols="1,4"]

役割 ガイドの説明
Credential Manager Apple の仕組みと直接つながる、主となる会社。鍵をスマートフォンに入れ、止める
Credential Provider スマートフォンに入れる資格情報を届ける。マスター鍵を握る。リーダーの製造者が担う例が書かれている
Participating Provider 建物を持つか、管理する者。Credential Manager を通じて Apple と契約する

事務所の会社は、三つ目の Participating Provider の立場で入る形です。

ガイドは、Credential Manager に次の事を求めています。

  • 本番の稼働率 99.99%
  • 複数の地域に備え、30分以内に切り替える
  • 全体が止まる障害に、15分以内に応じる
  • 検査用、負荷の試験用、本番の三つの環境

リーダーは、Apple が試験して認証します。使える資格情報の技術は、MIFARE DESFire、Seos、Aliro です。費用と対象の国は、ガイドに書かれていません。

開けるかどうかの判断は、リーダーか制御の機器が行い、Apple の仕組みとスマートフォンは関わらない、とガイドは書いています。

NFC & SE Platform

Apple には別に、開発者が自分のアプリから iPhone の NFC を使える道として、NFC & SE Platform があります。iOS 18.1 からの物です。対象には、社員証、家の鍵、ホテルの鍵などが挙がっていて、対象の国に日本が入っています。使うには、Apple との契約と費用、アプレットを認定の試験所で確かめる事が要ります。

Google Wallet の社員証

Google Wallet には、社員証(Corporate Badge)があります。Google Wallet の更新の記録(2024年6月4日)は、対応する入館の方式と Account Hub(例として NXP)を使う開発者が、社員証を組み込める、と書いています。

ウォレットを通さないアプリ

ここは、Apple、Google、CSA の発表ではなく、会社の説明です。Aliro を扱う会社 Safetrust の資料(2026年6月18日)は、次のように書いています。

  • iOS と Android では BLE で、Android では NFC で、Aliro の資格情報を出せる
  • 客が自分で発行者を持つ形も選べる

認証と権限を分ける

ウォレットの社員証を足すときに、扉の側で考える仕事は二つです。

  • 認証: スマートフォンの中の鍵が本物で、コピーではない事を確かめられるようにする
  • 権限: その鍵を、どの扉に、いつ通すかを決める

Aliro の仕様も、資格を与える者(Access Manager)と、資格の文書に署名する者(Credential Issuer)を、別の役割として定めています(Aliroとは何か)。

ただし Aliro では、発行者が署名した文書が、そのまま通してよい印になります。役割を分けるだけでは、ウォレットに鍵を載せる会社の署名一つで扉が開きます。

そこで、このサイトの決めでは、次のようにします(R-AC-25)。

  • ウォレットに鍵を載せる会社の署名は、鍵が本物である事の確かめにだけ使う
  • 扉は、管理者が登録した鍵だけを通す
  • 登録は、リーダーにかざして行える
  • ウォレットに鍵を載せる会社の仕組みが止まっていても、登録と取り消しができる
  • ウォレットに鍵を載せる会社には、誰がどの扉を通れるかの台帳と、出入りの記録を渡さない

これで良くなる事は二つです。ウォレットに鍵を載せる会社が攻められても、扉は開きません。鍵を出す事と止める事が、会社(情報システム部門)の手に残ります。

誰が何の記録をとるか

[cols="2,4"]

誰が 何の記録
扉 誰の鍵で、いつ開いたか。拒んだか
扉の管理者 誰の鍵を、どの扉に、いつ登録し、取り消したか
ウォレットに鍵を載せる会社 どのスマートフォンに鍵を入れ、いつ止めたか
製造者 どの扉にどのモジュールを組み込み、どこへ出したか。配ったバージョン

出入りの記録は、扉と扉の管理者の側にだけ残ります。ウォレットに鍵を載せる会社が持つのは、鍵を入れた事と止めた事の記録です。

事務所の扉が、使えるようになるまで

[cols="1,4"]

段 する事
工事と試験 配線、ネットワークの区画分け、試験
試験の鍵を消す 試験に使った鍵を消し、扉が「鍵の無い状態」を返す事を確かめる(R-CT-27)
管理者の鍵を入れる 情報システム部門が、自分で管理者の鍵を入れる。予備の鍵は会社が保管する(R-EB-39)
鍵を出す 社員に、アプリの鍵を出す
退職の日 アカウントと、全部の経路の鍵を、同じ日に止める(R-EB-34)

分かっていない事

2026年11月11日の時点で、次の事は会社の公開の資料に見つかりませんでした。

  • Apple Wallet Access Program の費用と、対象の国
  • Aliro を使うときに、誰が資格の文書に署名するか
  • ウォレットを通さないアプリが、Aliro の認証を受けられるか
  • iPhone の BLE で開けるときに、アプリを開く操作が要るか
