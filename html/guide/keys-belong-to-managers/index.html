デジタルキーは管理者が自分で持つ

扉は変わらないが、鍵は毎日変わる。受託では重すぎる仕事を、管理者が道具と手順で引き受ける

2026.10.20

扉と錠は、一度作って付ければ、何十年も変わりません。鍵は毎日変わります。客が泊まり、入居者が出ていき、掃除の人が来て、誰かがスマートフォンをなくし、建物の持ち主が替わります。扉が付いている間に、鍵は何千回も発行され、失効されます。

デジタルドアの一番の課題は、この生きている部分、つまりデジタルキーをどう管理するかです。

鍵は毎日変わる

出来事 すること 誰が確かめる
泊まる、入居する 本人を確かめ、期間と範囲を決めて発行する 管理者
掃除や点検の人が来る その日の時間帯だけの鍵を出す。終われば効かなくなる 管理者
端末をなくした その人の鍵を全部の経路で止め、新しい端末に出し直す 管理者と本人
退去した、辞めた 全部の経路の鍵を失効し、貸した機械の鍵を回収する 管理者
管理者が替わる、持ち主が替わる 発行者の鍵と、扉が信頼する発行者の一覧を作り直す 前と新しい管理者

受託では重すぎる

鍵の管理を、外の会社に任せる形があります。月ごとの料金で、発行と失効と問い合わせを引き受ける形です。しかし、この仕事は受託には向きません。

  • 出来事が毎日、その場で起きる。 本人か、その場の事情はどうかを一番よく知っているのは、現場の管理者です。受託先は毎回、離れた所から本人を確かめることになり、遅く、誤りやすくなります。
  • 受付の窓口が、攻撃の入口になる。 「スマートフォンをなくしたので出し直してほしい」と電話で頼むのは、攻撃者の常套手段です。米国の CISA と FBI は 2023年11月の注意喚起(AA23-320A)で、大企業と、その IT のヘルプデスクを請け負う会社を狙い、担当者に成りすましてパスワードと多要素認証を作り直させる攻撃者の集団を挙げています。窓口を外に置くほど、本人の確かめは弱くなります。
  • 集めると、一度に全部を失う。 一つの受託先が多くの建物の鍵を持てば、そこが破られたときに全部が開きます(業者に預けた鍵と権限)。防御は集中化できません。
  • 責任の重さが合わない。 扉が誤って開いたときに責任を問われるのは、建物の持ち主と管理者です。受託先は、契約で責任の上限を決めています。

鍵の管理は、それぞれの管理者が責任を持って、自分で行う仕事です。業者がするのは、道具(ソフトウェアと機器)を渡すこと、管理者を育てること、困ったときに手を貸すことで、鍵は持ちません。管理者が自分でやれるのは、AI が手順と確かめる項目を手伝えるようになったからでもあります(AI の時代に、委託をやめて自社で育てる)。

誰が持つか

建物 発行者 業者がすること
民泊、貸家 経営者 道具を渡す。鍵は持たない
分譲マンション 住戸の錠は区分所有者(賃貸では貸主)。共用部は管理組合(R-AP-38) 管理会社と業者の鍵では住戸を開けられない(R-AP-39)
企業、事業所 情報システム部門(R-EB-33)。設備の担当は扉と錠の物理を持つ 出入りの業者には、その日の鍵を情報システム部門が出す(R-AC-06、10)

発行者の鍵が届くのは、その発行者が管理する扉だけです(R-AC-09)。秘密鍵は取り出せない所に置きます(R-AC-11)。

企業では、情報システム部門が持つ

会社の扉の鍵は、アカウントや多要素認証と同じ、「誰が、どこに、いつまで入れるか」の権限です。総務や設備の担当が別の台帳で持つと、退職したのにアカウントは止まり、扉の鍵は生きている、という漏れが起きます。端末をなくしたときも、アカウントと端末の管理と、扉の鍵の窓口が分かれていると、本人の確かめが二重に弱くなります。

そこで、事業所の鍵の発行者は情報システム部門とし、発行者の鍵と台帳の責任者を置きます(R-EB-33)。扉と錠の据付、点検、交換は、これまでどおり設備の担当が持ちます。

  • 入社、異動、退職は、人事の届けを正として扉の台帳に入れ、アカウントと扉の鍵を同じ日に変えます。退職の日には、両方が止まったことを照らし合わせます。片方からもう片方を自動では動かしません(R-EB-34)。
  • 従業員の鍵にも、網の届かない扉では失効が効くまでの最長の時間を設け、網が届くときに自動で延ばします(R-EB-35)。
  • 端末の紛失は、情報システム部門の窓口で受け、本人を確かめてから、全経路の鍵を止めて出し直します。この窓口を外の会社に任せません(R-EB-36)。

民泊や小さな貸家では、情報システム部門にあたるのは経営者本人です。分譲マンションでは、住戸は所有者、共用部は管理組合がその役を持ちます。

Microsoft の ID は扉に使えない

会社のアカウントの多くは、Microsoft の Entra ID にあります。それを扉の台帳に使えないかと考えたくなりますが、使えません。Microsoft の ID は二つに割れていて、どちらも扉には合いません。

ID その人の物か 管理の仕組み
Entra ID(職場のアカウント) 違う。会社の管理者が作る会社の持ち物で、本人は作れず、辞めれば消える ある
Microsoft アカウント(個人) その人の物 無い。権限を分けられず、記録を管理者が見られず、皆で一つのパスワードを使うことになりやすい

鍵を運ぶのは、本人のスマートフォンです。そこに入っている本人の ID は Apple か Google の物で、財布の鍵(Aliro)もそこに入ります。Aliro 1.0 の発表(2026年2月26日)で財布を合わせると約束したのは Apple、Google、Samsung で、仕様を出した会社にも、最初に認証を受ける見込みの会社にも、Microsoft の名前はありません。Entra ID を本人のスマートフォンに持ち込むには、私物の電話を会社の端末管理に登録させることになります。

Entra ID の台帳としての弱さも、はっきりしています。決め手は、鍵の要る人が載っていないことです。清掃、警備、派遣、アルバイト、出入りの業者、来客は、ライセンスの費用がかかるので、Entra ID には作られないのが普通です。全員を載せられない台帳は、扉の台帳の正になれません。逆に、サービス用のアカウント、共有のメールボックス、外部のゲスト、メールを残すために生かしてある退職者のアカウントは載っています。Entra ID はアカウントの台帳で、建物に入る人の台帳ではありません。

自動でつなぐと、もっと悪くなります。Entra ID から自動で扉の鍵を出す形にすると、テナントを乗っ取った攻撃者は、偽の社員を一人作るだけで建物の扉を開けられます。クラウドの侵入が、そのまま建物への侵入になります。人の一覧を読むためのアプリの資格情報も、広い権限を持つつなぎとして狙われます。

扉の台帳は、鍵の要る全員を載せる、それ自身が正の台帳にします。入社と退職は人事の届けから入れ、Entra ID のアカウントとは、止まったかどうかを照らし合わせるだけにします(R-EB-37)。

失効は、有効期限の長さで決まる

網につながっている扉は、失効の知らせを受け取れば、すぐに鍵を拒みます。網が切れている扉では、失効は有効期限でしか効きません(R-AC-03)。つまり、網の届かない扉を守っているのは、有効期限の長さです。

そこで、扉ごと、鍵の役ごとに、「網が届かないときに失効が効くまでの最長の時間」を決め、管理ソフトに表示します(R-AC-14)。客の鍵は滞在の期間だけ、掃除の人の鍵はその日の時間帯だけ、住人の鍵は短く出して網が届くときに更新する、というように決めます。失効の知らせが長く届いていない扉は、長い期限の鍵を拒む設定も選べます。

長くすれば便利になり、短くすれば失効が早く効きます。この兼ね合いを決めるのは、扉の事情を知っている管理者です。

一人の鍵を、全部の経路で一度に止める

同じ人が、スマートフォンの鍵、カード、暗証番号、後付け錠のアプリ、機械の鍵を持つことがあります。一つでも止め忘れると、失効したつもりで開きます。台帳は、一人に結びついた全経路の鍵を一覧にし、一度の操作で全部を失効できるようにします。機械の鍵は、回収したことを記録します(R-AC-15)。

出来事ごとの手順を持つ

端末の紛失、退去と退職、管理者の交代、建物の持ち主の交代、発行者の鍵の漏れ。それぞれについて、何を失効し、何を作り直し、誰が確かめるかを、手順として持ちます(R-AC-16)。

持ち主が替わるときは、前の持ち主の発行者の鍵が残っていると、前の持ち主が鍵を出せてしまいます。発行者の鍵と、扉が信頼する発行者の一覧を作り直します。

一番上の鍵をなくしたとき

扉が信頼する発行者を変えられるのは、管理者の鍵だけです(R-AC-12)。管理者の鍵をなくしたら、扉の前で、物理の操作(登録モード)と本人の確かめによって、一覧を作り直します。この操作は遠隔ではできず、記録に残ります(R-AC-17)。

一番上の鍵の戻し方を、扉の前に立つことに結びつけておけば、遠くの攻撃者は同じことができません。現場にいる人が最後の拠り所になります(人に残るのは現場)。

スマートフォンの財布の鍵

スマートフォンをかざすだけで開くには、アプリを開かなくても OS がその場で鍵を差し出せる必要があります。つまり、財布に組み込まれたデジタルキー(Aliro)が要ります。自分のアプリを開いてから使う形なら今でも組めますが、毎回アプリを開くのは不便です。

かざすだけの鍵には、財布の会社への載せ方が要ります。一軒一軒の持ち主がそれを結ぶのは無理なので、載せ方を業者や管理会社に任せる形になりがちです。そのとき業者が発行者の鍵まで持てば、表面化している委託の問題(業者の資格情報が奪われる、窓口への成りすまし、一つの業者に鍵が集まる)に戻ります。

Aliro は、決める者と運ぶ者を分けられる

Aliro 1.0 の仕様(2026年2月18日版)を読むと、次のことが分かります。

  • 扉の側で開けるかを決める者(Access Manager)、鍵に署名する者(Credential Issuer)、読取機の証明書を出す者(Reader System Issuer)は、別の役として定められています。同じ者か別の者かは、仕様の外です(6.1)。
  • 鍵の中身(Access Document)は発行者の秘密鍵で署名し、読取機はその発行者の公開鍵か、その CA の証明書を知っている必要があります(6.5)。
  • 財布の中の鍵は端末ごとに一つの鍵の対を持ち、署名された中身にその公開鍵が入ります。写しを送り直しても開きません(6.4)。
  • 端末と読取機への載せ方と、その後の管理は、仕様の外です(6.2)。
  • 網につながらない読取機には、端末が発行者の署名つきの失効の一覧(Revocation Document)を運べます(6.6、7.6)。

つまり、発行者の鍵を管理者が持ち、財布への載せ方だけを業者に任せる形は、Aliro の仕組みの上で取れます。ただし、載せ方は仕様の外なので、仕様だけでは保証されません。

分け方を要求にする

役 誰が 持つ物
決める 管理者 発行者の鍵と台帳。誰に、どの扉を、いつまで
運ぶ 財布への載せ方を担う業者、財布の会社 管理者が署名した資格情報を、財布まで届ける仕組みだけ
判定する 扉 管理者の署名を確かめる。業者の鍵は信じない
  • 財布への載せ方を担う業者は、発行者の秘密鍵を持ちません。資格情報は管理者が自分の機械か鍵を取り出せない所で署名し、業者は運ぶだけです。扉が信じる発行者の鍵は、管理者の鍵の操作でだけ入れ替えます(R-AC-20)。業者が破られても、管理者の署名の無い資格情報は扉が拒みます。
  • 資格情報は持ち主の端末の鍵に結び、扉は毎回違う問いかけへの署名を確かめます(R-AC-21)。
  • 網の届かない扉は、利用者の端末が運んできた失効の一覧を受けて使えるようにします(R-AC-22)。失効が有効期限でしか効かない問題(R-AC-14)を縮められます。
  • 財布の鍵も発行者の一つとして台帳から発行と失効を行い、財布の会社の仕組みが止まっても、カード、暗証番号、機械の鍵で開けられるようにしておきます(R-AC-18)。

財布の会社の載せ方の仕組み(Aliro の載せ方の手引きは会員の場で公開待ち)が、この分け方を許すかどうかは、これから確かめます。許さないなら、それは CSA と財布の会社への要望になります。

管理者が自分でやれる道具

道具は、管理者が自分の機械で動かせる形で渡します。発行者の鍵と台帳を、道具を作った業者のクラウドに置く必要はありません(R-AC-19)。網が止まっても、建物の中で発行と失効ができます。

このリポジトリの受け入れの参照実装(digitalkey/entrance)は、民泊や貸家の管理者が、自分の機械で、本人の確かめ、鍵の発行と失効、台帳を扱うための物です。

デジタルドアを売るとは

ここまでをまとめると、デジタルドアを売るとは、扉という物を渡すことではなく、買った側が鍵を管理し続けられる状態を渡すことです。売る側が鍵を管理すれば委託に戻るので、売る側の仕事は、買った側の管理者を育てることになります。

人に教えられるのは、自分でやったことだけです。売る物と同じ扉と鍵の管理を自社の建物で運用していない売り手は、売り先の管理者を育てられません。だから、自社でできないうちは売りません(R-RS-16〜18)。引き渡しの受入れ試験には、売り先の管理者が自分で鍵を発行し、止め、紛失に手当てし、管理者の鍵をなくしたときに戻せることを含めます。

急ぐ理由もありません。サイバー攻撃への対策として、各社が自分で鍵とルートを持つ体制を作れば、それがそのままデジタルドアを入れる下地になります(デジタルドアはサイバー攻撃対策そのもの)。
