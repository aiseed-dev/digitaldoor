= Matterとは何か。どこまで届いて、どこから届かないか

Matterは、家の中の機器を同じ言葉で話させるための規格である。錠も照明もセンサーもスピーカーも、どの会社の物でも、同じ言葉で状態を伝え、命令を受ける。この記事では、何ができるかを先に書き、その後で、扉の側から見てどこから届かないかを書く。

== 何であるか

Connectivity Standards Alliance(CSA、旧Zigbee Alliance)が定める規格で、1.0は2022年10月に出た。Apple、Google、Amazon、Samsungが揃って推した点が、それまでの家の規格と違う。

* 通信はIPの上で動く。Wi-Fi、Ethernet、そして低消費電力の網であるThreadを使う。Bluetooth LEは、機器を最初に網へ入れるときにだけ使う。
* 仕様は公開されていて、参照実装(SDK)も公開されている。
* 製品として名乗るには、CSAの認証を受ける。機器は製造者の証明書(DAC)を持ち、管理者はそれを検めてから網に入れる。

版は年に一回か二回上がる。1.2(2023年)で冷蔵庫や洗濯機などの家電、1.3(2024年)でエネルギー管理、1.4(2024年末)で家庭用ルーターと、錠へのlink:/guide/aliro/[Aliro]の資格情報の対応、1.5(2025年11月)でカメラが入った。版の中身はCSAの発表による。

== 仕組み

機器は、管理者の網(ファブリック)に登録されて動く。登録は、機器のQRコードか手動コードを管理者のアプリに読ませて行う。管理者になるのは、Apple Home、Google Home、Alexa、SmartThings、そしてHome Assistantのような自分で立てる管理者である。

一台の機器を複数の管理者の網に登録できる。Apple HomeとGoogle Homeの両方から同じ錠を扱える、ということである。

== 錠には何があるか

Matterの錠(Door Lockクラスタ)が持つ物は、住宅の玄関に要るものとしては十分に揃っている。

* 施錠、解錠、そしてラッチだけを外す動作
* 利用者と資格情報。暗証番号、カード、指紋、顔、そしてAliroの鍵
* 曜日、日付、休日ごとのスケジュール
* 扉の位置。開いている、閉じている、半開き、こじ開け、詰まり
* 操作の通知
* 通常、不在、プライバシー、遠隔禁止、通行の各モード
* 自動再施錠と、警報

== 扉の側から見て、どこから届かないか

ここからは評価である。住宅の玄関にはMatterで足りる。業務用の扉には足りない。理由は三つに分けられる。

*入り口。* 機器は管理者の網に入らないと動かない。業務システムから扉を扱おうとすると、管理者の会社のアカウントと同意の画面を通って、初めて機器に届く。Appleにはサーバーから呼ぶ入り口が無い。Googleは自社の家庭用の枠の中でだけ他社のアプリに開けている。自分で管理者を立てる道はあるが、それでも得られるのは「施錠、解錠、状態」という機器の言葉で、誰が承認し、何が記録され、どの権限で呼んだかは含まれない。

*主導権。* 網の鍵を持つのは管理者で、管理者はApple、Google、Amazonのアプリである。通信の言葉は公開されていても、その言葉で話すには三社の網に入る必要がある。ソフトウェアの席を三社に集める形で、扉の側から見れば独占の道具になる。

*情報の置き場。* Matterの通信そのものは構内で閉じる。しかし管理者は、遠隔操作と音声のために、機器の状態と操作を自社のサーバーへ同期する。扉なら、誰がいつどこを通ったかが外に載る。企業では、社員の出退勤と来客が一社のサーバーに集まることになり、文書と働き方が一社のクラウドに集まるMicrosoft 365と同じ形になる。

そして、業務用の扉に要るもののうち、次の物はMatterの範囲の外にある。火災と停電と避難のときの挙動、改ざんの分かる監査の記録、二人同時と強要、読取機と制御盤の間の秘匿、建物との連動、保守者の権限。

== どう扱うか

Matter対応のセンサーやスピーカーは、買って足す周辺機として受ける。扉の判断と記録と鍵の発行は、Matterの外に置く。扉の側に、認証と監査と権限を含んだ自分の口を持ち、Matterはその口の一つの入力にする。

= Aliroとは何か。スマートフォンが本人の証明になる仕組み

Aliroは、スマートフォンや時計を鍵として、扉の読取機に本人であることを示す仕組みを決めた規格である。決めているのは読取機の手前までで、読取機から後ろは決めていない。この記事では、何を決めたか、何を決めていないか、そして扉の側から見た値打ちと壁を書く。

== 何であるか

link:/guide/matter/[Matter]と同じConnectivity Standards Alliance(CSA)の規格で、1.0は2026年2月26日に公開された。Apple、Google、Samsungのスマートフォンの側と、ASSA ABLOY、Allegion、HIDのような錠と読取機の側が同じ席にいる。参加は220社を超える。

それまで、スマートフォンを鍵にする仕組みは会社ごとに閉じていた。AppleのHome KeyはiOS 15(2021年)でNFCの鍵を財布に入れ、iOS 18(2024年)でUWBの近接解錠を足したが、Apple対応と名乗る錠にしか使えなかった。Aliroは、この部分を一つの言葉にする。

== 何を決めたか

* スマートフォンと読取機の間の相互認証。楕円曲線P-256の鍵、AES-256-GCMの暗号、圧縮したX.509の証明書。
* 入館の資格を示す文書の形(mdoc)。
* 経路は三つ。NFC、Bluetooth LE、UWB。かざす、近づく、手を触れずに通る、の三つの使い方に対応する。
* 検証は読取機の中で終わる。網につながっていなくても、スマートフォンと読取機の二者で開く。
* 網が無い状態での失効。

== 何を決めていないか

Aliroは範囲を自分で狭く決めている。

* 読取機から後ろ。制御盤、業務のシステム、読取機と制御盤の間の言葉(OSDPなど)は問わない。
* パソコンへのログインのような、物理でない入場。
* 鍵の共有と、監査の記録は、将来の版へ。

扉に何かを命じない規格である。誰が来たかを確かに示すだけで、その後をどう扱うかは扉と発行者(誰に鍵を出し、いつ失効させるかを決めて記録する側)に残す。だから扉の側は自由なままでいられる。

== 扉の側から見た値打ち

物理鍵を無くすには、代わりが一本では足りない。Aliroは、代わりを何本にも増やす道具になる。

* 経路が三つある。一つが不調でも別の経路で通る。
* 端末が複数持てる。スマートフォンと時計に同じ鍵が入る。
* 電池切れに耐える。iPhoneは電源が落ちた後も数時間、財布の鍵をNFCで使える。
* 発行者が複数でも同じ読取機が受けられる。経営者の鍵、管理の鍵、点検の人の鍵を、別々の発行者が出せる。

どの経路も網に頼らない。網に頼る経路は何本足しても、サーバーが止まれば全部同時に止まるので、多重化にならない。Aliroが多重化に使えるのは、検証を読取機の中で終えると規格の側で決めているからである。

== 壁

財布に鍵を入れるには、AppleとGoogleの財布との契約が要る。読取機の側は自由でも、発行の側はそこを通る。これは鍵の発行者の層にある参入の壁で、Aliroの値打ちを減らすものではないが、知っておく必要がある。

読取機を作る側には、参照設計がある。Espressif、Nordic、STMicroelectronicsが、Aliroの読取機の開発キットとソフトを出している。読取機は買う物になりつつあり、扉の側が作る物ではない。

== どう扱うか

Aliroの読取機からの「認証が通った、誰である」という結果を、扉の側の口の入力の一つとして受ける。カメラの顔、マイクの声、扉の位置のセンサーも同じ形の入力にして、組み合わせの判断は扉の側が持つ。読取機はいつでも別の物に替わる、という作りにしておく。

= スマートドアに望まれるもの

スマートドアと呼ぶのは、電子錠と読取機とコントローラを持ち、鍵をソフトで出し入れできる扉のことである。売り物は多いが、望まれるものは少ない。ここでは六つに分けて書き、最後に、読取機の本命と見るAppleのドアホンをその条件に照らす。

== ローカルだけで動くこと

網が無くても、開いて、閉まって、記録する。これが無い錠は信じられないので、経営者は外のシリンダーを残し、物理鍵を財布に入れたままにする。電子錠は追加の一台になり、費用も鍵の管理も増える。いまの後付けのスマートロックがサムターンに被せる形なのは、この理由である。

ローカルで完全な錠は、物理鍵の代わりになる。外のシリンダーを無くせば、ピッキングの口が消え、鍵の複製もなくなり、開口の規格が一つになる。これは扉を作る側にしかできない変更である。残るのは、避難のための内側からの機械的な解放と、非常給電の口だけでよい。

== 錠を選べること

扉と錠を替えずに、読取機や鍵の発行者を替えられること。錠とアプリを一組で囲った製品は、公開の規格ができた瞬間に真ん中から割れる。扉の側が仕様を出し、錠の側が入居する形が望ましい。錠の言葉としてのlink:/guide/matter/[Matter]は住宅では足りるが、業務用の扉に足りない理由は別の記事に書いた。

== 読取機はいつでも替えられること

誰が来たかを読む機器は、顔はカメラ、鍵はスマートフォンの財布、声はマイクで読む。玄関でそれをやるのはドアホンで、Apple、Google、Amazonが競う場所である。競争の果実は買う側に落ちる。扉の側は読取機を作らず、「誰が来たか」の出来事を受ける口を持って待つ。

== 記録が手元にあること

扉の記録は、誰が何時に来て帰ったか、来客が誰か、休日に誰が出たか、という人事と営業の情報である。それが個人向けのアカウントで外部のサーバーに載る形は、企業では通らない。記録は自分の箱に置き、外へ出す先と内容は事業者が決める。

== 認証が一社に集まらないこと

一社のサーバーが認証を握る形は、障害、撤退、侵害、値上げ、差押えの一点に全戸が集まる。扉が自分で判定し、発行者は署名した伝票を渡すだけで、開くたびに呼ばれない。監査は扉と台帳の二か所に別々に残す。

== 経路が何本もあること

物理鍵を無くすには、代わりが一本では足りない。スマートフォンの鍵、時計の鍵、顔、暗証番号、非常手段。どの経路も網に頼らないことが条件で、網に頼る経路を何本足しても、サーバーが止まれば同時に止まる。link:/guide/aliro/[Aliro]が多重化に使えるのは、検証を読取機の中で終えると規格の側で決めているからである。

== 読取機の本命: Appleの顔認証ドアホン

Appleが、顔を見て玄関の錠を開けるドアホンを準備している。そういう話が2024年の暮れから続いている。上に挙げた条件に照らして、何が事実で何が噂かを分け、それでも本命と見る理由を書く。

=== 何が報じられているか

発端はBloombergのMark Gurmanが2024年12月22日に書いた記事である。報道の中身は次のとおり。

* 玄関に立った人の顔を読み、住人なら錠を自動で開けるドアホン。iPhoneのFace IDで本人を通すのと同じ発想。
* 錠はApple製ではなく、HomeKitに対応した既存の他社製デッドボルトと無線でつなぐ。一社と組んで公式の組み合わせを出す可能性もある。
* Appleが自分で設計した無線チップProximaを使う可能性がある。顔の処理は機器の中で行う。
* 「開発の初期段階」で、出るとしても2026年が最短。
* Appleが自分で製造せず、LogitechやBelkinのような他社を通して技術を売る可能性もある。

2026年2月の9to5Macの記事も、この報道を「今年出るかもしれない」と繰り返しただけで、新しい事実は加わっていない。

=== 2026年9月の時点

9月9日の発表会で出たのは、iPhone 18 ProとiPhone Duo、Apple Watch、AirPodsだった。ドアホンも、家の製品も出ていない。

家の製品では、7インチ画面のホームハブと室内カメラが「2026年後半か2027年初め」と報じられている。ホームハブが顔で人を見分けることは、8月にmacOS 26.7の候補版のコードから確認された。ドアホンは、報道の中でもハブとカメラの後に置かれていて、3月の製品一覧の記事には名前が出てこない。

つまり、「準備している」は一社の報道として事実で、「発売する」はまだ事実ではない。Apple自身は一度も口にしていない。

=== それでも本命と見る理由

スマートドアで読取機と呼ぶのは、誰が来たかを読む機器のことである。顔はカメラで、鍵はスマートフォンの財布からNFCかUWBで、声はマイクで読む。玄関でそれをやる機器はドアホンである。報道されている姿は、この読取機の本命になる条件を三つ揃えている。

*顔の処理を機器の中で終える。* クラウドに顔を送らない読取機は、網が切れても動く扉と同じ側に立つ。企業で使うなら、社員の出退勤が外部のサーバーに載らないことが条件になる。三社の中でこの姿勢を製品の売りにするのはAppleだけである。

*錠は他社の既存品を開ける。* 自社の錠とアプリを一組で囲わず、HomeKit対応の錠なら何でもつなぐ。扉を作る側から見れば、錠を選べる扉の前提と同じである。読取機が変わっても、扉と錠を替えなくてよい。

*スマートフォンと財布の鍵を持つ会社が、顔も読む。* 鍵と顔と声を一台で読む読取機の姿を、いちばん揃えて持っているのがAppleである。iPhoneは電源が落ちた後も数時間、財布の鍵をNFCで使える。物理鍵を無くすための多重化が、同じ会社の中で閉じる。

=== まだ分からないこと

* 財布の鍵(NFC、UWB)をドアホン側で読むかどうかは、報道にない。UWBの近接解錠は、いまも錠の側の読取で成り立っている。
* 日本での発売時期。
* 集合住宅の住戸玄関に付くかどうか。これは機器ではなく建物の側の話になる。

=== 扉の側で準備しておくこと

読取機は作らない。ドアホンから来る「誰が来たか」という出来事を受ける口を、扉の側に用意して待つ。Aliroの読取機からの認証結果と同じ形の入力として扱えば、Appleのドアホンが出た日にそのまま入居できる。

火災や停電のときの挙動、記録、二人でしか開けない部屋の判断は、読取機ではなく扉の側が持つ。読取機はいつでも別の物に替わる、という作りにしておくことが、本命を待つ側の準備である。

=== 判断の目安

10月か11月に二回目の発表会があるという観測がある。ホームハブとカメラがそこで出れば、ドアホンは次の段階に進む。出なければ2027年である。
