= 今日、デジタルドアを始めました

今日、2026 年 11 月 11 日に、扉と鍵の技術を解説するサイト「デジタルドア」を始めました。電子錠、ドアホン、扉のコントローラ、鍵の発行、業務システムとの連携を扱います。このブログも、今日から書いていきます。

扉に関する情報は、錠のメーカー、ドアホンのメーカー、規格の団体がそれぞれの立場で出していて、扉を使う側から全体を見渡した解説はあまりありません。このサイトでは、玄関まわりの技術を層に分けて整理し、層ごとの役割と、誰が責任を持つかを書いていきます。

もう一つの目的は、会社が自社のシステムと鍵を、自社の人が AI と一緒に確かめて守れるようにすることです。扉の鍵は、建物や住戸の持ち主が自分で出し、止め、記録する物で、業者に預ける物ではないと考えています(link:/guide/keys-belong-to-managers/[解説 17])。

== 頁の案内

* link:/guide/[解説]。規格(link:/guide/matter/[Matter]、link:/guide/aliro/[Aliro])、層の分け方、日本の現状、サイバー攻撃に耐える扉、鍵の管理などを、20 本書いています。
* link:/3d/[立体図]。玄関ドアを、図面から立体にして、扉が鍵を確かめて開ける様子を見られる頁です(link:/blog/drawing-to-3d/[次の記事])。
* link:/check/[始め方]。自社のシステムと納められたコードを、AI で確かめるときの始め方です。
* link:/manual/[マニュアル]。参照実装のソフトウェア(事業所サーバー、スマートフォンのアプリ、扉のコントローラ、命令)の使い方で、コードから作っています。
* link:/news/[ニュース]。扉と鍵に関するニュースです。AI がガイドに沿って元の記事を開いて確かめて書き、人が読んで直した物を、出典と確かめた日を付けて載せます。
* link:/consult/[相談と教室]。システムを確かめる相談と、AI 教室の案内です。

仕様と参照実装のコードは、GitHub(https://github.com/aiseed-dev/digitaldoor)で公開しています。仕様の文書は CC BY 4.0、扉のコントローラの参照実装は Apache-2.0 です。

= 扉の図面を立体にして見せる頁を作りました

玄関ドアを立体で見られる頁(link:/3d/[立体図])を作りました。開くと、廊下の側から見た扉の図面(姿図、縮尺 1:20)が出て、その線が厚みを持ち、立体の扉になります。

== 図面から立体へ

右の欄の「図面から立体へ」のつまみを動かすと、図面と立体の間を行き来できます。つまみを図面の側に戻すと、寸法の入った図面に戻ります。立体になった後は、ドラッグで回し、ホイールで寄ることができます。寸法は例です。

== 扉が確かめて開ける様子

「鍵をかざす」の欄から、四つの場面を選べます。

* 住人が帰る。スマートフォンをかざすと、扉が鍵の署名と期限を確かめて開けます。
* ネットワークが切れている時。ルーターが止まっていても、扉だけで確かめて開けます。
* 止めた鍵。退去した人や、なくした端末の鍵は、扉が拒みます。
* 火災の信号。報知器の信号で、避難のために錠を解放します。

場面ごとに、画面の下の「扉の記録」に一件ずつ記録が足されます。記録は一件ごとに前の記録とつながり、扉が署名します(ここに出るのは、画面の中の例です)。

「中を透かす」を押すと、扉の中のドアホン、電子錠、扉のコントローラが見え、「五つの層」の欄で層を選ぶと、その部品が光ります。色と意匠(フラット、横目地、縦スリット)も切り替えられます。

== 作り方

この頁は、図面も写真も使わず、文章の指示から AI(Claude)が書きました。立体の表示には three.js を使い、サイトの外のサービスには何もつなぎません。

製品の図面と写真があれば、その寸法と色で、一品ずつこの頁と同じ物を作れます。扉の会社がカタログの一品ごとに見せる使い方を考えています。

WebGL が使えないブラウザでは、立体を描けないという通知だけが出ます。画面の動きを減らす設定にしているときは、開いた時に図面から立体へ自動で移らないので、つまみで移してください。

= 扉がスマートフォンで開く。難しいのは、守りだけです

解説 25「link:/guide/door-maker-and-wallet-keys/[扉を作る会社が、ウォレットの鍵を出す会社になるには]」を書きました。扉がスマートフォンのウォレットの鍵で開くために作る技術は、Apple、Google、CSA が作った物を使うだけで、難しくありません。課題は、会社としてセキュリティ対策ができるかどうかです。解説では、その理由と、会社の形と、始める順を書いています。

ここでは、運営者の見方を書きます。

== 話は素直です

扉は、開ける人が持っている物で開けるしかありません。今、誰もが持っているのはスマートフォンです。扉の鍵はスマートフォンの最も守られた部分に入り、そこに入れるには Apple と Google の審査を通るしかありません。話は素直で、扉がスマートフォンで開く、の一つに行き着くと見ています。

== 鍵を発行できる会社は、数社に絞られる

携帯電話の会社が 3 社と少しになったのと同じように、ウォレットの鍵を発行できる会社も、数社に絞られると見ています。入るのに要るのは、資金と、扉を作れることです。違うのは、選ぶのが国ではなく、Apple と Google だという事です。だから、国内の付き合いでは通れず、会社の場所や大きさも物差しに入らないと見ています。

その数社の上で、建物の管理者や導入する会社が、自由にアプリを作れる形が良いと考えています。回線を持つ会社と、回線を借りて売る会社の関係と同じです。

== 扉を作れる会社は、一番難しい所を持っている

扉を作れる会社は、一番難しい所を既に持っていると見ています。海外では、錠の大手が扉を作る会社を買っています。Allegion は、米国証券取引委員会に出した四半期の報告(2026年9月30日までの期間)で、2026年3月2日に中空の金属の扉と枠を作る Door Components, Inc.(DCI)を、2026年10月2日に防音、防弾、金庫などの扉を作る Overly Door Company を買ったと書いています。

変える物は少なくて済みます。新しく作る部門は、本社の鍵の部門と、営業所の鍵の管理の二つです。扉を作るのも、売るのも、今のままです。

詳しくは、link:/guide/door-maker-and-wallet-keys/[解説 25] を読んでください。
