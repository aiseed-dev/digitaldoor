# 監視を作る — 何を監視し、何を異常と見て、誰に知らせるか

このガイドは、会社の人が、自社のコンピューターとシステムの監視(検知)を、自分の Claude と一緒に作るための物です。相談に来なくても、このガイドと Claude があれば、小さな会社でも回る監視を作れるように書いています。

監視は四つの部品でできています。

1. **一覧。** 何を監視するか(入口、管理者の操作、鍵の使用、外向きの通信、実行される物、控え)。
2. **記録。** どのコンピューターのどの記録を、コンピューターの外の一か所に集めるか。
3. **決まり。** 普段の形を先に書き、そこから外れた物を異常と見る。決まりごとに、何を見るか、どの記録か、調べる命令、鳴った時に最初にする事。
4. **通知。** 誰が受け、何分以内に何をするか。鳴りすぎを週ごとに直す。

この仕事は、Anthropic の Cyber Verification Program の Defense Access が許す仕事の一つ(detection engineering)です。Defense Access の始め方は `docs/確かめの始め方.md`(サイトでは https://door.aiseed.dev/check/ )にあります。

## 始める前に聞くこと

監視を作り始める前に、次の五つを人に聞き、答えを作業の記録の最初に書きます。一つでも答えが無ければ、そこで止めて聞き直します。

1. **何を監視するか。** コンピューターとアカウントとクラウドの名前の範囲。
2. **持ち主は誰か。** 全部が自社の持ち物か。借りている物、業者が持つ物があれば、その契約で記録を読んでよいか。
3. **誰の許しで監視するか。** 許した人の役と日付。
4. **社員に何を知らせたか。** 社員の操作を記録に残すなら、何を見るかを本人たちに知らせた事。就業規則と個人情報の扱いは会社が決めます。
5. **AI に渡してよい物と渡さない物。** 顧客の名簿、取引の中身、給与、健康の情報、メールの本文など。

## 守ること

1. **監視する相手は、自社が持ち主のコンピューターとアカウントだけです。** 他社のコンピューター、取引先のネットワーク、公開のネットワークの他人のコンピューターには、決まりも試しも向けません。
2. **社員の監視は、目的を守りに限ります。** 何を見るか(ログインの時刻と場所、管理者の操作、実行された物など)を本人たちに知らせます。働きぶりの評価や、私的なやり取りを読む事には使いません。就業規則と個人情報の扱いは会社が決めます。
3. **記録をそのまま AI に渡しません。** Cyber Verification Program では、制度に入った者のデータの保持が必須です(出典は `sources.md`)。渡す前に、要る行だけを取り出し、名前とアドレスを伏せます(`scripts/mask.py`。02 章)。伏せた物も、渡す前に人が目で読みます。
4. **Defense Access は、基本は社内の使い道です。** 自社のコード、製品、コンピューターのための仕事が対象です。お客の監視を請け負う時は、別の承認が要ります(`sources.md`)。
5. **鍵、パスワード、トークンの値を会話に出しません。** 記録に値が出ていたら、その事を一件の問題として書き、値は伏せます。会話に貼られた値は、使わず、取り消して作り直す手を出します(`skills/kagi/06-鍵.md`)。
6. **コンピューターを変える手は、AI が文で出し、人が読んでから打ちます。** 記録の転送の設定、防火壁の記録の行、監査の決まり、アカウントの停止は、どれも人が打ちます。AI が動くアカウントに sudo や管理者の権限を渡しません。
7. **命令と設定の例は、確かめた物と確かめていない物を分けて書きます。** 各章の例には「確かめた」「確かめていません」を付けています。確かめていない例は、試験用のコンピューターで打って確かめてから本番に入れます。
8. **値は例です。決めるのは会社です。** 保存の期間、何回の失敗で鳴らすか、何分で知らせるか、どの国からの入りを異常とするかは、このガイドでは例として出すだけです。決めた人と日付を一覧に書きます。
9. **攻撃の手順を本番で試しません。** 鳴るかの試しは、試験用の環境で、害の無いやり方(自分のアカウントで失敗を続ける、表に無いポートを一つ開ける)でします。侵入の試験は Red Team Access の枠で、このガイドの外です(05 章)。

## AI(あなた)の動き方

- 最初の会話で、上の五つを聞きます。答えが揃うまで、決まりも設定も書きません。
- 一覧(01)と普段の形(03)を、人の言葉で聞き取って表にします。記録の中身から推し量って埋めません。分からない欄は「分からない」と書きます。
- 記録を読む時は、人に `scripts/mask.py` で伏せてもらった物か、件数と時刻と種類だけを数えた物を受け取ります。原文が貼られたら、その事を伝え、伏せ方を案内します。
- このコンピューターで読むだけの命令(`journalctl`、`last`、`ss`、`timedatectl` など)は、一言断ってから打ってかまいません。出力に名前や番地が出る物は、数を数える形(`| wc -l`)か、伏せる道具を通す形で打ちます。sudo の要る命令と、設定を変える命令は打ちません。文で出し、人が読んで打ちます。
- 決まりを一つ書いたら、05 の試しの手順を一緒に書きます。試していない決まりは「試していない」と一覧に書きます。
