# 08 週の定例と、AI が新しくなった時の見直し

監視は、作った日から古くなります。人が入れ替わり、コンピューターが増え、クラウドの設定が変わります。週に一度の定例で、監視を今の形に合わせます。

## 週の定例(例: 30 分)

時間と曜日は会社が決めます。正と副の二人で読みます。

| 順 | する事 | 使う物 | 書き残す物 |
|---|---|---|---|
| 1 | kagi で全部のサーバーのコピーを取り直し、差を読む | `kagi weekly`、`kagi log verify`(07) | 増えた直す物と、その扱い |
| 2 | この週に鳴った通知を、決まりごとに数える | 06 の直しの表 | 本物、業務の例外、決まりの誤りの数 |
| 3 | 鳴りすぎと、鳴らなすぎの決まりを一つずつ直す | 06 の 3 | 直した事と理由 |
| 4 | 記録が全部のコンピューターから届いているかを見る | 決まり 8 | 届いていないコンピューター |
| 5 | 記録のサーバーのディスクの残りと、記録のサーバーの控えを見る | 02 の 1 | 残り、控えの日付 |
| 6 | 人とコンピューターの変わり目を、一覧と普段の形に入れる | 01、03 | 入った人、辞めた人、足したコンピューター、やめたコンピューター |
| 7 | 試していない決まりを一つ試す | 05 | 試しの記録 |

定例の結果は、kagi の記録に一行足します。

```bash
kagi log add --actor aoki --action detection.weekly --detail "2026-W46 定例。増えた差 1、鳴った数 14、直した決まり DT-01"
```

## 月と年にする事(例)

- **月に一度**: 01 の一覧を最初から読み直す。業者が持つ機器の記録を、こちらに渡してもらえているかを確かめる。
- **年に一度**: 保存の期間(02 の 5)を見直す。受ける人の表(06)を見直す。全部の決まりを 05 の手順で試す。

周期は例です。会社が決めます。

## AI が新しくなった時の見直し

使っている AI(Claude のモデル)や、その使い方の制度が変わった時は、次の所を見直します。

1. **渡してよい物の線。** Cyber Verification Program の条件(データの保持、社内の使い道、Defense Access に要る守りの設定)は変わる事があります。`sources.md` の頁を読み直し、閲覧日を書き直します。たとえば、原文は 2026-12-15 から Defense Access に、フィッシングに強い多要素の認証と、長く使い続ける API の鍵を使わない事を求めると書いています。
2. **AI に任せる所。** 新しい AI が、決まりの案、記録の読み取り、Sigma の形への直しを、前より正確にできるようになっている事があります。前に人がしていた所のうち、AI に案を出させる所を増やせるか見ます。決めるのは人のままです。
3. **AI が誤った所。** これまでの定例の記録で、AI の案が外れた所(存在しない命令、違うイベントの ID、確かめていない設定)を読み返し、新しい AI でも同じ誤りが出るかを、試験用の環境で確かめます。
4. **命令の例。** 各章の「確かめていません」の例を、新しい AI と一緒に、試験用のコンピューターで一つずつ確かめ、確かめた日を書き足します。
5. **守ることの見直し。** SKILL.md の「守ること」を読み直します。AI が新しくなっても、記録をそのまま渡さない、値を会話に出さない、コンピューターを変える手は人が打つ、の三つは変えません。

## 道具やコンピューターが変わった時

- OS のメジャーバージョンが上がった時は、02 の記録の置き場と命令の形を確かめ直します(例: Debian 13 では `/var/log/auth.log` が標準で無く、`last` が wtmpdb の物です)。
- 記録の置き場(SIEM)を替えた時は、04 の決まりを全部 05 で試し直します。Sigma の形で書いてあれば、書き直しが少なく済みます。
