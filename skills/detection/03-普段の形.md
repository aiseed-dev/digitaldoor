# 03 普段の形を書く

異常は、普段の形から外れた物です。普段の形を先に書かないと、何を鳴らすかが決まりません。逆に、普段の形が書いてあれば、決まり(04)の多くは「表に無い物」として書けます。

## 何を書くか

01 の一覧の行ごとに、次の五つを人の言葉で書きます。

| 欄 | 書くこと | 例 |
|---|---|---|
| 誰が | 入る人、操作する人の名前か役 | 係の 2 人(アカウントの名は表に) |
| いつ | 曜日と時刻の幅 | 平日 8〜20 時。月末は 22 時まで |
| どこから | 網、国、機械 | 社内の網から。在宅の日は国内の家の回線から VPN で |
| 何で | 入り方 | SSH の鍵で。VPN は証明書とワンタイムの番号で |
| どれだけ | 回数、量 | ログインは一日 10 回ほど。外への送り出しは一日 2 GB まで |

数と時刻は例です。会社の普段を書きます。

## どうやって知るか

普段の形は、二つの道で集めます。

1. **人に聞く。** 係、各部署の人、業者に、誰がいつ何をするかを聞きます。聞いた事をそのまま表に書きます。
2. **記録で確かめる。** 聞いた形と、記録の数を並べます。記録の中身でなく数で見ます。

Linux の例(この机の PC で、sudo なしで形が通る事を確かめた物。自分の記録しか見えない時は、係のアカウントで打ちます):

```bash
# この 7 日の SSH の成功の数を、日ごとに
journalctl _COMM=sshd --since -7d --no-pager -q -o short-iso --grep 'Accepted' \
  | cut -c1-10 | sort | uniq -c

# この 30 日のログインの履歴の、時刻の分かれ方(時ごとの数)
last -j --time-format iso -s "$(date -d '-30 days' '+%Y-%m-%d %H:%M:%S')" | python3 -c '
import json, sys, collections
d = json.load(sys.stdin)
c = collections.Counter(e["login"][11:13] for e in d["entries"])
for h in sorted(c): print(h, c[h])'
```

Debian 13 の `last` は wtmpdb の物で、`-s` の時刻は `YYYY-MM-DD HH:MM:SS` の形で書き、`-j` で JSON を出します(2026-11-11 にこの机の PC で確かめた)。ほかの版の `last`(util-linux の物)では、`-j` と `--time-format` が無い事があります。その時は `last -F -n 5` で列を見てから数え方を直します。

Windows の例(2026-11-11 に learn.microsoft.com で確かめた書き方。Windows の機械では打っていません):

```powershell
# この 7 日のログオンの成功(4624)を、ログオンの種類ごとに数える
$since = (Get-Date).AddDays(-7)
Get-WinEvent -FilterHashtable @{ LogName='Security'; Id=4624; StartTime=$since } |
  Group-Object { $_.Properties[8].Value } -NoElement
```

`Properties[8]` がログオンの種類(LogonType)に当たるかは、イベントの版で変わります(確かめていません)。一件を `$e.ToXml()` で見て、`LogonType` の位置を確かめてから使います。

## 書き方の決まり

- **普段を書いてから、外れを決めます。** 「夜中の管理者のログイン」は、「管理者は平日の昼にしか入らない」と書いてあって初めて決まりになります。
- **例外も普段に書きます。** 月末の締め、年に一度の棚卸し、業者の定期の保守の日。知っている例外を書いておくと、鳴りすぎが減ります。
- **一人の普段を細かく書きすぎません。** 社員一人ひとりの行動の型を作る事は、守りに要る範囲を超えやすく、社員の見張りになります。普段は、役(管理者、係、業者)と網(社内、VPN、国外)の単位で書きます。
- **変わったら書き直します。** 人が入れ替わった、在宅の日が増えた、新しいクラウドを入れた。普段が変われば、決まりも変わります。週の定例(08)で見直します。
