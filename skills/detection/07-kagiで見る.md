# 07 kagi で見る

記録を監視する決まり(04)は、起きた出来事を拾います。kagi は、サーバーの今の形を、人が書いた表と突き合わせ、違いを出します。違いは、出来事の記録が無くても、何かが変わった事を示します。この章では、kagi の差を「検知」として扱う形を作ります。

kagi の入れ方と使い方は `skills/kagi/` にあります。kagi は鍵の値を読まず、サーバーを変えません。直す手は文で出し、打つのは人です。

## 表と記録を揃える

- kagi の `machines.toml` と `ports.toml` の `host` の名を、01 の一覧と 02 の記録に出るコンピューターの名と同じにします。
- kagi の在庫表(`inventory.toml`)に、監視に使う秘密(記録を送る証明書の秘密鍵、通知を送るトークン、記録のサーバーの管理者の鍵)を一件ずつ書きます(値は書きません)。

## kagi の差と、決まりの対応

| kagi が出す物 | 命令 | 当たる決まり(04) | 重さの例(06) |
|---|---|---|---|
| 表に無いポート、表にあって開いていないポート、外向きで表と違うポート | `kagi check ports`、`kagi machine check` | 5 | 中 |
| 表に無い鍵、弱い鍵、在庫表に無い鍵 | `kagi machine check`、`kagi key list` | 6 | 高 |
| 表に無いアカウント、表に無い管理者 | `kagi machine check` | 4 | 高 |
| パスワードで入れる、root がパスワードで入れる | `kagi machine check` | 3 の備え | 中 |
| ホストの鍵の指紋が表と違う | `kagi machine check` | 入れ直したのでなければ、別のサーバーか、間に誰か居る | 高 |
| 表のサービスが止まっている、落ちた unit | `kagi machine check` | 10 | 中 |
| 控えの timer が止まっている | `kagi machine check`(`timers`) | 7 | 中 |
| 時計が合っていない | `kagi machine check` | 14 | 低 |
| 期限切れ、期限の近い秘密 | `kagi check inventory` | — | 低 |
| 期限切れのまま取り消していない token | `kagi check tokens` | — | 中 |
| 記録の連鎖が切れた(行が消された、変えられた) | `kagi log verify` | 8 | 高 |
| 秘密らしい文字列がファイルにある | `kagi scan` | — | 中 |

重さは例です。会社が決めます。

## 週の定例の中で

週に一度、`kagi weekly` を走らせます。全部のサーバーのコピーを取り直し、前のコピーから「増えた直す物」と「消えた直す物」を一枚に書きます(`skills/kagi/07-週の定例.md`)。

```bash
kagi weekly --dir ~/kagi-data
kagi log verify --dir ~/kagi-data
```

- **増えた直す物は、検知です。** 増えた一件ごとに、04 の当たる決まりの「最初にする事」をします。誰が、いつ、なぜ変えたかを、記録(02)の同じ時期で探します。
- **消えた直す物は、直した証です。** 直した人と日付を、kagi の記録に一行足します。
- **入れなかったサーバーは、それ自体が検知です。** `kagi weekly` は入れなかったサーバーを末尾に出します。止まっているのか、鍵が替わったのか、ネットワークが切れたのかを確かめます。

kagi の出力には、鍵の値も番地も出ません(サーバーの名と指紋とポートの番号は出ます)。AI に渡す時は、サーバーの名を伏せたければ `scripts/mask.py` を通します。

## 記録と kagi を並べて読む

kagi で差が出たら、そのサーバーの記録を同じ時期で読みます。例:

- 「表に無い鍵が aoki に入っている」と出た → 記録で、その週に aoki で入った送り元と時刻(決まり 1、3)、`authorized_keys` を変えた記録(auditd を入れていれば)を探します。
- 「表に無い管理者」と出た → 記録で、usermod や gpasswd の行(決まり 4)を探し、誰の sudo で足されたかを追います。
- 「表に無いポート」と出た → 記録で、そのポートのサービスがいつ動き始めたか(`journalctl -u <サービス>`)を探します。

並べて読んでも理由が分からない差は、入られた疑いとして扱い、`skills/incident-response/` に移ります。
