## 1. 試験の対から始める

仕様の多くは、終わりに「入力 → 期待する出力 → 要求の番号」の表を持っています(例: `docs/扉コントローラ仕様書.md` 第 8 章、`docs/要求仕様/02_reader.md` の試験の表)。テストはこの一行を一つの関数にするのが基本です。表に無い要求は、要求の文から入力と期待を起こし、表に足す案として使う人に見せます。仕様を先に直し、テストを後に書くのが、このリポジトリの順番です。

期待値は、仕様の言葉から決めます。実装を読んで「今こう動くから」と期待値を決めると、実装の誤りが正しいことになってしまいます。

## 2. 番号の付け方

テストの docstring の先頭の行に、確かめる要求の番号を空白区切りで書き、コロンの後に何を確かめるかを書きます。

```python
def test_fire_refuses_lock_whatever_power_policy():
    """R-CT-05: 火災中の施錠要求は、停電の設定が保持でも受け付けない。"""
```

一つのテストで複数の要求を確かめるときは並べます(`"""R-CT-16 R-CT-24: ..."""`)。番号は仕様にある物だけを書きます。`taiou.py --check` は、仕様に無い番号を名指ししたテストがあると失敗します。

## 3. テストの形

疑似の扉(digitaldoor-controller)のテストは pytest で、接点を模擬(`SimContacts`)に替えて回ります。

```python
from digitaldoor_controller.audit import Audit, HmacSigner
from digitaldoor_controller.contacts import SimContacts
from digitaldoor_controller.controller import Config, Controller

def test_autolock_waits_while_door_open():
    """R-CT-09: 扉が開いている間は自動施錠せず、閉じた後に施錠する。"""
    c = Controller(SimContacts(), Audit(HmacSigner(b"k" * 32)), Config(autolock_s=5))
    c.set_time(1000.0, True)
    c.on_auth("A")
    c.contacts._door_open = True
    c.on_door(True)
    c.tick(1010.0)
    assert not c.locked                 # 開いている間は施錠しない
    c.contacts._door_open = False
    c.on_door(False)
    c.tick(1011.0)
    assert c.locked
```

- 時刻は `set_time` と `tick` で与え、実時間を待ちません。テストが速く、決定的になります。
- 記録の中身(種別、事象、結果、詳細)も確かめます。扉の要求の多くは「記録に残す」ことだからです。
- 個人情報はバイト列と架空の名前で代えます。

## 4. わざと壊す

テストを書いたら、実装を一か所ずつ壊して、テストが落ちることを見ます。落ちなかったら、そのテストは何も守っていません。

壊し方の例:

| 壊し方 | 落ちるべきテスト |
|---|---|
| 火災中の施錠の拒否の条件を、停電の設定で決めるように戻す | 火災中の施錠要求を拒むテスト |
| 監査の検査で、署名の確認を飛ばす | 鍵違いや書き換えを指摘するテスト |
| 伝票の書き出しで、どこまで出したかを覚えない | 続きから出す、二度出さないテスト |
| 記録の書き出しを、判断の排他の中で行う | 箱が固まっても自動施錠が進むテスト |

壊したら必ず元に戻し、全部のテストが通ることを確かめてから次へ進みます。退避と復元は、作業用の一時ディレクトリにファイルをコピーして行うのが確実です。

## 5. 対応の集計(taiou.py)

```bash
python3 tools/taiou.py --check
```

`docs/適合の現在.md` に、要求の番号ごとのテストと、テストの無い要求(未検証)を書き出します。標準ライブラリだけで動きます。要求仕様やテストを直したら作り直します。未検証は失敗ではありません。実機で確かめる物と、まだ書いていない物を分けて、理由を報告に書きます。

## 6. よくある落とし穴

- **待ち続けるテスト。** スレッドや排他を扱うテストで `with lock:` のように無期限に待つと、壊れた実装でも、待った後に通ってしまいます。`lock.acquire(timeout=1)` のように上限を付け、時間内に取れないことを失敗にします。
- **同じセッションで実装とテストを一度に作る。** テストが実装に合わせて書かれ、何も確かめなくなります。仕様 → テスト(先に固定) → 実装の順にします。
- **一度通ったら終わりにする。** 実装を変えたら全部のテストを回し、`taiou.py` で対応を作り直します。
- **記録の形を言語に依存させる。** ハッシュや署名の元のバイト列を、ある言語の JSON の書き出しに頼ると、他の言語の受け手が同じバイト列を作れないことがあります(小数の書き方が言語で違う)。署名したバイト列そのものを渡すか、整数と文字列だけの正規の形を決めます。
