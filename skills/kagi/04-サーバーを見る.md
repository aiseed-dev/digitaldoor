# 04 サーバーを見る(Linux のサーバーの今の形)

`machines.toml` にサーバーと鍵を書きます(`kagi init` の雛形に欄の説明があります)。書くのは、サーバーの名、役、入れてよい人(`users`)、sudo を持ってよい人(`admins`)、入れてよい鍵(`keys`)です。鍵は `[[key]]` に、名と持つ人と公開鍵のファイル(`.pub`)を書きます。**秘密鍵とパスワードは書きません。**

## コピーを取り、比べる

```bash
kagi machine collect --host db1
```

```bash
kagi machine check --host db1
```

`collect` は、自分の ssh と自分の鍵でサーバーに入り、読むだけの文を走らせて、コピーを `facts/` に置きます。サーバーは変わりません。走らせる文は `kagi machine script` で読めます。パスワードを尋ねられるサーバーと、初めてのサーバー(ホストの鍵をまだ確かめていない)には入りません。先に自分で `ssh db1` し、尋ねられた指紋を、サーバーの画面で打った `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` の結果と比べてから使います。

ssh で入れないサーバーは、文を持って行って走らせ、出力をファイルで渡します。

1. `kagi machine script > k.sh`
2. サーバーで `sh k.sh > facts.txt`(root のコピーは `sudo sh k.sh > facts.txt`。見える物が増えます)
3. `kagi machine check --host db1 --facts facts.txt`

この PC 自身は `kagi machine collect --host <名> --local` です。

## 直す手

出るのは「直す」と「見るだけ」です。直す物の手は次の命令で出ます。

```bash
kagi machine fix --host db1
```

sh の文が出ます。**kagi は走らせません。** 読んで、サーバーの端末で一つずつ打ちます。`【読んで確かめてから】` の印が付いた手(ssh の形、鍵、人と管理者、防火壁、ポート、入口、ホストの鍵)は特に一行ずつ読みます。ssh の形を変える行は、先に別の窓から鍵で入れる事を確かめてから打ちます。防火壁の外へ出る通信を閉じる手は「二段目」として最後に分けて出ます。入る向きを閉じて ssh で入れる事を確かめ、要る外への道を数えてから打ちます。終わったら `collect` と `check` をもう一度走らせます。

確かめ方: 「直す物は無い」まで進めます。「見るだけ」の中の「表に指紋が無い」は、サーバーの画面で指紋を見てから `hostkey` に書きます。

## サーバーの役に合わせて足す欄

- **公開のサーバー(入口がある)。** `[[door]]` に、入口ごとに `site`、`who`(誰が入れるか)、`auth`(`public` 誰でも、`app` 裏のアプリが確かめる、`gate` 前の Caddy が確かめる、`lan` ネットワークで絞る)を書きます。書いていない入口は「表に無い入口」、`gate` なのに確かめる行が無い入口は「門が無い」と出ます。`app` の入口でアプリが本当に確かめているかは、kagi は見ません。外から、招待コードやログイン無しで試して確かめます。
- **動かしている物があるサーバー。** `services`(と、自分の systemd で動かす物は `user_services`)を書きます。止まると「直す」に出ます。控えの timer は `timers = ["backup"]` です。
- **重いデータを置くサーバー。** `data = ["/srv/photos"]` と書きます。大きさと、そのディスクの残りが「見るだけ」に出ます。置き場が無い(ディスクが外れた)と「直す」に出ます。

公開のサーバーとデータベースのサーバーの表と手順の見本は、seed のリポジトリ(https://github.com/aiseed-dev/seed )の `deploy/` にあります。
