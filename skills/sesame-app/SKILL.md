# Sesame を自分で作ったアプリで動かす

Sesame は、登録のときに錠とアプリの間で 16 バイトの鍵(32 桁の 16 進)を一つ作ります。この鍵を持つ物は、誰でもその Sesame を開けられます。錠が知っている鍵はこの一つだけで、写した物は全部同じ鍵です。このスキルは、その鍵をなくさず、漏らさずに、自分のアプリと PC で Sesame を動かすところまで進めます。

錠一台で、鍵の管理の課題(写すと散る、一人だけは止められない、ログに漏れる)がそのまま見えます。実演と、情報システム部門の勉強会の最初の段に使えます(5 章)。

## 守ること

- **鍵の 32 桁と管理者の符号を、会話に入れない。** あなた(AI)は 32 桁も符号も見ない、書かない、貼らせない。チャット、メール、Issue、コミット、ログにも入れない。人に頼むのは「アプリの画面を見て、PC の伏せた入力に打つ」ことだけです
- **アプリをアンインストールさせない。** スマートフォンの鍵はアプリの保管庫にあり、Android ではアンインストールで消えます(iOS のキーチェーンは残ることがあります)。上書きで入らないときも、消す前に止めて人に相談します(3 章)
- **上書きの前に、念のため鍵を PC に写しておくことを勧める。** 初めて起動したときに、鍵を今までの保存領域から端末の保管庫へ移します。移し替えは失敗しても元を消さない作りですが、写しがあれば何が起きても戻れます(3 章)
- **鍵のファイルはリポジトリに入れない。** PC の鍵は `~/.config/digitalkey/sesame-keys.json`(権限 600、`.gitignore` 済み)。疑似の鍵は `sesame-keys-fake.json` で、本物と混ざりません。試験と画面の確かめで、本物のファイルを読まず、作らず、触りません
- **まず疑似で通す。** 画面とコマンドは `--fake` で、実機も Bluetooth も使わずに動きます。実機は BLE のアダプタを挿してから触ります
- **公式アプリの鍵とは別の物。** 公式アプリで登録した Sesame は、このアプリから見ると「登録済 (鍵なし)」です。公式アプリの鍵を取り出す手順は、このスキルでは扱いません
- **役の分け方は画面の歯止めで、鍵の守りではない。** 利用者に鍵を渡したあと、その人が別の道具を使えば管理者の画面を通らずに開けられます。このことを、画面にも説明にもそのまま書きます(4 章)

## 1. 構成

| 物 | 置き場 | 役 |
|---|---|---|
| 画面(Flet) | `drivers/digitalkey-sesame/digitalkey_sesame/app.py` | 利用者の画面(鍵のある Sesame の一覧、開け閉め、鍵を受け取る)と、管理者の画面(探す、登録、渡す、渡した相手の控え、リセットと渡し直しの案内、設定)。PC でもスマートフォンでも同じ画面 |
| 命令 | `digitalkey_sesame/cli.py`(`digitalkey sesame ...`) | `scan`、`register`、`import`、`status`、`lock`、`unlock`、`toggle`、`version`、`keys`、`app` |
| 鍵の置き場 | `keystore.py` | 鍵と役(管理者、利用者)、設定、移し替え(`migrate_kv`)。PC は JSON のファイル、スマートフォンは端末の保管庫 |
| 保管庫と端末の認証 | `securestore.py` | Flet の SecureStorage(flet-secure-storage。Android Keystore、iOS のキーチェーン)の設定と、管理者の画面を開くときの端末の認証 |
| 渡し方 | `handoff.py` | QR の中身、管理者の符号、QR の画像、渡した相手の控え、受け取り(ログインできたときだけ保存) |
| QR を読む | `qrread.py`、`qrcamera.py` | 画像から QR を読む口(pyzbar)と、アプリ自身のカメラ(flet-camera)の口。差し替えられる |
| 通信 | `protocol.py`、`device.py` | 広告の解析、ECDH での登録、AES-CMAC でのログイン、AES-CCM の命令。説明は各ファイルの先頭 |
| Bluetooth | `transport_bleak.py`(PC)、`transport_fletble.py` と `flet_ble/`(Android、iOS) | 同じ画面が、PC では bleak、スマートフォンでは flet-ble で話す |
| 疑似の Sesame | `fake.py` | テストと、実機なしの画面の確かめ。疑似の保存領域、端末の認証、カメラも入っている |
| 錠のドライバ | `locks.py` | `sesame:<UUID>`(BLE)と `sesameweb:<UUID>`(Hub 3 経由の Web API)。扉のコントローラから錠を動かす |

## 2. PC で動かす

```bash
.venv/bin/pip install -e ./controller -e . -e "drivers/digitalkey-sesame[app,dev]"
digitalkey sesame app --fake          # 疑似の Sesame で画面を見る
digitalkey sesame app --web --fake    # 画面をブラウザで開く(Bluetooth はこの PC のまま)
digitalkey sesame --fake scan         # 命令も疑似で
```

PC で QR を読むには libzbar(Debian なら `libzbar0`)が要ります。無くても動き、読み取りの代わりに 32 桁を打ち込む道だけになります。

実機は、BLE のアダプタを挿し、`bluetoothctl show` で見えてから使います。

```bash
digitalkey sesame scan                        # 近くの Sesame。未登録か登録済みかが出る
digitalkey sesame register <UUID> --name 玄関  # 未登録の Sesame だけ。管理者の鍵を PC に保存する
digitalkey sesame unlock <UUID>
```

## 3. スマートフォンのアプリを組んで入れる

組むのは `drivers/digitalkey-sesame` で行います。設定(アプリ名「Sesame の鍵」、パッケージ名 `dev.aiseed.digitalkey.sesame`、Bluetooth とカメラと位置情報の権限、iOS の利用目的の文、Python の部品、バックアップの除外)は `pyproject.toml` の `[tool.flet]` にあります。

```bash
cd drivers/digitalkey-sesame
flet build apk        # Android(arm64)。開発機で試す形
flet build ipa        # iOS(macOS と Xcode が必要)
```

### 今の鍵が入ったスマートフォンに上書きするとき

前の版のアプリは、鍵をアプリの保存領域(SharedPreferences)に置いていました。新しい版は、鍵を端末の安全な保管庫に置きます。**初めて起動したときに、鍵を保管庫へ移します。** 手順は次の順です。

1. **移す前に、念のため鍵を PC に写しておく。** 前のアプリで Sesame を選び、「鍵を書き出す」で 32 桁を出し、PC で `digitalkey sesame import <UUID> --name 玄関` を実行して打つ(4 章)。PC の鍵が写しになる(管理者の符号は要らない。この PC では利用者の鍵として入るが、Sesame を開け閉めするには足りる)
2. 前と同じ開発機で、同じ署名の鍵で組む。署名の鍵と証明書は、リポジトリに入れず開発機で持つ
3. 上書きで入れる: `adb install -r build/apk/<組んだファイル>.apk`
4. **アンインストールしない。** 「署名が違う」「入れられない」と出たら止めて、人に相談する。道は二つ: 前と同じ署名の鍵を探して組み直す、または手順 1 で写した鍵を PC に残したまま入れ直す(そのとき、スマートフォンの鍵は新しいアプリに無いので、管理者から鍵を受け取り直すか、登録し直す)
5. 起動して、Bluetooth とカメラと位置情報(Android が近くの機器を探すのに求める権限)を許可する
6. ログ欄に「鍵の保管庫: 鍵 N 件を保管庫に移し、読み戻して確かめてから、元を消しました」が出ること、一覧に今までの Sesame が「(管理者)」付きで出ること、開け閉めできることを確かめる

移し替えは、写す → 読み戻して一致を確かめる → 元を消す、の順で行います。保管庫が読めない、書けない、書いたはずが読めない、のどれでも元は消さず、今までの保存領域のまま動き(ログ欄とメッセージに理由が出ます)、次の起動でもう一度移します。前の版の鍵は「管理者」として引き継ぎます。保管庫は、エラーのときに中身を全部消す設定(`reset_on_error`)を無効にしています。

- 上書きできるのは、前と同じ署名の鍵で組んだときだけです
- 配布するときは Google Play(`flet build aab`)と App Store で行い、APK をリポジトリに置いて配ることはしません
- 鍵は端末のバックアップで別の端末へ移りません。Android はアプリのデータをバックアップから外し(`allowBackup = "false"`)、iOS はキーチェーンの項目を「この端末だけ」(ThisDeviceOnly)の扱いにします。機種変更のときは、バックアップの復元に頼らず、管理者から鍵を受け取り直します
- 依存の部品は `pyproject.toml` の `[tool.flet.android]` と `[tool.flet.ios]` の `dependencies` にあります。flet-secure-storage、flet-camera、segno(QR を作る)、pillow、pyzbar と flet-libzbar(QR を読む)です。**組む環境で、この部品が入ることはまだ確かめていません**(下の 8 章)

## 4. アプリで使う

### 役

鍵ごとに役を持ちます。一台の端末で、ある Sesame は管理者、別の Sesame は利用者、ということがあります。

| | 管理者 | 利用者 |
|---|---|---|
| なり方 | その端末で登録した。管理者として渡された。前の版の鍵(役の欄が無い物) | 利用者として渡された。32 桁を打ち込んだ。管理者の符号の無い鍵 |
| 利用者の画面 | 開く | 開く |
| 管理者の画面 | 開く | 開かない |

- 管理者の画面は、管理者の鍵が一つでもある端末で開きます。鍵が一つも無い端末でも開きます(最初の Sesame を登録するため)。利用者の鍵しか無い端末では開きません
- 管理者として渡すときだけ、32 桁に「管理者の符号」(鍵と UUID から決まる 8 桁)を付けます。符号の無い鍵は利用者として入り、あとから管理者には上がりません
- 管理者の画面を開くときに、端末の認証(生体認証か PIN)を求めるかどうかは、管理者が管理者の画面の設定で選びます(スマートフォンのアプリ)

### 画面の歯止めであって、鍵の守りではない

Sesame の錠が知っている鍵は 32 桁の一つだけで、錠の側では人を分けられません。役の分け方は、このアプリの画面の中の約束です。32 桁を持つ人が別の道具(このリポジトリの命令行や公開の SDK)を使えば、歯止めは通ります。管理者の符号も、端末の認証も、画面の中の関所です。防げるのは、受け取った人がこのアプリで鍵をさらに写して広げることです。一人を本当に止めるには、Sesame をリセットして登録し直し、残る人に渡し直します(「リセットと渡し直しの案内」が管理者の画面にあります)。

### 操作

| 操作 | 画面 | 起きること |
|---|---|---|
| つなぐ | 利用者の画面の「鍵のある Sesame」を押す | 近くからその Sesame を探し、鍵でログインし、状態(施錠、解錠)、電池、角度が出る |
| 開け閉め | 「解錠」「施錠」「トグル」 | 「自分の呼び名」が Sesame の履歴に残る(名乗りなので偽れる) |
| 鍵を削除 | 「鍵を削除」 | この端末の鍵だけを消す。ほかの機械に写しがあればそちらは使える。写しが無ければ、鍵を受け取り直すか、Sesame をリセットして登録し直すまで動かせない。管理者の鍵でも、渡した相手の鍵は消えない |
| 鍵を受け取る | 利用者の画面の「鍵を受け取る」 | 渡す人の画面の QR を、このアプリのカメラで読む。その Sesame にログインできたときだけ保存する |
| 探す | 管理者の画面の「スキャン開始」 | 近くの Sesame が並ぶ。印は「鍵あり (管理者)」「鍵あり (利用者)」「登録済 (鍵なし)」「未登録 → 登録可」 |
| 登録 | 管理者の画面で未登録の Sesame を押し、「この Sesame を登録」 | 鍵を作って、この端末に管理者の鍵として保存する |
| 渡す | 管理者の画面の「渡す」 | 下の「鍵を渡す」 |
| 渡した相手の控え | 管理者の画面 | 誰に、いつ、どの役で、どの道で渡したか。この端末から渡した分だけ。追記だけで消さない。リセットして登録し直した後は、前の行に「リセット前」の印が付く |

### 鍵を渡す(対面で、アプリからアプリへ直接)

網(LINE、メール、クラウド)を通しません。送った先のサービスにも写しが残るからです。

1. 渡す人が、管理者の画面の「渡す」で Sesame を選び、役(利用者として、管理者として)と相手の呼び名(控えに残る名前)を入れて、「QR を出す」を押す。確かめの文のあとに QR が出る
2. 受け取る人が、自分のアプリの「鍵を受け取る」で、自分のカメラで QR を読む。端末のふつうのカメラアプリや、画像を読み取るサービスは使わない。読んだ内容がそちらに残ることがあるため
3. QR は 60 秒で自動で閉じて消える。受け取ったら閉じる。周りの人に撮られない所で行う
4. 受け取る側は、その Sesame にログインできたときだけ保存する。違う鍵、未登録の Sesame、近くに無い Sesame では何も保存しない

QR の中身は、版、UUID、32 桁、役、管理者の符号(管理者のときだけ)の 1 行です(`handoff.py`)。人の名前は入れません。

読み取りが使えないとき(カメラが使えない、許可しない、libzbar が無い)は、32 桁を打ち込む道があります。受け取る側が「鍵を受け取る」の「32 桁を打ち込む」で、近くの Sesame を選んで 32 桁を打ち込みます(伏せ字)。この道で入った鍵は利用者です。

### 鍵を PC に写す

1. 管理者の画面の「渡す」で Sesame を選び、相手の呼び名(「PC」など)を入れて、「32 桁を見せる」を押す。確かめのあとに 32 桁が出る(管理者として渡すときは管理者の符号も出る)。閉じると消える
2. PC で `digitalkey sesame import <UUID> --name 玄関` を実行し、32 桁を打つ(画面に出ない、履歴に残らない)。続けて管理者の符号を尋ねられる。管理者として写すときだけ符号を打ち、利用者なら空のまま Enter
3. PC はその鍵で Sesame にログインできたときだけ保存する。できなければ何も保存しない

- 32 桁は、見て打ちます。スマートフォンのコピーと貼り付けは、クリップボードがほかのアプリやクラウドに写ることがあるので、使うときはそのことを承知の上で使います
- 写したあと、スマートフォンの鍵を残すか消すかは、持ち主が決めます。残せば、鍵は二か所にあります。どこに写しがあるかは、持ち主が書き留めます

### Matter の電子錠として見せる

鍵を写した PC(miniPC)で、扉を立て(`digitalkey door-serve --lock sesame:<UUID>`)、盤(`digitalkey panel`)の QR をスマートフォンのホームアプリで読みます。手順と要る物(BLE のアダプタ、avahi-utils)は `docs/使い方.md` の「実演」にあります。

## 5. 実演と勉強会で見せること

| 見せること | アプリと PC での操作 | 気づいてもらうこと |
|---|---|---|
| 開け閉めは簡単 | アプリで一押しで開く | 錠を動かすのは部品の仕事 |
| 鍵はただの 32 桁 | 「32 桁を見せる」の画面 | 期限も記録もなく、持てば開く |
| 写せば増える | PC に写すと、アプリと PC の両方から開く | 写した数を、錠は知らない |
| 渡し方 | 管理者が QR を出し、家族のアプリが読む | 網を通さなくても、渡した数は控えにしか残らない |
| 役は画面の歯止め | 利用者として受け取ると管理者の画面が開かない。PC の `import` なら通る | 錠の側では人を分けられない |
| 一人だけは止められない | 「この人の分だけ止めてください」 | 止めるには Sesame のリセット。全員が止まる |
| 管理された道 | 扉のコントローラの道(`tools/jitsuen.py`) | 一人ずつの資格情報なら、一人だけ止められ、記録が残る |

錠の側に鍵が一つしかないのは、この製品の作りです。一人ずつの鍵は、錠の外の門番(扉のコントローラ)で作ります。

## 6. 困ったとき

| 起きること | 見る所 |
|---|---|
| 「Bluetooth: 利用不可」 | PC は BLE のアダプタと `bluetooth.service`。スマートフォンは Bluetooth と位置情報の許可 |
| 一覧に出ない、つなげない | Sesame の電池。近づける。別の端末がつないだままだと、つなげないことがある |
| 「登録済 (鍵なし)」 | 別の端末か公式アプリで登録した Sesame。管理者から鍵を受け取る。どこにも無ければ、Sesame をリセットして登録し直す |
| ログインに失敗する | 鍵が違う。リセットして登録し直した Sesame には、前の鍵は効かない。渡し直してもらう |
| 管理者の画面が開かない | 利用者の鍵しか無い端末では開かない(仕様)。管理者の認証を入れていれば、端末の画面ロックと生体認証(PIN)が使えるか確かめる |
| 「鍵を受け取る」でカメラが使えない | カメラの許可。許可しないときは「32 桁を打ち込む」(利用者として入る) |
| 「QR の読み取りを使えません」 | PC なら libzbar(`libzbar0`)が無い。スマートフォンでは組むときに pyzbar と flet-libzbar が入っていない。32 桁を打ち込む道は使える |
| 「鍵の保管庫: …元は消していません」 | 保管庫に移せなかった。鍵は今までの保存領域に残り、そのまま使える。次の起動でもう一度移す。続くなら、鍵を PC に写してから、人に相談する |
| 「保管庫が空です」 | 以前に移した鍵が失われた可能性。PC に写した鍵があれば `import` で取り込み、無ければ Sesame をリセットして登録し直す |
| 盤が起動しない | `avahi-utils` が無い。直し方が標準エラーに出る |

## 7. テストと確かめ

```bash
.venv/bin/python -m pytest -q drivers/digitalkey-sesame
```

テストは疑似の Sesame と疑似の保存領域で回り、本物の鍵を使いません。どの試験も鍵の置き場を一時のフォルダに向けます。確かめているのは、鍵と管理者の符号がログ、画面の記録欄、例外の文、標準出力に出ないこと(R-CM-12)、写す先と受け取る側でログインを確かめてから保存すること(R-CM-13)、役で画面を分けること(R-CM-14)、渡し方(R-CM-15)、保管庫への移し替えで鍵を失わないこと(R-CM-16)です。テストの docstring の先頭の行に、確かめる要求の番号を書きます。

疑似の画面で QR の出し方と画面の流れを見るには、`digitalkey sesame app --web --fake` を使います(鍵の置き場を変えるには `SESAME_KEYSTORE`、疑似のカメラの置き場を変えるには `SESAME_FAKE_CAMERA`)。疑似の Sesame の状態(登録済みか)は、画面を起動した処理の中にあるので、二つの画面の間で受け取りを通すことはできません。渡す端末から受け取る端末までの通しは、試験(`tests/test_app_screens.py`)で行います。実機の読み取りと保管庫は、疑似では確かめられません(8 章)。

## 8. 作らなかった物と、実機で確かめる物(2026-10-21)

### 実機で確かめる物

この機械では Android も iOS も実機で試せないので、次は組んだアプリで確かめます。上から順に行います。

1. **今の鍵が入ったスマートフォンへの上書き**(3 章の手順)。鍵を PC に写してから上書きし、初めての起動で「鍵を保管庫に移しました」が出て、一覧に「(管理者)」付きで出て、開け閉めできること。もう一度起動しても鍵があること。ここで鍵が出ないときは、アンインストールせず、PC の写しで戻る
2. **保管庫のバックアップ**。Android は、バックアップを有効にした端末で復元して(別の端末か、入れ直し)、鍵が出ないこと。`allowBackup = "false"` が組んだアプリの AndroidManifest に入っていること。iOS は、暗号化したバックアップを別の端末に復元して、キーチェーンの項目が出ないこと(ThisDeviceOnly)
3. **QR を読めること**(Android と iOS)。flet-camera の画像の流れ(JPEG)を pyzbar で読む。pyzbar と flet-libzbar と pillow が組んだアプリに入っていて、渡す側の画面の QR を、距離と明るさを変えて読めること。読めなければ、画像の大きさ(`qrcamera.py` の解像度)か、読む側の部品(OpenCV、自前の Flutter 拡張)を見直す
4. **端末の認証**。管理者の設定を入れると、管理者の画面を開くたびに生体認証か PIN が出て、取り消すと開かないこと。端末に画面ロックが無いときは設定を入れられないこと。Android では `enforce_biometrics` の鍵が画面ロックの変更で無効になることがあり、そのときの戻し方は決めていない(下)
5. **カメラの許可**。許可しない、あとから許可する、の両方で、「32 桁を打ち込む」に案内されること
6. **アプリの名前**。ホーム画面に「Sesame の鍵」と出ること

### 作らなかった物

- 読み取りの Flutter 拡張(mobile_scanner 等)。pyzbar で足りるかを、実機で見てからにする
- 端末の認証が壊れたとき(画面ロックを外した、生体認証を登録し直した)の戻し方。今は管理者の画面を開けなくなり、利用者の画面は使える。実機の挙動を見て決める
- 管理者の画面を開いたあとの認証の有効時間。毎回開くたびに求める
- 渡した相手の控えの書き出しと、複数の端末での同期。控えは、渡した端末にだけ残る
- Android の `dataExtractionRules`(端末間の移行の細かい指定)。`allowBackup = "false"` で足りる想定で、実機で見る
- 管理者の符号を鍵と別の秘密から作る(今は鍵と UUID から決まる。32 桁を持ち、このリポジトリを読んだ人は作れる)。画面の歯止めと割り切っている
- 組む環境での確認。`flet build` を、この機械で通していない(Flutter と Android SDK が無い)。依存の名前と版は pypi.flet.dev の mobile 用の車輪で確かめたが、組んで入ることは確かめていない
