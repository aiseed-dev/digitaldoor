# 04 作り直す

## この章で読むこと

止めた物(02)と、範囲(03)の中の物を、使える形に戻します。鍵、パスワード、トークンを出し直し、入られたコンピューターを入れ直し、控えから戻し、戻した後に監視します。

作り直しの手は全部、コンピューターやアカウントを変える手です。Claude は手順の文と順を出し、人が読んでから行います。値(新しいパスワード、新しい鍵)は、人が自分の端末で作り、Claude に見せません。

## 作り直す前に

- **入られた道が閉じているか。** 03 の「残っている道」が全部閉じたか、閉じていない物を止める権限を持つ人が知っているか。道が開いたまま作り直すと、新しい値もまた盗まれます。警察庁も、同じ経路から入られて再び被害に遭うおそれを挙げています(`sources.md` 10)。JPCERT/CC も、侵入の経路を塞ぐことを復旧の前に行うよう書いています(`sources.md` 14)。
- **コピーが取れているか。** 入れ直すコンピューターのコピー(01 の歩 4)。入れ直すと、調べる手がかりは無くなります。
- **警察と調査の会社に断ったか。** 通報している時は、入れ直す前に、警察に残しておく物が無いかを聞きます。警察は、復旧と業務の継続に配慮して捜査するとしています(`sources.md` 10)。

## 鍵、パスワード、トークンの出し直しの順

上から順に出し直します。上の物が攻撃者の手にあるうちに下の物を出し直しても、上の物から下の物を作り直されるからです。

| 順 | 物 | 理由 | 出し直した後の確かめ |
|---|---|---|---|
| 1 | 管理者の非常用のアカウント、一番上の鍵(00 の「人に結びつかない鍵」) | これがあれば他を全部作れる | 非常用で入れることを一度試し、また封をする |
| 2 | 認証の仕組みそのものの鍵(ドメインの鍵、クラウドの管理者の権限) | 全員のログインを偽れる | 調査の会社と手順を確かめてから |
| 3 | 機器の管理者のパスワード(VPN の機器、ルーター、防火壁、無線の機器) | 入口の機器 | 管理の画面に新しい値で入れる |
| 4 | サーバーの ssh の鍵、サービスのアカウント、API の鍵、証明書 | コンピューターどうしの道 | 新しい鍵で動くこと、古い鍵で断られること |
| 5 | 範囲(03)の中の人のパスワードと多要素の登録 | 盗まれた値の入れ替え | 本人が新しい値で入れる |
| 6 | 範囲の外の全員のパスワード | 範囲が分かり切らない時の念のため | 会社が決める |
| 7 | 控えの暗号のパスワード、無線 LAN のパスワード | 共有の値 | 控えが新しいパスワードで取れて戻せる |

6 を行うか(全員を替えるか)は、範囲がどこまで分かったかで、経営者が決めます。

### 値の作り方

- 新しい値は、パスワードの管理の道具で、人が作ります。前の値を少し変えた値(末尾の数字を増やす)は使いません。
- 同じ値を二つの所で使いません。漏れた値を他で使っていた所は、全部を替えます。
- 新しい値を人に渡す時は、事故の起きていた道(社内のメール、チャット)を使わず、手渡しか、00 で決めた会社の外の手段で渡します。
- ssh の鍵は、使う人の端末で作り、公開鍵だけをコンピューターに入れます。

```
[変える] 人(自分の端末で)
ssh-keygen -t ed25519 -C '<人>-<作った日>'
                                    # パスフレーズをつける。秘密鍵は端末から出さない
[変える] 人(読んで確かめてから。サーバーの上で、公開鍵を一行ずつ足す)
sudo install -o <人> -g <人> -m 600 /dev/null /home/<人>/.ssh/authorized_keys
sudo sh -c 'cat <公開鍵のファイル> >> /home/<人>/.ssh/authorized_keys'
```

```
[読む] 古い鍵で断られることの確かめ(別の端末から)
ssh -o IdentitiesOnly=yes -i <古い秘密鍵> <人>@<コンピューター>
                                    # Permission denied (publickey) と出れば止まっている
```

### 止めたアカウントを戻す時

02 で止めた本人のアカウントを戻すのは、次の三つがそろってからです。

1. その人の端末が範囲(03)の外か、入れ直したか。
2. その人のパスワードと多要素の登録を作り直したか。
3. その人がアプリに渡していた許可(OAuth の同意)を見直したか。

```
[変える] 人(読んで確かめてから)
# Linux
sudo usermod -e '' <人>    # 期限を外す
sudo usermod -U <人>       # パスワードのログインを戻す
# Windows
Enable-LocalUser -Name <人>
Enable-ADAccount -Identity <人>    # ドメイン
```

## コンピューターの入れ直しと控えからの復元

入られたコンピューターは、直すより入れ直す方が確かです。攻撃者は、入口を閉じられても入り直せるよう、遠隔で操作できる道具を残していくことがあります(警察庁 令和 7 年上半期の情勢、`sources.md` 11)。

**誰が決めるか:** 入れ直すか、見て直すかは、止める権限を持つ人が、03 の範囲と、調査の会社の意見で決めます。

### 歩 1 控えが無事かを確かめる

控えも攻撃の対象です。攻撃者は、復旧させないために控えを消すことがあります(`sources.md` 11)。戻す前に、控えが無事かを確かめます。

| 確かめる事 | 方法 |
|---|---|
| 控えが、入られた時刻より前の物か | 控えの日付と、03 の「いつから」を比べる。入られた後の控えには、攻撃者の仕掛けが入っているかもしれない |
| 控えの中身が暗号化されていないか | 控えから、いくつかのファイルを別のコンピューターに取り出して開く |
| 控えの仕組みの設定が変えられていないか | 控えの仕組みの管理の画面の変更の履歴 |
| 控えのファイルの値が変わっていないか | 控えを取った時に sha256 の一覧を残していれば、比べる |

JPCERT/CC は、被害を免れた控えを、安全が確かめられるまで切り離すか退避させること、自動の控えの仕組みで良い控えが上書きされるおそれがあることを書いています(`sources.md` 14)。控えの仕組みの自動の実行を止めるかを、ここで決めます。

```
[読む] Linux: 控えの中の物の sha256 を、前に取った一覧と比べる
cd <控えを取り出した所>
sha256sum -c <前に取った一覧>.sha256 2>&1 | grep -v ': OK$'
                                    # 何も出なければ全部一致

[読む] Windows
Get-FileHash -Algorithm SHA256 <ファイル>
```

### 歩 2 入れ直す

- 入れ直す時は、ネットワークから切り離した所で入れ、更新を当ててからネットワークに戻します。
- 入れ直しの元(OS の入れ物)は、提供元から取り直し、提供元が出している値(sha256 など)と照らします。
- 前のコンピューターの設定をコピーする時は、設定を一つずつ読んでからコピーします。攻撃者が足した設定(新しいアカウント、定期の仕事、外への転送の決まり)を写さないためです。
- 予備のコンピューターとイメージがあれば、ネットワークが無くてもその場で戻せます(R-RS-08 の考え)。

### 歩 3 控えから戻す

- 入られた時刻より前の控えから戻します。
- 戻した後、03 の「時系列」の中で攻撃者が作った物(アカウント、ファイル、定期の仕事)が無いことを確かめます。
- 戻せなかったデータを一覧にし、06 の報告書と 05 の報告(滅失や毀損に当たるかもしれない)に使います。ガイドラインは、ランサムウェアで暗号化され戻せなくなった場合を毀損の例に挙げ、同じデータが他に保管されていれば毀損に当たらないとしています(通則編 3-5-1-4)。

### 暗号化されたファイル

- 一部のランサムウェアには、復号の道具が公開されています(No More Ransom。警察庁の頁から辿れます。`sources.md` 10)。警察庁は、自ら開発した復号の道具も案内しています。使えるかは、ランサムノートと暗号化されたファイルの拡張子で調べます。
- 道具が使えない時も、暗号化されたファイルは、将来道具が出ることがあるので残すかを決めます(`sources.md` 14)。

## 戻した後の監視

戻した後の決まった間、入り直しが無いかを監視します。間の長さは会社が決めます。

| 見る物 | 何が出たら気づくか |
|---|---|
| 認証の記録 | 範囲の中の人の、普段と違う時刻と場所からのログイン。止めたアカウントでの試み |
| VPN、リモートデスクトップ | 03 で見つけた番地(伏せる前の値は会社の中の記録にある)からの接続 |
| 新しいアカウント、管理のグループの変更 | 4720、4728、4732、4756。Linux の useradd、usermod |
| 新しいサービス、定期の仕事 | 4697、4698、7045。systemd の新しい unit、cron |
| 外への通信 | 03 で見つけた相手への通信 |
| 記録の消去 | 1102。journal の欠け |

監視の決まりを作る仕事は、`skills/detection/` にあります。03 の時系列の表を渡して、同じ跡が出たら知らせる決まりにします。記録をコンピューターの外へ追記だけで送る仕組み(R-RS-12)が無い時は、ここで作ります(00 の「記録の置き場」)。

## 作り直した事の記録

`03-作り直した事.md` に、一つずつ追記します。値は書きません。

```
## <時刻> <作り直した物>
- した人 / 確かめた人:
- 何をしたか(値は書かない):
- 古い物が使えないことの確かめ:
- 新しい物で動くことの確かめ:
- 戻した控えの日付(戻した場合):
- 戻せなかった物:
```

## 確かめていない事

- ドメイン全体の鍵の作り直しの手順は、このガイドでは書いていません。Microsoft の文書と調査の会社で確かめる物として扱っています。
- クラウドのサービスごとの「アプリに渡した許可」の見直しの画面の場所は、書いていません。
