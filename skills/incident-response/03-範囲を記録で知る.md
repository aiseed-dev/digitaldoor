# 03 範囲を記録で知る

## この章で読むこと

何が、いつから、どこまで起きたかを、記録から知ります。範囲が分からないと、作り直す物(04)と、知らせる中身(05)が決まりません。

答える問いは三つです。

1. **何に。** どの機械、どのアカウント、どのデータに触られたか。
2. **いつから。** 最初に入られた時刻。気づいた時刻より前のことが多いです。
3. **どこまで。** 外へ出た物はあるか。他の機械へ広がったか。今も入れる道が残っているか。

記録は、01 の歩 4 で写した物を読みます。事故の起きた機械の上の元の記録は、読むだけにします。

## 時刻を揃える

記録ごとに、時刻の書き方が違います。並べる前に、全部を協定世界時(UTC)か日本時間のどちらかに揃えます。どちらに揃えたかを `02-範囲.md` の一行目に書きます。

| 記録 | 時刻の書き方の例 | 揃え方 |
|---|---|---|
| Linux の journal | `journalctl -o short-iso-precise` で時差つき | 時差を見て揃える |
| `/var/log/auth.log` など | 機械の地方時。年が無い形もある | 機械の時差と年を足す |
| Windows のイベントログ | 内部は UTC。画面と `Get-WinEvent` は地方時で出る | `TimeCreated.ToUniversalTime()` で揃える |
| クラウドの監査の記録 | 多くは UTC。書き出しの設定で変わる | 書き出した物の列の名を見る |
| VPN、防火壁、ルーター | 機器の設定の時刻。時刻が合っていない機器もある | 01 の歩 1 と同じく、機器の時刻と正しい時刻の差を測って足す |

01 の歩 1 で測った「機械の時刻と正しい時刻の差」も、ここで足します。

## 見る記録

### どこから見るか

入口から内へ向かって見ます。入口は、外から届く口(VPN、リモートデスクトップ、メール、外に見せている Web、業者の遠隔の道具)です。

| 記録 | 何が分かるか | どこにあるか |
|---|---|---|
| VPN の機器の記録 | 誰が、いつ、どこから繋いだか。失敗した試み | 機器の管理の画面、機器から記録を送っている先 |
| 防火壁、ルーターの記録 | 外との通信。大きな送り出し | 同上 |
| 認証の記録(社内の認証、クラウドのサインイン) | ログインの成功と失敗、どこから、多要素を通ったか | ドメインコントローラのイベントログ、クラウドの管理の画面の監査の記録 |
| リモートデスクトップの記録 | 誰が、どこから、どの機械へ | 各 Windows のイベントログ |
| メールの記録 | 転送の決まりの追加、外への大量の送信、受信箱への不審なアクセス | メールのサービスの管理の画面の監査の記録 |
| ファイル共有の記録 | 大量の読み出し、名前の変更、削除 | ファイルサーバーの監査、クラウドの共有の監査の記録 |
| サーバーの記録(Linux) | ssh のログイン、sudo、新しいアカウント、新しい定期の仕事 | journal、`/var/log/auth.log` |
| 業務のシステムの操作の記録 | 誰がどのデータを見たか、書き出したか | システムの管理の画面。無ければ業者に求める |
| 業者の側の記録 | 業者の遠隔の道具の接続の記録 | 業者に写しを求める(02) |

クラウドのサービスの監査の記録は、残る日数がサービスと契約で決まっています。古い分から消えていくので、早めに書き出します。何日分残るかは、使っているサービスの文書で確かめます。

### Linux

写しを読む命令です。`$D` は 01 の歩 4 の写しの置き場です。写しの journal は文字の形なので `grep` で読みます。

```
[読む] ssh のログイン(成功と失敗)
grep -E 'sshd.*(Accepted|Failed|Invalid user)' "$D/20-journal.txt"
grep -E 'sshd.*(Accepted|Failed|Invalid user)' "$D"/var-log/auth.log*   # rsyslog がある場合

[読む] sudo で何を打ったか
grep -E 'sudo:.*COMMAND=' "$D/20-journal.txt"

[読む] アカウントとグループの変更
grep -E '(useradd|usermod|userdel|groupadd|gpasswd|passwd)\[' "$D/20-journal.txt"

[読む] ログインの履歴(写した wtmp を読む)
last -F -f "$D/var-log/wtmp"
lastb -F -f "$D/var-log/btmp"      # 失敗の履歴。root で

[読む] 新しい定期の仕事、新しいサービス
grep -E '(CRON|cron).*(CMD|REPLACE|BEGIN EDIT)' "$D/20-journal.txt"
grep -E 'systemd.*(Started|Created)' "$D/20-journal.txt" | grep -v -E 'Session|user@'
```

動いている機械で、まだ写していない物を読む時の命令です(読むだけ)。

```
[読む] 機械の上で
journalctl -u ssh -u sshd --since '<2026-11-01>' -o short-iso-precise
journalctl _COMM=sudo --since '<2026-11-01>' -o short-iso-precise
sudo find / -xdev -type f -newermt '<2026-11-09 00:00>' ! -newermt '<2026-11-11 12:00>' \
     -not -path '/proc/*' -not -path '/sys/*' 2>/dev/null | head -500
                                   # その間に変わったファイル(多い時は場所を絞る)
awk -F: '$3 == 0 {print $1}' /etc/passwd          # root と同じ番号のアカウント
sudo find /home /root -name authorized_keys -exec ls -la --time-style=full-iso {} +
dpkg --verify 2>/dev/null | head -100             # パッケージの元の物と違うファイル
```

`dpkg --verify` は、設定のファイルの変更も出します。出た行を全部「攻撃」と読まず、変えた覚えのある物と分けます。

## 線を引く: 何に、いつから、どこまで

記録から分かった事を、一本の時系列に並べます。Claude は、伏せた写し(下の節)から、行を選んで並べる手伝いをします。

```
# 範囲  事故 <2026-11-11-001>  時刻は UTC に揃えた

## 時系列
| 時刻(UTC) | 機械 / アカウント | 出来事 | 出どころ(写しの名と行) | 分かった / 推測 |
|---|---|---|---|---|
| 2026-11-07 14:02 | VPN / 人-9ed46f | 外IP-3a… から VPN にログイン成功 | vpn-log.fuseta.txt:1182 | 分かった |
| 2026-11-07 14:10 | ファイルサーバー | 人-9ed46f で 4624(種類 3) | logon.csv:88 | 分かった |
| 2026-11-07 14:30 頃 | ファイルサーバー | 大量の読み出し | 時刻の近い記録が無い | 推測(根拠: 共有の監査が無い) |

## 何に
- 機械: …(分かった)/ …(推測)
- アカウント: …
- データ: どのフォルダ、どの表。個人データを含むか、何人分か(05 で使う)

## いつから
- 最初に分かっている跡: <時刻>(出どころ)
- それより前の記録が無い理由: <残っている日数を超えている、など>

## どこまで
- 外へ出た物: <分かった / 分からない。分からない理由>
- 広がった機械: …
- 残っている道: <閉じた道(02)と、まだ確かめていない道>

## まだ分からない事
- …
```

### 分かった事と推測を分ける

- **分かった事** は、記録の行がある物です。出どころの列に、写しの名と行の番号を書きます。
- **推測** は、記録の行が無く、他の事実から考えた物です。根拠の事実を括弧で書きます。
- **記録が無い** ことと **起きなかった** ことは別です。「記録していなかったので分からない」と書きます。

この区別は 05 の報告でそのまま使います。個人情報保護委員会のガイドラインは、報告の対象の「おそれ」を、その時点で分かっている事実から蓋然性を考えて判断するとしています(通則編 3-5-3-1 の注 2)。推測を「漏れていない」と書き換えないことが、後で報告をやり直さないためにも要ります。

個人データの漏えいの「おそれ」に当たりうるサイバー攻撃の例として、ガイドラインは、データが盗まれた跡、情報を盗む動きをするマルウェアへの感染、攻撃の指令の相手として知られている番地やドメインへの通信、入力の頁の改ざん、公的機関や専門家からの根拠のある連絡を挙げています(通則編 3-5-3-1 の注 4)。範囲を書く時は、この五つのどれかに当たる記録があるかを、一行ずつ書きます。

## AI に渡す前に伏せる

記録には、人の名、アカウントの名、メールのアドレス、電話、番地が入っています。Claude に渡すと、そのデータは Anthropic の側に保持されます(SKILL.md「Claude の使い方と、データの扱い」)。だから、渡す前に、機械の上で伏せます。

下のプログラムは、Python の標準ライブラリだけで、記録の写しから伏せた写しを作ります。

- 元のファイルは読むだけです。
- 同じ値は、同じ文字に置き換わります(例: `人-9ed46f`)。ファイルをまたいでも同じなので、「同じ人が、VPN とファイルサーバーの両方に出てくる」ことは、伏せた後も分かります。
- 番地は、外の番地(`外IP-…`)と内の番地(`内IP-…`)に分けて置き換えます。外か内かは分かり、どの番地かは分かりません。
- 置き換えの元の値との対応表は、鍵と同じ所に書きます。対応表と鍵は、事故の記録の置き場に置き、Claude に渡しません。
- 名前、アカウントの名、機械の名、取引先の名は、形では見分けられないので、一覧のファイルを人が作って渡します。

```
[読む] 使い方(事故の記録の置き場で)
cd /media/<外>/jiko/<2026-11-11-001>
mkdir -p himitsu && chmod 700 himitsu     # 鍵と対応表と名前の一覧の置き場
python3 fuseru.py --kagi himitsu/key --out fuseta \
    --names himitsu/names.txt --words himitsu/words.txt \
    utsushi/<機械>/20-journal.txt utsushi/logon-4624-4625.csv
```

下のプログラムを、事故の記録の置き場に `fuseru.py` として保存して使います。00 の備えの時に保存し、見本の記録で一度試しておきます。

`himitsu/names.txt` には、一行に一つ、伏せる名を書きます(社員の名、アカウントの名、機械の名)。`himitsu/words.txt` には、取引先の名、自社のドメインなどを書きます。

```python
#!/usr/bin/env python3
"""記録の写しから、名前・アドレス・番地を伏せた写しを作る(標準ライブラリだけ)。

使い方:
  python3 fuseru.py --kagi <鍵のファイル> --out <伏せた写しの置き場> \
      [--names <名前の一覧>] [--words <伏せる語の一覧>] <写し> [<写し> ...]

- 元のファイルは読むだけで、変えません。
- 同じ値は、同じ置き換えの文字になります(例: 人-3f9a1c)。ファイルをまたいでも同じです。
- 置き換えの元の値との対応表は --out の外(鍵と同じ所)に書きます。AI には渡しません。
- 鍵のファイルが無ければ作ります(権限 600)。鍵が漏れると置き換えを試して戻せるので、
  鍵と対応表は事故の記録の置き場に置き、会話に出しません。
"""
import argparse, hashlib, hmac, ipaddress, json, os, re, sys

EMAIL = re.compile(r'[A-Za-z0-9._%+\-]+@[A-Za-z0-9.\-]+\.[A-Za-z]{2,}')
IPV4 = re.compile(r'(?<![\d.])(?:\d{1,3}\.){3}\d{1,3}(?![\d.])')
IPV6 = re.compile(r'(?<![0-9A-Fa-f:])(?:[0-9A-Fa-f]{0,4}:){2,7}[0-9A-Fa-f]{0,4}(?![0-9A-Fa-f:])')
TEL = re.compile(r'(?<!\d)0\d{1,4}-?\d{1,4}-?\d{3,4}(?!\d)')
MAC = re.compile(r'(?<![0-9A-Fa-f:-])(?:[0-9A-Fa-f]{2}[:-]){5}[0-9A-Fa-f]{2}(?![0-9A-Fa-f:-])')


def load_key(path):
    if not os.path.exists(path):
        fd = os.open(path, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
        with os.fdopen(fd, 'wb') as f:
            f.write(os.urandom(32))
    with open(path, 'rb') as f:
        return f.read()


def load_list(path):
    if not path:
        return []
    with open(path, encoding='utf-8') as f:
        items = [l.strip() for l in f if l.strip() and not l.startswith('#')]
    return sorted(set(items), key=len, reverse=True)   # 長い物から置き換える


class Fuseru:
    def __init__(self, key):
        self.key = key
        self.table = {}      # 置き換えの文字 -> 元の値
        self.count = {}

    def tag(self, kind, value):
        h = hmac.new(self.key, f'{kind}:{value}'.encode(), hashlib.sha256).hexdigest()[:6]
        t = f'{kind}-{h}'
        self.table[t] = value
        self.count[kind] = self.count.get(kind, 0) + 1
        return t

    def ip(self, m):
        s = m.group(0)
        try:
            a = ipaddress.ip_address(s)
        except ValueError:
            return s                      # 版の番号など、番地でない物は残す
        if a.is_loopback:
            return s
        kind = '外IP' if a.is_global else '内IP'   # 文書用の番地も「内」に入る
        return self.tag(kind, s)

    def line(self, text, names, words):
        # 形で分かる物を先に、一覧の語を後に置き換える(メールの中の名前を壊さないため)
        text = EMAIL.sub(lambda m: self.tag('メール', m.group(0)), text)
        text = MAC.sub(lambda m: self.tag('MAC', m.group(0)), text)
        text = IPV4.sub(self.ip, text)
        text = IPV6.sub(self.ip, text)
        text = TEL.sub(lambda m: self.tag('電話', m.group(0)), text)
        for n in names:
            if n in text:
                text = text.replace(n, self.tag('人', n))
        for w in words:
            if w in text:
                text = text.replace(w, self.tag('語', w))
        return text


def main():
    p = argparse.ArgumentParser(description=__doc__, formatter_class=argparse.RawDescriptionHelpFormatter)
    p.add_argument('--kagi', required=True, help='鍵のファイル(無ければ作る)')
    p.add_argument('--out', required=True, help='伏せた写しを置く所')
    p.add_argument('--names', help='伏せる名前の一覧(一行に一つ。人の名、アカウント名、機械の名)')
    p.add_argument('--words', help='ほかに伏せる語の一覧(取引先の名、ドメインなど)')
    p.add_argument('files', nargs='+')
    a = p.parse_args()

    f = Fuseru(load_key(a.kagi))
    names, words = load_list(a.names), load_list(a.words)
    os.makedirs(a.out, exist_ok=True)
    for src in a.files:
        dst = os.path.join(a.out, os.path.basename(src) + '.fuseta.txt')
        if os.path.abspath(dst) == os.path.abspath(src):
            sys.exit('元のファイルに書こうとしています。--out を変えてください')
        with open(src, encoding='utf-8', errors='replace') as r, \
             open(dst, 'w', encoding='utf-8') as w:
            for l in r:
                w.write(f.line(l, names, words))
        print(f'{src} -> {dst}')

    table = os.path.join(os.path.dirname(os.path.abspath(a.kagi)), 'fuseta-taiou.json')
    old = {}
    if os.path.exists(table):
        with open(table, encoding='utf-8') as t:
            old = json.load(t)
    old.update(f.table)
    fd = os.open(table, os.O_WRONLY | os.O_CREAT | os.O_TRUNC, 0o600)
    with os.fdopen(fd, 'w', encoding='utf-8') as t:
        json.dump(old, t, ensure_ascii=False, indent=1)
    print('置き換えた数:', json.dumps(f.count, ensure_ascii=False))
    print('対応表:', table, '(AI に渡さない)')


if __name__ == '__main__':
    main()
```

伏せた後に、人が確かめる事:

- 伏せた写しを `grep` で開き、一覧に入れ忘れた名前が残っていないかを目で見ます。
- 四つの数の組(例: 版の番号 `1.2.3.4`)も番地として置き換わります。読み違えないよう、Claude に伝えます。
- 形で見分けられない物(住所、生年月日、口座の番号、記録の中の自由な文)は、このプログラムでは伏せません。そういう物を含む記録は、要る列だけを取り出してから伏せるか、渡さずに人が読みます。
- 何を、いつ、どの形で Claude に渡したかを、`02-範囲.md` の末尾に一行ずつ書きます。

Claude から返ってきた答えの中の `人-9ed46f` などは、人が対応表を引いて元の名に戻し、会社の中の記録に書きます。戻した名は、Claude に送り返しません。

## 範囲が分かったら

- 04 で作り直す物の一覧を、「何に」の欄から作ります。
- 05 で知らせる中身を、「何に」の「データ」と「どこまで」から作ります。
- 同じ穴が他の所に無いかは、`skills/system-check/` で、自社のコードと設定を確かめます。
- 見張りの決まり(同じ跡が出たら気づく)は、`skills/detection/` に、時系列の表を渡して作ります。

## 確かめていない事
