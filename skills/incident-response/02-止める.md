# 02 止める

## この章で読むこと

入られた道と、漏れた値を、使えなくします。止めるのは、アカウント、鍵、トークン、外部からのアクセス経路、業者の遠隔の道具です。止める手は全部、コンピューターやアカウントを変える手なので、Claude は文を出し、人が読んでから打ちます。

止める前に、01 の歩 4 のコピーがあることを確かめます。止めると、記録に残らない物(ログインしていた状態、動いていたプログラム)が消えます。

## 止める順

1. **今、使われている道。** 攻撃者が今いる道(ログイン中のアカウント、開いている遠隔の接続)。
2. **管理者の権限を持つ物。** 管理者のアカウント、サーバーの鍵、クラウドの管理の権限。
3. **漏れた値。** 漏れたパスワード、鍵、トークン。
4. **入られた人の全経路。** その人に結びついた全部(下の「一人の全経路」)。
5. **業者のリモートアクセス経路。** 使われた形跡が無くても、範囲が分かるまで閉じるかを決めます。

順は目安です。止める権限を持つ人が、03 で分かってきた事に合わせて変えます。

## 止めると仕事が止まる物

止めると仕事が止まる物は、止める前に、止める権限を持つ人(00)に「何が止まるか」を伝えて決めてもらいます。Claude は、止める物ごとに次の表を一行書いて示します。

| 止める物 | 止めると止まる仕事 | 代わりの手段 | 止めない場合に残る危うさ | 決めた人と時刻 |
|---|---|---|---|---|
| | | | | |

例えば、VPN を閉じると外からの仕事が止まります。閉じない場合、入られた道が開いたままです。どちらを選ぶかは会社が決めます。決めた事と理由は、そのまま 06 の報告書に入ります。

## 一人の全経路(R-AC-15)

一人のアカウントが乗っ取られた、退職した人のアカウントが使われていた、という時は、その人に結びついた全部の経路を一度に止めます。一つだけ止めると、残った道から入り直されます。

00 の「鍵とアカウントの一覧」の、その人の行を開き、全部の列を順に止めます。一覧が無い時は、次の表を Claude と一緒に作りながら止めます。

| 経路 | 止める手 | 止めた時刻 | 止めた人 | 止まったことの確かめ |
|---|---|---|---|---|
| 社内の認証(ドメイン、ディレクトリ) | アカウントを無効にする | | | ログインを試して断られる |
| メール | アカウントを止め、サインインのセッションを取り消す | | | |
| クラウドの仕事の仕組み | 同上。アプリに渡した許可(OAuth の同意)も取り消す | | | |
| 業務のシステム | アカウントを止める | | | |
| VPN | アカウントを止め、今の接続を切る | | | |
| リモートデスクトップ、遠隔の道具 | アカウントを止め、今の接続を切る | | | |
| サーバーの ssh | 公開鍵を外す、アカウントを止める | | | |
| API の鍵、トークン | 取り消す | | | |
| 多要素認証の登録 | 登録した端末を外す | | | |
| 会社の端末 | 遠隔で止める、回収する | | | |
| 扉の鍵(スマートフォン、カード、暗証番号) | 失効する | | | 扉で試して開かない |
| 機械の鍵、物の鍵 | 回収し、回収の記録を残す | | | |

**パスワードを変えるだけでは足りません。** パスワードを変えても、すでに発行されたログインの状態(セッション)とトークンが残ることがあります。アカウントを止め、セッションを取り消し、トークンを取り消します。クラウドの管理の画面にある「サインインのセッションを取り消す」に当たる機能の名と場所は、使っているサービスの管理の文書で確かめ、00 の手順書に書いておきます。

### Linux のアカウント

```
[読む] その人のアカウント、ログイン中か、鍵
getent passwd <人>
who | grep <人>; loginctl list-sessions
sudo cat /home/<人>/.ssh/authorized_keys     # 公開鍵の一覧。秘密鍵ではない
sudo -l -U <人>                               # sudo の権限

[変える] 人(読んで確かめてから)
sudo usermod -L <人>             # パスワードでのログインを止める(取り消せる: usermod -U)
sudo usermod -e 1 <人>           # アカウントの期限を過去にする。鍵でのログインも止まる
                                  # (取り消せる: usermod -e '' <人>)
sudo mv /home/<人>/.ssh/authorized_keys /root/jiko-<人>-authorized_keys
                                  # 公開鍵を外す。消さずに移す(証拠)
sudo loginctl terminate-user <人> # 今のログインを切る。動いていたプログラムも止まる
```

`terminate-user` は、その人の動いているプログラムを止めます。01 のコピーを取ってから打ちます。

### Windows のアカウント

```
[読む]
Get-LocalUser <人> | Format-List *
quser
# ドメインの場合(Active Directory の道具が入ったコンピューターで)
Get-ADUser <人> -Properties Enabled,LastLogonDate,MemberOf,PasswordLastSet

[変える] 人(読んで確かめてから)
Disable-LocalUser -Name <人>          # 取り消せる: Enable-LocalUser
logoff <セッション番号>                # quser で見た番号。今の接続を切る
# ドメインの場合
Disable-ADAccount -Identity <人>      # 取り消せる: Enable-ADAccount
```

ドメインの管理者のアカウントが乗っ取られた疑いがある時は、ドメイン全体の鍵(Kerberos のチケットを署名するアカウントなど)の作り直しが要ることがあります。手順は特別で、間違えると全員がログインできなくなります。Microsoft の文書を読み、調査の会社と相談して、04 で行います。

## 漏れた値

パスワード、鍵、トークンが漏れた(公開のリポジトリに上げた、チャットに貼った、メールで送った、画面を共有した)時です。

1. **値を探しに行かない。** 漏れた先(公開のページ、リポジトリ)を開いて値をコピーすることはしません。どこに、いつから、誰が見られる形で出ていたかを書きます。
2. **取り消す。** 値を出した仕組みの管理の画面で、その値を取り消します。消すと出し直しが要る物は、04 の順で出し直します。
3. **使われたかを見る。** 03 で、その値で入った記録を見ます。
4. **出ていた場所から下ろす。** 公開のリポジトリの場合、ファイルを消しても履歴に残ります。取り消しが先です。下ろすのは取り消しの後です。

値が Claude との会話に貼られた時: Claude は値を使わず、写さず、「この値を取り消して作り直します」と言い、2 の手を出します。会話の記録にも値が残るので、取り消しは必ず行います。

| 漏れた物 | 取り消す所 | 作り直す時の注意(04) |
|---|---|---|
| 人のパスワード | 認証の仕組み | 同じパスワードを他で使っていたら、そちらも |
| 管理者のパスワード | 認証の仕組み、機器の管理の画面 | 同じ値を使っていた機器を全部 |
| ssh の秘密鍵 | 入れていた全部のコンピューターの `authorized_keys` から公開鍵を外す | 鍵の対を作り直す |
| API の鍵、トークン | 出したサービスの管理の画面 | 使っていたプログラムの設定を直す |
| 証明書の秘密鍵 | 証明書を出した所で失効する | 鍵と証明書を作り直す |
| 無線 LAN のパスワード | 無線の機器 | 全部のコンピューターの設定を直す |
| 控えの暗号のパスワード | 控えの仕組み | 新しいパスワードで控えを取り直す。古い控えの扱いを決める |

## 外部からのアクセス経路

外部から社内に入れるアクセス経路(VPN、リモートデスクトップ、外に見せているサーバーの管理の画面)です。警察庁のまとめでは、ランサムウェアの侵入の道の 8 割以上が VPN やリモートデスクトップ用の機器でした(令和 7 年上半期、`sources.md` 11)。

```
[読む] Linux(サーバー自身のポート)
sudo ss -tlnp                   # 待ち受けているポートと、プログラム
sudo ufw status verbose          # ufw を使っている場合
sudo nft list ruleset            # nftables を使っている場合

[読む] Windows
Get-NetTCPConnection -State Listen |
  Select-Object LocalAddress,LocalPort,OwningProcess
Get-NetFirewallRule -Enabled True -Direction Inbound |
  Select-Object DisplayName,Action,Profile
(Get-ItemProperty 'HKLM:\System\CurrentControlSet\Control\Terminal Server').fDenyTSConnections
                                  # 0 ならリモートデスクトップを受けている
```

VPN の機器、ルーター、防火壁は、その機器の管理の画面で見ます。管理の画面の「今の接続」「アカウント」「設定の変更の履歴」を写真に撮るか、画面の書き出しの機能でコピーします。

```
[変える] 人(読んで確かめてから)
# Windows のリモートデスクトップを止める
Set-ItemProperty 'HKLM:\System\CurrentControlSet\Control\Terminal Server' -Name fDenyTSConnections -Value 1
# 取り消す: -Value 0
```

VPN の機器のアクセス経路を閉じる手は機種ごとに違います。機種の文書を読み、業者(00 の表)に確かめてから行います。機器の管理の画面に入るパスワードも漏れた疑いがある時は、管理の画面に入る時に新しい値に替えます(04)。

## 業者のリモートアクセス経路

業者の遠隔の保守の道具、業者用の VPN のアカウント、業者に渡したクラウドの管理の権限です。00 の「業者のリモートアクセス経路」の表の行を順に閉じます。

- 道具の常駐のサービスを止めるか、道具の側の管理の画面で自社のコンピューターを外します。どちらが出来るかは、道具と契約で違います。
- 業者に電話で知らせ、業者の側でも、その道具のアカウントが使われていないか、業者の側の記録を見てもらいます。業者の記録のコピーを求めます(03)。
- 業者の道から入られた形跡がある時は、業者が自分で直す前に、業者の側の記録を残すよう頼みます。

```
[読む] Windows: 遠隔の道具のサービスが動いているか
Get-Service | Where-Object { $_.DisplayName -match '<道具の名>' }
Get-CimInstance Win32_Service | Where-Object { $_.PathName -match '<道具の名>' } |
  Select-Object Name,State,StartMode,PathName

[変える] 人(読んで確かめてから)
Stop-Service -Name <サービスの名>
Set-Service -Name <サービスの名> -StartupType Disabled   # 取り消す: -StartupType Automatic
```

## 端末の紛失

PC、スマートフォン、USB の記憶装置をなくした時です。

1. **いつ、どこで、最後に見たか**を本人から聞き、01 の様式で書きます。
2. **端末の中身を書きます。** ディスクの暗号化をしていたか、画面のロックがあったか、中にどんな個人データがあったか。これで 05 の報告の要否が変わります(「高度な暗号化その他の個人の権利利益を保護するために必要な措置」を講じた物は、報告の対象から外れる形があります。ガイドライン通則編 3-5-3-1)。暗号化していたかは、推測でなく、端末の管理の記録で確かめます。
3. **止めます。** その端末に入っていたログインの状態、メールの同期、多要素の登録、扉の鍵を、本人の全経路の表で止めます。端末の管理の仕組みで遠隔で止める・消す機能があれば、使うかを止める権限を持つ人が決めます(消すと、戻ってきた時に調べられません)。
4. **警察に遺失の届けをします。** 盗まれた疑いがある時は、被害の届けです。どちらかは、本人と警察署で相談します。
5. **出てきた時。** 出てきた端末は、すぐにネットワークに繋がず、誰かが触った形跡が無いかを見てから扱います。

## 止めた事の記録

止めた物は、一つずつ記録の `01-止めた事.md` に追記します。後で戻す時と、06 の報告書に使います。

```
## <時刻> <止めた物>
- 止めた人 / 決めた人:
- 打った命令、画面での操作(値は書かない):
- 取り消すには:
- 止まったことの確かめ(試した事と結果):
- 止めて止まった仕事:
```

止めた後は、本当に止まったかを試します。止めたアカウントでログインを試して断られること、閉じたアクセス経路に外から繋いで繋がらないこと、扉で失効した鍵をかざして開かないこと。試していない物は「試していない」と書きます。

## 確かめていない事

- クラウドのサービスごとのセッションの取り消しの画面の名と場所は、サービスごとに違うので書いていません。00 の手順書に、自社が使うサービスの物を書きます。
- `usermod -e 1` で鍵のログインも止まることは、一般の資料と照らしましたが、すべての ssh の設定(PAM を使わない設定など)で通しては確かめていません。止めた後に、必ずログインを試します。
