# 00 起きる前に決めておく事

## この章で読むこと

事故の最中に決めることを減らすために、先に決めて紙にしておく物です。決める事は、会社の大きさ、仕事の中身、使っている仕組みで変わります。この章は、**誰が決めるか**と**何を書いておくか**を並べます。値(何時間以内、誰が担当)は会社が決めます。

この章の表は、要求仕様の R-AC-16(出来事ごとの手順)、R-RS-03 と R-RS-04(鍵と業者の権限の目録)、R-RS-09(切り離して戻す人と、ネットワークが止まっても使える連絡の手段)、R-RS-12(記録をコンピューターの外へ)を、会社のシステムに当てはめた物です。

## 進め方

歩 1 から順に、一つずつ埋めます。一度に全部を埋めなくてかまいません。歩 1 と歩 2 だけでも、事故の夜の動きが変わります。

```
歩 1 連絡先の表          (この章の「連絡先の表」)
歩 2 止める権限を持つ人   (「止める権限」)
歩 3 記録の置き場         (「記録の置き場」)
歩 4 鍵とアカウントの一覧 (「鍵とアカウントの一覧」)
歩 5 業者のリモートアクセス経路の一覧 (「業者のリモートアクセス経路」)
歩 6 控えと復元の訓練     (「控え」)
歩 7 紙に刷る             (「紙に刷る物」)
歩 8 年に一度の訓練       (08)
```

Claude は、聞き取りをして表を埋める手伝いをします。値(電話の番号、アカウントの名)は会社の中の表に書き、公開の場所と、このガイドのコピーには書きません。

## 止める権限

事故の夜に「止めてよいか」を聞く相手が居ないと、止める手が遅れます。

**誰が決めるか:** 経営者が、止める権限を持つ人と、その代わりの順を決め、文書にします。

| 止める物 | 止めてよい人 | その人が居ない時の代わり(順) | 止めると止まる仕事 | 止める前に知らせる相手 |
|---|---|---|---|---|
| 一人のアカウント(全経路) | | | その人の仕事 | |
| 管理者のアカウント | | | | |
| VPN、リモートデスクトップの外部からのアクセス経路 | | | 外からの仕事全部 | |
| 業者のリモートアクセス経路 | | | 業者の保守 | 業者 |
| メール | | | | |
| 業務のシステム | | | | |
| ネットワーク全体(回線を抜く) | | | 全部 | |

決めておく事:

- **連絡が取れない時は、止める側に倒すか。** 「止める権限を持つ人に、決めた時間の中で連絡が取れなければ、係が止めてよい」と書くかどうかを、経営者が決めます。時間の長さも経営者が決めます。
- **止めた事を、誰に、いつ知らせるか。** 止めた後に、止める権限を持つ人へ知らせる順。
- **止めてはいけない物があるか。** 人の命や安全に関わる物(扉、火災報知の連動、医療の機器)は、止める手順を別に決めます。扉は、ネットワークから切り離しても安全側の挙動(火災と停電の設定、内側からの機械の解錠)を保つ作りであることを、受入れの時に確かめておきます(R-RS-07)。

## 記録の置き場

事故の記録は、事故の起きたコンピューターと、事故で使えなくなるかもしれない仕組み(社内のファイル共有、メール、クラウドの文書)の外に置きます。ランサムウェアの攻撃者は、ログと控えを消すことがあります(警察庁 令和 7 年上半期の情勢、`sources.md` 11)。

**誰が決めるか:** 係が案を出し、経営者が決めます。

| 書く事 | 例 |
|---|---|
| 記録を書く物 | ネットワークに繋がない PC 一台、または紙の帳面。事故用にして普段は使わない |
| コピーを入れる物 | 書き込みのできる外付けの記憶装置を二つ。事故の時まで封を切らないか、空にして置く |
| 置き場所 | 鍵のかかる所。誰が鍵を持つか |
| 普段の記録を外へ送る先 | 認証、VPN、防火壁、サーバーの記録を、別のコンピューターへ追記だけで送る(R-RS-12)。送り先のコンピューターの名と、何日分を残すか(残す日数は会社が決める) |
| 時刻 | 全部のコンピューターが同じ時刻の源に合わせているか。源の名 |

普段の記録を外へ送っていないと、03 で範囲が分かりません。この表を埋める時に、「今、何の記録が、どこに、何日分残っているか」を一度見ます。見方は 03 の「見る記録」と同じです。足りない物は、`skills/detection/` に渡して、送る仕組みを作ります。

## 鍵とアカウントの一覧

誰が、何の鍵と権限を持っているかの一覧です。事故の時に「一人の全経路」(02)を止めるのにも、「出し直す順」(04)を決めるのにも、この一覧を使います。値は書きません。

**誰が決めるか:** 係が作り、総務・人事と突き合わせます。人の出入り(入社、退職、異動、業者の交代)の届けがあった日に直します。

### 人ごとの表

| 人 | 立場(社員、派遣、業者) | アカウント(社内の認証、メール、クラウド、業務のシステム) | 管理者の権限 | 多要素認証の手段 | 端末(会社の PC、スマートフォン) | リモートアクセス経路(VPN、リモートデスクトップ) | 物の鍵とカード(扉、金庫) | 止める手順の行 |
|---|---|---|---|---|---|---|---|---|
| | | | | | | | | |

一人の行には、その人に結びついた全部の経路を書きます。扉の鍵(スマートフォンの鍵、カード、暗証番号)も同じ行です(R-AC-15)。退職した人の行は消さず、「止めた日」と「確かめた日」を書いて残します。

## 業者のリモートアクセス経路

業者が社内のコンピューターに遠隔で入れる道(遠隔の保守の道具、VPN のアカウント、クラウドの管理の権限)の一覧です。業者が破られると、その業者が持つ道から入られます(解説「業者に預けた鍵と権限」)。

**誰が決めるか:** 係が作り、契約の担当と突き合わせます。

| 業者 | 入る道(道具の名、VPN、クラウドの権限) | 入れるコンピューター | 常に開いているか、その時だけ開けるか | 誰が開けるか | 記録が自社に残るか | 止め方(02 の行) |
|---|---|---|---|---|---|---|
| | | | | | | |

常に開いている道は、「その時だけ開ける」形に変えられるかを業者と話します。要求仕様の R-AC-10 は、扉について、業者と連携先に扉を開ける常の権限を持たせず、遠隔の操作は一回ごとの一時の許しで行う形を求めています。会社のシステムの業者の道も、同じ考えで見直せます。変える・変えないは、契約の担当と経営者が決めます。

## 控え

控えは、取れていることではなく、戻せることで確かめます。

**誰が決めるか:** 係が、何を、どこへ、どの間隔で控えるかの案を出し、経営者が決めます。

| 書く事 | 中身 |
|---|---|
| 控える物 | 業務のシステムのデータ、ファイル共有、メール、設定(ルーター、防火壁、サーバー) |
| 控えの先 | 少なくとも一つは、ネットワークから切り離した所(外した記憶装置、書き換えられない保管) |
| 控えを消せる人 | 普段の管理者のアカウントで消せないか。消せるなら、攻撃者も消せる |
| 控えのパスワード | 人に結びつかない鍵の表の一行 |
| 戻す訓練 | 年に何回、どの範囲を、別のコンピューターに戻すか。戻すのにかかった時間を記録する |

警察庁は、ランサムウェアでバックアップも暗号化される事例が多いことを挙げ、こまめに取り、ネットワークから切り離して保管することを勧めています(`sources.md` 10)。

戻す訓練の記録の様式:

```
控えの戻しの訓練 <日付>
- 戻した物:
- 控えの日付:
- 戻した先(本番と別のコンピューター):
- かかった時間:
- 戻らなかった物と理由:
- 次に直す事:
- した人 / 確かめた人:
```

## 紙に刷る物

ネットワークと社内の仕組みが止まった時に、手元に要る物です。刷った日を一枚目に書き、鍵のかかる所に置きます。

- このガイドの SKILL.md、01、02(最初の一時間と止める手)。
- 連絡先の表。
- 止める権限の表。
- 05 の「最初の日に見る表」。
- 01 の「時刻と見た事の様式」を何枚か。
- 鍵とアカウントの一覧は、値を含まないので刷ってかまいません。ただし、人の名と役の表なので、置き場所に鍵をかけます。

刷った物は、表を直した時に刷り直し、古い物は細断します。

## 出来事ごとの手順(R-AC-16)

R-AC-16 は、出来事ごとに、何を失効し、何を作り直し、誰が確かめるかの手順を持つことを求めています。会社のシステムでの出来事と、このガイドの章の対応です。手順書は、この表の行ごとに、会社の名と人の名を入れて一枚にします。

| 出来事 | 失効する物 | 作り直す物 | 確かめる人 | このガイド |
|---|---|---|---|---|
| 端末の紛失 | その端末の中の鍵、ログインの状態、端末の登録 | その人の多要素の登録、端末に入っていたトークン | | 02、04、05 |
| 退職と退去 | その人の全経路 | 共有していたパスワード | | 02 |
| 管理者の交代 | 前の管理者の権限 | 管理者の非常用のアカウント、前の管理者が知っていたパスワード | | 02、04 |
| 業者の交代 | 前の業者のリモートアクセス経路 | 前の業者が知っていたパスワードと鍵 | | 02、04 |
| 鍵、パスワード、トークンの漏れ | 漏れた値 | 漏れた値と、それで守っていた物 | | 02、04 |
| 不正なアクセス、ランサムウェア | 入られた経路と、入られたコンピューターの上の鍵 | 範囲(03)の中の全部 | | 01〜06 |

## 確かめていない事

- 連絡先の表と止める権限の表の形は、まだ実際の会社で使っていません。
- 業者のリモートアクセス経路の一覧を、自動で作る道具は、このガイドにはありません。`kagi/` のサーバーのポートの突き合わせが使えるかは、`skills/kagi/` を読んで確かめます。
