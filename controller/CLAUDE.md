# controller/(digitaldoor-controller)— 作業の約束

リポジトリ全体の約束(最上位の CLAUDE.md)に加えて、ここでは次を守る。

- 仕様は同じリポジトリの `docs/扉コントローラ仕様書.md` と `docs/要求仕様/` が正。実装を変えるときは、仕様書を先に直す。設計の判断も仕様書に書く
- テストは最上位で `.venv/bin/python -m pytest -q controller`。commit は全テストが通ってから、別のコマンドで行う。commit は本人の合図で行い、push は本人が行う
- テストは、確かめる要求の番号(R-XX-nn)を docstring の先頭の行に書く。期待値は仕様から決め、実装を見て決めない。実装とテストは別のセッションで作る。わざと壊して落ちることを確かめる
- 判断は扉が持つ。外へ出す口(伝票、通知)の不調で判断を止めない。記録は追記だけ
- 署名の口(Signer)は後でセキュアエレメントに差し替える。秘密鍵はリポジトリに入れない
- 依存は標準ライブラリと cryptography だけに保つ
- 公開する物なので、文書に書く固有名は製品名と会社名にとどめる。提案先の会社の名前は、文書にもコミットメッセージにも書かない
- ライセンスは Apache-2.0(`controller/LICENSE`)。リポジトリのほかのコード(AGPL)を写して入れない
