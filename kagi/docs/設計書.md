# kagi — 設計書

この設計書は、seed のリポジトリ(https://github.com/aiseed-dev/seed )の `docs/kagi 設計書.md`(2026-11-06 初版)を、2026-11-11 に digitaldoor へコピーした物です。中身は保ち、経緯の発言の引用は「選んでいる物」として短く直し、例のサーバーの名と人の名は架空の物(`web1`、`db1`、`suzuki`)に替えました。

kagi は扉の鍵(digitalkey)ではなく、サーバーと業務システムの秘密の在庫・ポート・記録を見る道具です。

決まりの番号(K-01〜15)は、seed のリポジトリの `docs/鍵の管理の仕組み.md` §2 にあります。計画書(`docs/kagi 計画書.md`)と配線図(`docs/kagi 配線図.md`)も seed のリポジトリにあります。使い方の手順は `skills/kagi/` です。

## 1. 形

- Python 3.11 以上、標準ライブラリだけ(`tomllib`、`hashlib`、`hmac`、`json`、`argparse`、`pathlib`、`re`、`datetime`)。外の package を入れない。机の画面(`kagi app`)だけが任意で `flet` を使う。
- パッケージ `kagi/kagi/`(配布の名 `digitaldoor-kagi`、import の名 `kagi`)。CLI は `kagi`(`kagi/pyproject.toml` の `[project.scripts]`)。digitaldoor のほかのパッケージ(`digitalkey`、`digitaldoor_controller`)を import しない。
- 作業の場所は `--dir DIR`(既定は `./kagi-data`)。中に `inventory.toml`、`ports.toml`、`machines.toml`(§3.4)、`audit.log` を置く。全部素の文字。
- 鍵の値は読まない、持たない、出さない。例外は署名の鍵で、それは読むが出さない。

## 2. ファイルの形

### 2.1 `inventory.toml`(在庫表。K-14、K-04、K-05)

```toml
[[secret]]
id = "web1-app-env"           # 一意の名
kind = "token"                # password | token | key | cert | passphrase | other
where = "web1:/etc/app/env"   # 置き場。サーバー:パス か 紙/金庫 の名。値ではない
holder = "suzuki"             # 持つ人
role = "業務のサーバーが外の API を呼ぶ"   # 一つの役(K-01)
made = 2026-11-04             # 作った日
expires = 2027-05-04          # 期限(無い物は書かない → 抜けとして報告)
rotate_days = 180             # 回す周期
lost = "token を失効し、新しい token を発行して env を書き直す"   # なくした時
leaked = "失効 → 記録で範囲 → 作り直し → 知らせる"              # 漏れた時
```

必須の欄: `id`, `kind`, `where`, `holder`, `role`。`expires` と `rotate_days` と `lost` と `leaked` は無ければ「抜け」として報告する。`value` という欄があったら読まずに拒む(K-13。報告して終了コード 2)。

### 2.2 `ports.toml`(ポートの表。K-07)

```toml
[[port]]
host = "db1"
port = 8080
proto = "tcp"
service = "業務のサーバー"
bind = "127.0.0.1"            # どこに向くか。0.0.0.0 や :: は外向き
reason = "nginx の後ろ"
```

### 2.3 `audit.log`(記録。K-06)

JSON Lines。一行一件、追記だけ。

```json
{"seq": 1, "ts": "2026-11-06T09:00:00+09:00", "actor": "suzuki", "action": "inventory.add", "detail": "web1-app-env", "prev": "0000…", "hash": "…", "sig": "…"}
```

- `prev` は前の行の `hash`。最初の行は 64 個の `0`。
- `hash` = SHA-256 of `seq|ts|actor|action|detail|prev` を UTF-8 で。
- `sig` = HMAC-SHA256(鍵, hash) の hex。鍵は §4。
- `verify` は、連番が 1 から飛びなく続く事、`prev` が前の `hash` と一致する事、`hash` が計算と一致する事、`sig` が鍵と一致する事、の四つを全行で見る。一つでも落ちたら、落ちた行の `seq` と理由を出し、終了コード 1。

## 3. 命令

| 命令 | 入力 | 出力 | 終了コード |
|---|---|---|---|
| `kagi init` | `--dir` | 三つのファイルの雛形を作る(在庫表とポートの表は例を一件ずつコメント付きで。記録は空) | 0 |
| `kagi check inventory` | `inventory.toml`、`--days N`(既定 30) | 期限切れ、N 日以内に切れる物、欄の抜け、を表で | 抜けか期限切れがあれば 1、無ければ 0 |
| `kagi check ports --ss FILE` | `ports.toml` と `ss -ltnp` の出力のファイル(`--host NAME` で表のどのサーバーか) | 表に無いポート(host, port, bind, process の名)、表にあって開いていないポート、外向き(0.0.0.0, ::, *)で表の `bind` と違うポート | 差があれば 1 |
| `kagi scan PATH...` | ファイルかディレクトリ | `path:line  kind` の行だけ。値は出さない。`.git/`、バイナリ(NUL を含む)、1 MB 超は飛ばす。`--exclude GLOB` 可 | 見つかれば 1 |
| `kagi log add --actor A --action X --detail D` | 署名の鍵(§4) | 一行追記。追記した `seq` を出す | 0。鍵が無ければ 2 |
| `kagi log verify` | 署名の鍵 | `ok N lines` か、落ちた行と理由 | 0 / 1 |
| `kagi report` | 上の全部 | Markdown 一枚(在庫の数と期限、ポートの差、走査の数、記録の検証の結果)。標準出力 | 0 |

`ss -ltnp` の行の読み方: `LISTEN 0 128 127.0.0.1:8080 0.0.0.0:* users:(("python3",pid=…,fd=…))` から `bind`=`127.0.0.1`、`port`=8080、`process`=`python3`。IPv6 の `[::]:22` と `*:22` も読む。

走査の型(最初は少なく。偽陽性が多いと人が読まなくなるため): PEM の頭(`-----BEGIN … PRIVATE KEY-----`)、`AKIA[0-9A-Z]{16}`、`ghp_[A-Za-z0-9]{36}`、`sk-[A-Za-z0-9_-]{20,}`、`xox[bp]-`、行頭からの `(password|passwd|secret|token|api_key)\s*[=:]\s*\S{8,}`(`.example` と `example` を含むパスは除く)。報告は種類の名(`pem-private-key`、`aws-access-key`、`github-token`、`openai-key`、`slack-token`、`assignment`)だけ。一致した文字列そのものは標準出力にもログにも出さない。

### 3.1 実装で選んでいる細部

- ポートの外向き: 表の `bind` が `0.0.0.0`・`::`・`*` のどれかなら、`ss` 側がその三つのどれでも表の通りとする。表の `bind` が外向きでない時だけ「外向きで表と違うポート」と出す。
- `--host` が無い時は表の全部のサーバーを一台とみなす。表にサーバーが二つ以上あれば `--host` が要る。
- `report` は `--ss FILE --host NAME --scan PATH... --exclude GLOB` を付けた時だけポートと走査を見る。付けなければ「突き合わせていない」「走らせていない」と書く。鍵が無ければ記録は「検証していない」。終了コードは 0。
- `--dir` は命令の前でも後でもよい。`scan` は作業の場所を使わない。
- `init` の雛形の例は全部コメント。既にあるファイルは触らない。
- 在庫表の `id` の重複と、`kind` が六つ以外の物は「形の誤り」で終了コード 1。期限が近いだけなら 0。
- 走査: PEM の頭は `-----BEGIN [A-Z0-9 ]*PRIVATE KEY-----`。`assignment` は大文字小文字を区別せず、行頭の空白を許す。パスに `example` を含む所を外すのは `assignment` だけ。一行に何種類も当たれば種類ごとに一行。1 MB は 1,048,576 バイト。シンボリックリンクは辿らない。数は標準エラー、標準出力は `path:line  kind` だけ。
- 記録: 鍵のファイルが空なら「鍵が無い」と同じ(終了コード 2)。`log add` は最後の行が読めなければ足さず 1。`verify` は落ちた行を全部出す。追記は `flock` を掛けてから。
- テストのファイル名は `kagi/tests/test_kagi_*.py`。

### 3.2 `kagi check smb --conf smb.conf`(Samba のファイル共有を持つ会社のため)

`smb.conf` を読み、待ち受けと認証の形を表で出す。値は出さない(パスワードの類は smb.conf に無いはずだが、`password` を含む行は内容を出さず「ある」とだけ)。見る物と決まり:

| 見る物 | 良い形 | 出す |
|---|---|---|
| `server min protocol` | SMB2 以上 | 無ければ「SMB1 が通る」 |
| `server signing` | `mandatory` | 違えば「署名が任意」 |
| `map to guest` / `guest ok` / `public` | `Never`、`no` | 共有ごとに「ゲストが入れる」 |
| `interfaces` と `bind interfaces only` | LAN の名かネットワークだけ、`yes` | 無ければ「全部のインターフェースで待ち受ける」 |
| 共有の `valid users` / `write list` | グループ(`@group`)で | 個人名だけなら「個人で付けている」 |
| `[global]` の `server role` | standalone か active directory domain controller | そのまま出す |
| `smb passwd file`、`passdb backend` | 場所だけ | 場所だけ出す(値は無い) |

終了コードは、直す物があれば 1。`report` のポートの節に、`--smb FILE` があれば足す。テスト: 見本の smb.conf(良い物と悪い物)で表と終了コード。

実装で選んでいる細部: 署名は `mandatory` と `required` を良い形とする。`map to guest` の値は出さない(`Bad Password` が「password を含む行は出さない」とぶつかるため)。interfaces は番地を出さず数だけ。個人名は出さない。`password` を含む行は「見るだけ」(行番号と「ある」)で終了コードに数えない。`passdb backend` の `user@` は伏せる。`server min protocol` が無い時は「SMB1 が通る」と出すが、Samba 4.11 以降の既定は SMB2 なので実際は通らない事が多い(書いて確かめるのが良い形)。AD DC では署名の既定が必須なので、`server signing` を書いていない AD DC で「署名が任意」と出るのは外れ(書いておくのが良い形)。`ipaddress` を使う(標準ライブラリ)。

### 3.3 `kagi app` — 係の机の画面(Flet の PC 版)

手元の Flet の PC 版で、係の PC の窓に一画面を出す。手元の窓なので、サーバーの管理にも使える。ネットワークに出さない(Web 版は作らない。K-07)。kagi の本体は標準ライブラリだけのままで、画面は任意の依存(`pip install -e 'kagi[app]'`。`kagi/kagi/app.py` は `flet` を遅く import し、無ければ一行で言う)。

画面は一つ(`--dir` の作業の場所を上に出す)。四つの札と一つの釦。

| 札 | 中身 | 元 |
|---|---|---|
| 在庫 | 件数、期限切れ、30 日以内、抜け。表(id、何、中身)。値は無い | `inventory.check` |
| ポート | `ss` のコピーのファイルを選ぶ釦 → 差の表(表に無いポート、開いていないポート、外向き)。無ければ「突き合わせていない」 | `ports` |
| 走査 | 場所を選ぶ釦 → `path:line  kind` の一覧。値は出ない | `scan` |
| 記録 | `verify` の結果(ok N か、落ちた行)。「一行足す」の小さな入力(actor、action、detail)→ `log add` | `audit` |
| 報告 | 釦。`report` の Markdown を作って `report-<日>.md` に書き、画面に出す | `report` |

- 命令: `kagi app [--dir DIR]`。`kagi app --web` は作らない。
- 文字は日本語(kagi の他の出力と同じ)。見た目は seed の theme と同じ種の色と `font_family="Roboto"`。
- テスト: 画面の関数が、在庫・ポート・走査・記録の結果を札の文字に変える所を、Flet を起動せずに確かめる(`build_cards(dir)` のような純粋な関数を一つ作り、それを試す)。`flet` が無い時に `kagi app` が終了コード 2 で一行出す事。
- 実装で選んでいる細部: `build_cards` と `write_report` は純粋な関数。`ElevatedButton` は Flet 1.1 に無く `FilledButton`/`OutlinedButton`。ポートと走査の札は「選ぶ」の隣に道を書く欄(ブラウザでは `pick_files` が道を返さないため)。ポートの札に `host` の欄。報告は `report-<日>.md`(同じ日は上書き)。鍵が無い時は記録の札に置き方の一行だけ。確かめの逃げ道: 環境変数 `KAGI_APP_WEB_PORT` がある時だけ 127.0.0.1 のそのポートでブラウザに出す。seed では 2026-11-06 にブラウザで札が並ぶ所まで見た。日本語の字形が □ に見えた回があり、PC の窓での描画は人が見る。

### 3.4 サーバー — Linux のサーバーを入れる、見る。認証と鍵はひと組

**選んでいる物。** Linux のサーバーを入れる事と動かす事は、覚える事が多く、サーバーごとに違い、確かめ方が人に付いていた所が難しかった。AI の時代には、人が「このサーバーは何の役で、誰が入れて、どの鍵で入るか」を表に書けば、入れる時の答えの文と、見た結果と表の差と、直す手の文を道具が書く。認証(誰が入れるか)と鍵(どの鍵で入るか)はひと組で、同じ表に並べ、同じ突き合わせで見る。人に残るのは、表を書く、画面でパスワードを打つ、ディスクを選ぶ、ホストの鍵の指紋を目で比べる、直す手を読んで打つ、の五つ。ここを道具に渡すと認証の根が道具に移るので、道具には渡さない。kagi はサーバーを変えない。

**ファイル `machines.toml`(サーバーの表と鍵の表。人が書く)。** 認証(誰が入れるか)と鍵(どの鍵で入るか)を一つのファイルに並べる。

```toml
[[machine]]
host = "db1"                  # サーバーの名
ssh = "db1"                   # ~/.ssh/config の名(無ければ host)
role = "社内のデータベース"     # 一つの役
os = "debian-13"
users = ["aoki"]              # 入れてよい人
admins = ["aoki"]             # sudo を持ってよい人。入れる時は先頭が最初の管理者
keys = ["suzuki-pc"]          # 入れてよい鍵([[key]] の id)
hostkey = "SHA256:…"          # ホストの鍵(ed25519)の指紋
lan = "192.168.1.0/24"        # 入れる時: ssh を通すネットワーク
profile = "server"            # 入れる時: server | desktop
encrypt = true                # 入れる時: ディスクを暗号化するサーバー

[[key]]
id = "suzuki-pc"              # 在庫表にも同じ id で一件(期限と回す周期はそちら)
holder = "suzuki"
pub = "~/.ssh/id_ed25519.pub" # 公開鍵のファイル。.pub だけを読む
fingerprint = "SHA256:…"      # pub があれば要らない
```

`value`、`private`、`password`、`passphrase` の欄があれば読まずに拒む(K-13)。`host` と `ssh` は英数字と `. _ -` だけで、先頭の `-` を許さない(ssh の引数に化けない)。指紋は公開鍵の中身の SHA-256 で、`ssh-keygen -lf` と同じ形。kagi が自分で計算する(標準ライブラリ)。`.pub` でないファイルと、`PRIVATE KEY` を含む物は読まずに拒む。

**命令。**

| 命令 | する事 | 終了コード |
|---|---|---|
| `kagi machine list` | サーバーの表と、コピーの有無 | 0 |
| `kagi machine script` | サーバーで走らせる読むだけの sh の文を出す(人が読める。約 90 行) | 0 |
| `kagi machine collect --host H [--local]` | コピーを取り `facts/<H>-<日時>.txt`(600)に置く。ssh を使った時は記録に `machine.collect` を一行(署名の鍵があれば) | 0 / 2 |
| `kagi machine check [--host H] [--facts FILE]` | コピーを、サーバーの表・ポートの表・在庫表と突き合わせる。`--host` が無ければ全部のサーバー | 直す物があれば 1 |
| `kagi machine fix --host H` | 直す手を sh の文で出す。**走らせない**。連載 2-02 の八つに当たる手(ssh の形、鍵、人と管理者、防火壁、ポート、入口、ホストの鍵)には `【読んで確かめてから】` の印。印の無い手(更新、サービス、時計)は、打ってコピーを取り直して確かめる。防火壁の外へ出る通信を閉じる手は、終わりに「二段目」の見出しを付けて分けて出す(入る向きを閉じて ssh で入れるのを確かめ、要る外への道を数えてから打つ) | 直す物があれば 1 |
| `kagi machine install --host H [--out DIR]` | 入れる時の三つのファイルを `install/<H>/` に書く | 0 / 2 |
| `kagi key list` | 鍵ごとに、持つ人、指紋、入れてよいサーバー、在庫表の期限 | 在庫表に無い鍵があれば 1 |
| `kagi key fingerprint FILE.pub` | 公開鍵の指紋 | 0 / 2 |

**コピー(`collect`)。** 境界(§6)の「外に繋がない」の例外の一つ。条件は四つ。(1) 人が命令を打った時だけ。(2) 入るのは人の ssh と人の鍵で、kagi は鍵を読まない。`BatchMode=yes`、`PasswordAuthentication=no`、`StrictHostKeyChecking=yes` で、尋ねられる形(パスワード、初めてのサーバー)は全部落ちる。初めてのサーバーは、人が自分で入ってホストの鍵の指紋を確かめた後でないと取れない。(3) サーバーに渡すのは決まった文(`SCRIPT`)だけで、標準入力で渡し、サーバーに置かない。文は読むだけ(テストが、変える命令の語が無い事を見る)。(4) 鍵を使った事として記録に一行。root でなくても走り、root のコピー(人が `sudo sh` で走らせてファイルで渡す)なら見える物が増える。

**突き合わせ(`check`)の見る物。**

| 何 | 良い形 | 直す物として出す |
|---|---|---|
| 認証(ssh) | `PasswordAuthentication no`、`KbdInteractiveAuthentication no`、`PermitRootLogin no`、`AllowUsers` が表の人 | パスワードで入れる(書いていなければ既定の yes として)、尋ねて答える形で入れる、root がパスワードで入れる、鍵で入れない、AllowUsers に表に無い人 |
| ホストの鍵 | コピーの ed25519 の指紋 = 表の `hostkey` | 表と違う(入れ直したのでなければ、別のサーバーか、間に誰か居る)。表に無ければ指紋を出して「書く」(見るだけ) |
| 入っている鍵 | authorized_keys の指紋が全部、表の `keys` | 表に無い鍵、弱い鍵(DSA、RSA 2048 未満)。RSA 3072 未満は見るだけ |
| 鍵の表 | `keys` の id が `[[key]]` にあり、在庫表にも同じ id | `[[key]]` に無い、在庫表に無い(K-14)、表の指紋と pub の指紋が違う |
| アカウント | 入れるアカウント(uid 1000 以上、shell が nologin でない)が全部、表の `users` か `admins` | 表に無いアカウント(警察庁の情勢の資料が挙げる「管理されずに残っていた不要なアカウント」)、パスワードが空(root のコピー) |
| 管理者 | sudo の組が表の `admins` | 表に無い管理者、パスワード無しの sudo(root のコピー) |
| 更新 | 更新 0、一覧が 7 日以内、unattended-upgrades が入り動く、再起動が要らない | それぞれ |
| 防火壁 | ufw が有効、か firewalld | 動いていない。nftables だけなら見るだけ(規則は見ない) |
| ポート | コピーの `ss -ltnp` = ポートの表(`ports.compare` をそのまま使う) | 表に無いポート、開いていないポート、外向き。ポートの表にそのサーバーが無ければ見るだけ |
| 時計 | NTP で合っている(K-11) | 合っていない |
| サービス、ディスク | 落ちた unit が無い、表の `services` が動いている、85% 未満 | それぞれ。暗号化されていないディスクは見るだけ。表に `encrypt = true` と書いたサーバー(個人情報を置くサーバーなど)で暗号化されていなければ直す物 |
| 入口 | Caddy の入口が全部、入口の表にあり、`gate` と `lan` の入口に確かめる行がある | 下の「入口の表」 |
| データ | `data` の置き場が在る | 置き場が無い。大きさとディスクの残りは見るだけ |

root でないコピーでは、実際に効いている sshd の値(`sshd -T`)、他の人の authorized_keys、パスワードの状態、sudoers が見えない。その事を「見るだけ」の行で必ず言う。sshd の設定をファイルから読む時は、最初に出た値が効くとして読み(Debian は drop-in が先)、`Match` の中は見ない。

**入れる(`install`)。Debian 13 だけ。** 三つを書く。

- `preseed.cfg`: インストーラーへの答え。**パスワードとディスクは書かない。** インストーラーが尋ね、人が画面で打つ・選ぶ(K-13。ファイルに秘密が無いので、LAN の HTTP で渡してよい)。root は止める(`passwd/root-login false`)。最初の管理者の `authorized_keys` に表の公開鍵を入れ、`/etc/ssh/sshd_config.d/10-kagi.conf` で鍵でだけ入る形にする(`late_command`。中身は base64 にして引用の入れ子を避ける)。公開鍵の後ろの注釈(メールやコンピューターの名)は入れず、表の id を付ける。
- `firstboot.sh`: 入れた後に人が `sudo sh` で一度。sshd の確かめ、ufw(入る向きを閉じ、ssh は `lan` があればそのネットワークだけ、無ければ回数を絞る。**ssh を通してから有効にする**)、自動の更新、時計。何度走らせても同じ形。今あるサーバーに形を当てる時にも使えるが、鍵が入っていなければ sshd は変えない(入れなくなるのを防ぐ)。
- `手順.md`: 十二歩。人がやる事、kagi がやる事、人が確かめる事。ホストの鍵の指紋をサーバーの画面で見て表に書き(歩 6)、初めての ssh で尋ねられた指紋と目で比べ(歩 7)、最後にパスワードでは入れない事を試す(歩 9)。

足りない物があれば書かずに拒む(半端な形で入れない): `admins` が無い、`keys` が無い(鍵でだけ入る形にできない)、pub が無い、弱い鍵、`lan` がネットワークでない、Debian 13 でない。

**表の欄(サービス)。** `services = ["app", "caddy"]`(systemd で動いているべきサービス)、`user_services = ["sync"]`(コピーを取る人の `systemctl --user` で動いているべき物)、`local = true`(この PC 自身。コピーを ssh でなくここで取る)。コピーには動いているサービスの一覧、起動した時、load、メモリ、ディスクの使用率が入る。表のサービスが動いていなければ「直す」に出て、手は `systemctl status …`(理由を見る)と `restart`。アプリを動かす人が、止まったサービスの直す手を自分で読めるようにするための欄。

**入口の表 `[[door]]`。** 公開のサーバーでも、特定の人だけが入れるようにするには認証が要る。ポートの表(どのポートが開いているか)の一段上で、外から来る入口ごとに、誰が、何で守られて入るかを書く。

```toml
[[door]]
host = "web1"
site = "app.example.org"      # Caddy の設定の入口の名
who = "招待した人"             # 誰が入れるか(人の言葉)
auth = "app"                  # public | app | gate | lan
```

`public` は誰でも(認証無しが正しい)、`app` は裏のアプリが確かめる(招待コード、ログイン)、`gate` は前の Caddy が確かめる(basic_auth、forward_auth、Authorization の照合、mTLS)、`lan` はネットワークで絞る(remote_ip)。コピーは `/etc/caddy/Caddyfile` から**形だけ**を取る(入口の名、通す先、認証の行の名。値は取らない。テストが、見本の設定の中の偽の値がコピーに出ない事を見る)。出す物: 表に無い入口(直す)、`gate` なのに確かめる行が無い(直す。誰でも通る)、`lan` なのに remote_ip が無い(直す)、表にあって設定に無い(直す。まだ置いていない入口)。`app` の入口は「アプリの中は見ていない」と必ず言う。kagi が見るのは設定の形までで、アプリが本当に確かめているかは外から試して見る。Caddy 以外(nginx など)はまだ無い。

**データの置き場 `data`。** 文字でないデータ(写真など)は大きくなり、管理が難しい。サーバーに `data = ["/srv/photos"]` と書くと、コピーにその道の大きさと、そのディスクの使用率と残りが入る。置き場が無ければ「直す」(ディスクが繋がっていない)。道は文に埋めず、引数で渡す(文は変えない)。道の字は英数字と `. _ / @ + -` だけ。大きさを測るので、待つ時間を 10 分まで延ばす。

**配備の見本。** seed のリポジトリの `deploy/` に、配備が済んだ後のポートの表、秘密の在庫の見本、サーバーと入口の表の見本、手順があります。digitaldoor にはコピーしていません。

**机の画面(`kagi app`)。** 四つの画面を上の釦で切り替える。

| 画面 | 中身 |
|---|---|
| サーバー(最初に開く) | サーバーごとの釦(`db1 直す 9`、`よし`、`コピー無し`)で選ぶ。選んだサーバーの頭の一行、「コピーを取る」「直す手を全部コピーする」「入れる時のファイルを作る」。直す物は一件ずつ、何・見た物・手(等幅の文)と、その手をコピーする釦。見るだけの行。「サーバーを足す」の欄(名、ssh、役、入れてよい人、sudo を持ってよい人、鍵の id、サービス、この PC 自身) |

画面から足したサーバーと鍵は `machines.toml` の末尾に一件ずつ書く(足した形を読めるか確かめてから。読めなければ書かない)。直す・消すはエディタで。画面はサーバーを変えない。コピーする釦は手の文を貼り付け用にコピーするだけで、走らせるのは人。窓が狭い時は窓の幅に合わせる。画面の中身を作る所は Flet を使わない関数(`machine_view`、`keys_view`、`add_machine`、`add_key`)でテストする。`kagi report` に「サーバー」の節。seed では 2026-11-06 にブラウザで開いて、札と表と直す手の文が出る所まで見た。その時、「ポート」の札が灰色の塊になっていた(折り返す行の中に、幅を伸ばす欄があった)ので、欄の幅を決めて直した(走査と記録の欄も同じ)。

**人の出入り(seed のサーバーを前提にした部分。`kagi/kagi/admin.py`)。** seed のサーバーは運営者の鍵で Claude を呼ぶので、誰がそのインターフェースを使えるか、鍵が何処に在っていつ切れるかを、欄と決まりのはっきりしたフォームの形で kagi の側に置く。seed のアプリはチャットの形で自由に作り、管理はここで厳格に行う。

- 繋ぐ先は作業の場所の `seed-admin.json`(600)に置く。画面に出すのは URL と「入っています」だけ。入れ替える、外す(二度押し)。在庫表に、id が `seed-admin-token` か置き場に `seed-admin.json` を含む一件が無ければ、「在庫表に一件足してください」と出し、欄を埋めた「在庫表に一件足す」へ移る釦を置く(勝手には足さない)。
- 呼ぶのは `/api/admin/*`(要求の頭 `x-seed-invite`)。`urllib` で、https だけ(`http://127.0.0.1`・`localhost` は手元で確かめるために通す)。転送(redirect)は辿らない(token を別の先へ運ばないため)。サーバーの答えに無い値の行は「分からない」か出さず、知らない値は読み飛ばす。
- token の欄: 渡す相手の名前(必須、64 字まで)、できる事(仲間・買い手・管理者)、期限(1〜365 の整数。既定 90、管理者は 30)、覚え書き。欄が決まりに合う時だけ「出す」が押せ、合わない欄の下に理由が出る。出た token は一度だけ見せ、コピーする釦。読み直すか画面を移ると消える。一覧は生きている物が先で、14 日以内に切れる物は赤(サーバーの数え方と同じ日数)。
- 取り消す、全部取り消す(自分の分は残る)、止める・再開する、取り下げる、一言を消すは、どれも二度押し。止めている間は、どの画面でも上に赤い帯が出る。
- 画面からした操作は kagi の記録にも一行ずつ(`seed.token.add`、`seed.token.revoke`、`seed.token.revoke_all`、`seed.pause`、`seed.resume`、`seed.withdraw`、`seed.connection_remove`。detail はサーバーの名と、誰に何を。token は書かない)。署名の鍵が無い時は、その事を一行出す。
- 操作の記録(サーバー)は、サーバーの記録の行を人の言葉にして出す。した事は、読み、草の名、照会、公開、取り下げ、一言、管理の操作に加えて `talk`(公開のサーバーを経由して Claude と話した。誰が、通した・断った)を「Claude と話した」と出す。今の状態の「今日の残り」には、overview の `remaining` の読み取りと話す(`talks`)の回数と使える額。
- 中身を作る所は `kagi/kagi/admin.py`(Flet を使わない関数。サーバーを呼ぶ所は通信の関数を差し替えられる)。kagi は seed を import しない。管理の画面はここだけで、seed のアプリの中には置かない。

**鍵の突き合わせ(seed のサーバーを前提にした部分)。** サーバーが外のサービスを呼ぶ鍵(Claude、Pl@ntNet)は、サーバーに在るか無いかだけを `overview` の `keys` で尋ね、在庫表の行と並べる。在庫表の行は、id か置き場に `anthropic`・`claude`、`plantnet` の語を含む物を、その鍵の一件と見る。サーバーに在って在庫表に一件も無ければ「直す」、在庫表に在ってサーバーに無ければ「見るだけ」(置く前か、外した後ならそれで合っている)。期限切れは「直す」、30 日以内は「見るだけ」で、在庫表の決まりと同じ。「人の出入り」をまだ開いていない時は、在るか無いかを「分からない」として、在庫表の行だけを出す。在庫表に一件足す欄に値の欄は無く、値らしい物(`sk-`、`AKIA`、`ghp_` などで始まる物、32 字以上の 16 進、大文字・小文字・数字の混じる 20 字以上の並び)が貼られたら断る。種類は `token`、作った日はその日で書く。回す周期(`rotate_days`)の欄は無いので、足した後は在庫の札に「抜け」と出る。エディタで書き足す。

**確かめた物(seed で 2026-11-06)。** テスト(公開鍵の形の見本は対になる秘密鍵が無い偽物)。三台のサーバー(ssh で入る二台と、`local` の机の PC)でコピーを取り、突き合わせと直す手が出た。机の画面はブラウザで開き、サーバーを選ぶ、画面からコピーを取る、直す手が出る、鍵の一覧、まで見た(PC の窓での描画は人が見る)。`preseed.cfg` は `debconf-set-selections -c` で文法を、`firstboot.sh` は `sh -n` で文法を、作ったファイルは `kagi scan` で秘密らしい文字列が無い事を見た。digitaldoor にコピーした 2026-11-11 には、`kagi/tests/` の 130 件が通る事を見た。

**確かめていない物。** `preseed.cfg` と `firstboot.sh` を、本物のインストーラーと入れたてのサーバーで通していない(仮想マシンで一度通すのが次。`手順.md` の頭にもそう書く)。Ubuntu(autoinstall)と RHEL 系(dnf、kickstart)は無い。root のコピーの節(`sshd -T`、`passwd -S`、sudoers)は見本でだけ試した。

### 3.4b 連載「Claude と一緒に育てる Debian サーバー」との対応

連載(https://aiseed.dev/debian-server/ )は、人が Claude と一緒に一台のサーバーを作って育てる手順。kagi は、その「良い形」にサーバーが今も合っているかを、何台でも同じ見方で確かめる道具。良い形の出どころは連載に置き、kagi の側で別の基準を作らない。第 4・5・10・11 章に揃えてある(同じ作者の連載なので、違っていたら連載の側が正しい)。

| 連載の章 | 連載の形 | kagi が見る物・書く物 |
|---|---|---|
| 3 最小インストール | netinst、tasksel は SSH サーバーと標準ユーティリティだけ | `machine install` の `preseed.cfg`(`standard, ssh-server`。パスワードとディスクは人が画面で) |
| 4 SSH という玄関 | ed25519 の鍵、パスフレーズを付ける、`PasswordAuthentication no`、`PermitRootLogin no`、`sshd -t` と `reload`、別の窓で確かめてから閉じる、退路(画面) | 認証(ssh)の行、入っている鍵と鍵の表、ホストの鍵の指紋。直す手は同じ順(先に別の窓で確かめる、`sshd -t`、`reload`) |
| 5 守りの基本 | ufw は入りも出も既定は拒否、ssh を通してから有効に、出口は 53・123/udp・80,443/tcp・67/udp(DHCP の要求)、unattended-upgrades、fail2ban(`jail.local` に 10m・10m・5 回、`[sshd]`)、不要なサービスを止める、`ss -tlnp` | 防火壁(入る向き・出る向きの既定、fail2ban)、更新(自動の更新、再起動)、ポートの表との突き合わせ。`firstboot.sh` は同じ規則を同じ順で書く |
| 6 サービスという単位 | systemd の unit と timer | `services`、`user_services`、`timers`、落ちている unit |
| 9 外の世界に公開する | リバースプロキシ、公開しないも選択肢 | 入口の表(`[[door]]`)と Caddy の設定の形 |
| 10 データを守る | restic、`backup.service` と `backup.timer`、パスワードは `/etc/restic/backup.env`(600)、復元の演習 | `timers = ["backup"]` が止まれば直す物。`data` の置き場が無ければ直す物。パスワードは在庫表に一件(値は書かない) |

**連載と違えてある所(一つ)。** ssh の設定を書くファイルの名。連載は `/etc/ssh/sshd_config.d/99-hardening.conf`、kagi は `10-kagi.conf`。sshd は同じ項目が二度出ると**最初の値**を使い、Debian は `sshd_config.d/*.conf` を名の順で先に読む。最小インストールには他のファイルが無いので `99-` でも効くが、VPS の雛形に `50-cloud-init.conf`(`PasswordAuthentication yes`)のような物が在ると、`99-` の値は効かない。kagi の突き合わせは「最初に出た値」で読むので、その時は「パスワードで入れる」が消えずに残る。

**連載に在って kagi にまだ無い物。** needrestart、PostgreSQL の中(第 7 章)、restic の中身と復元の演習の記録、月の保守の日付の記録、`journalctl` のエラーの中身(数だけ見ている)。

**三台のサーバーで週の定例を走らせた結果(seed で 2026-11-06)。** 直す物は 10、12、3。三台とも、出る向きを既定で通していた(連載の形と違う所)。自分の書いた形に自分のサーバーが合っているかは、道具で見て初めて分かる。

### 3.5 `kagi check tokens` — 相手に出した token の台帳(K-05、K-14)

アプリの門(seed のサーバーなど)に入る token を、誰に、どのアプリの、どの範囲で、いつまで出したか。台帳は `~/.config/aiseed/tokens.json`(`--file` で別の場所。seed のサーバーでは `/var/lib/seed/gate/tokens.json`)で、書くのはアプリ(`seed token add`。seed の設計書 §5.9)。在るのはハッシュだけで、kagi はハッシュも出さない。token そのものの欄(`token`、`code`、`value`)があれば読まずに拒む(終了コード 2)。

出すのは、期限切れのまま取り消していない物(直す。終了コード 1)、期限の近い物(`--days`、既定 30)、生きている物、取り消した物。期限の無い物は期限切れと同じ扱い。机の画面では「鍵」の画面の下に同じ表。kagi は seed のコードを使わない(JSON を読むだけ)。サーバーに入る鍵(`[[key]]`)と、アプリに入る token(この台帳)が、同じ画面に並ぶ。台帳の形は seed の物に合わせてあり、seed 以外のアプリでも同じ形の JSON を書けば読める。

サーバーの記録(誰が何をしたか)は kagi の記録と同じ形なので、`kagi log verify --dir <記録の場所>` でそのまま確かめられる。

## 4. 署名の鍵

順に探す。(1) `$CREDENTIALS_DIRECTORY/kagi-log-key`(systemd の credential)。(2) `$KAGI_LOG_KEY_FILE` が指すファイル。どちらも無ければ `log add` と `log verify` は終了コード 2 で、鍵の置き方(`skills/kagi/02-記録.md`)を一行出す。鍵の中身は読んで HMAC に使うだけで、出力・ログ・例外のメッセージに出さない。ファイルの許可が `600` でなければ警告する。

## 5. テスト(`kagi/tests/`)

- 在庫表: 必須の欄の抜け、期限切れ、N 日以内、`value` 欄の拒否。
- ポート: `ss` の出力の見本(IPv4、IPv6、`*`、プロセス名付き)と表の突き合わせの三種の差。
- 走査: 見本のファイル(偽の形の文字列。実際の鍵ではない)で種類だけが出て、文字列そのものが出力に無い事を `capsys` で確かめる。バイナリと `.git` を飛ばす事。
- 記録: 追記 → 検証 ok。一行消す → 落ちる。一文字変える → 落ちる。鍵を替える → 落ちる。鍵が無い → 終了コード 2。
- 報告: 一枚が出て、値を含まない事。
- 人の出入り(§3.4): 欄の決まりで「出す」が断られ理由が出る、token の値が保存したファイルの外(画面の文字、記録、例外の文)に出ない、ファイルが 600、http を断り https と手元の番地を通す、偽の返事から状態・気を付ける事・token・載せる前の記録・公開・操作の記録が組める、知らない値と欠けた値で落ちない、二度押し、操作ごとに kagi の記録に一行、鍵の突き合わせ、在庫表の欄が値らしい物を断る。
- サーバーと鍵(§3.4): 公開鍵の指紋、秘密鍵と値の欄の拒否、名の形、認証・鍵・アカウント・更新・ポートの差、コピーを取る命令の形(鍵でだけ、確かめ済みのサーバーだけ)、読むだけの文に変える命令の語が無い事、入れるファイルにパスワードとディスクが無い事。

回し方: リポジトリの最上位で `.venv/bin/python -m pytest -q kagi`。

## 6. 境界

- 外に繋がない。`ss` を自分で走らせない(人がファイルで渡す。`ss` を走らせるにはサーバーに入る必要があり、AI の token の範囲を広げないため)。例外は二つ。`kagi machine collect`(§3.4 の四つの条件: 人が打った時だけ、人の ssh と鍵で、読むだけの決まった文、記録に一行)と、机の画面の「人の出入り」(人が繋ぐ先を入れて開いた時だけ、https で seed のサーバーの管理のインターフェースだけ、変える操作は二度押しで記録に一行)。
- サーバーを変えない。直す手は文で出し、走らせるのは人(sudo は人の手)。入れる時のファイルも、渡すのと走らせるのは人。AI が動くアカウントに sudo を渡さない。連載 2-02 は、壊れても初期化で始め直せるサーバーなので AI に root を渡す。人の記録と写真を預かるサーバーでは、初期化で戻るのは OS だけで、預かった物は控えから人が戻すしかないので、ここは連載より厳しくしている。
- 鍵を作らない、回さない、発行しない。それは人の手。読むのは公開鍵と指紋だけ。「人の出入り」で出す token は seed のサーバーが作る物で、kagi は人が押した時にそのインターフェースを呼び、出た値を一度だけ画面に見せる(どこにも書かない)。
- seed のコードにも digitaldoor のほかのコードにも依存しない。単独で切り出せる。
